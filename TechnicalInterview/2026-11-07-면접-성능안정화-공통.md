## 2. 문제 해결 — 출근 피크 8,000명 / 10분

### 근태 표시
- **Q11.** 근태 표시를 켜면 왜 서버가 죽었나요?
  → 장면: [E·코드를 열어보니][PE코드] · 키워드: readOnly=false 전 사원 dirty checking / `em.flush()` / 출근 1건 = 회사 전원 XMPP
  - **↳ Q12.** 1차 개선은 왜 실패했나요?
    → 장면: [E·처음 시도 (1차)][PE시도] · 키워드: 근태 상태 캐시 / 30초 → 1초인데 장애 동일 / 큐 이후 발송 쪽이 문제
    - **↳↳ Q13.** 🎯 함정 — "30초 → 1초"와 "28초 → 0.6초"는 같은 측정인가요?
      → 장면: [E·처음 시도 (측정 구분)][PE시도] · 키워드: 1차 보고 엑셀 vs 2차.xlsx / 1차 브랜치 미머지 / 2차는 원래 코드에서 출발
- **Q14.** 🎯 함정 — XMPP 발송을 없앴나요?
  → 장면: [E·최종 결정과 대가][PE대가] · 키워드: 화면 진입은 `/display` 응답(pull) / 이후 1분마다 회사별 묶음 push / XMPP는 유지
  - **↳ Q15.** 응답 방식만, 또는 스케줄러만으로는 안 됐나요?
    → 장면: [E·처음 시도 (2차 측정)][PE시도] · 키워드: 응답만 CPU 81% / 스케줄러만 82% 장애 / 둘 다 71% 통과
  - **↳ Q16.** 이 방식의 대가는?
    → 장면: [E·최종 결정과 대가][PE대가] · 키워드: 최대 약 1분 지연 / 옵션 기본 false / 다음 분 커밋 누락 → `/display`로 보정
    - **↳↳ Q17.** ⚠️ 기억 확인 필요 — 고객사에서 relay 옵션을 실제로 켰나요? 7월 쿼리 수정은 왜?
      → 장면: [남은 질문 3번][P남은] · 키워드: `timeline.display.relay` / 7월 전엔 날짜 단위로 잘려 빈 구간 / GO-45487

  - **↳ Q20.** 왜 "변경분" 대신 "전체 트리"를 주기로 했나요?

    - **↳↳ Q21.** 그럼 "바뀌었는지"는 어떻게 알려주나요?

- **Q24.** 🎯 함정 — 조직 변경 이벤트 14종을 다 만들었나요?

  - **↳ Q25.** 변경 지점마다 evict를 직접 부르지 않고 이벤트로 한 이유는?

  - **↳ Q26.** 고객사 외부 조직도 동기화(하루 2번) 때 캐시는 어떻게 깨지나요?

- **Q87.** 메일 스토어 구조의 대가는?
  → 장면: [메일 1·대가][L1대가] · [메일 3·대가][L3대가] · 키워드: Netty 이벤트 루프에서 DB 처리 / 사용자 단위 쓰기 직렬화 / NFS라 WAL 못 씀

## 13. 보유 기술 장

- **Q88.** 🎯 함정 — 보유 기술에 KEDA가 있는데, 어디에 어떤 기준으로 썼나요?
  → 장면: [AI 1-1][I11] · [질문 모음·AI][QAI] (AI-13·AI-27) · 키워드: agent는 처리 중 채팅 수(active_llm_requests) 기준, 부하테스트하며 180→150 조정 / stream은 CPU 기준 / automation은 KEDA 없이 2파드 고정(큐 길이 증설은 설계만)
- **Q89.** Ehcache(Terracotta)를 어디까지 다뤄 봤나요?
  → 장면: [성능 B·대가][PB대가] · [성능 D][PD] · 키워드: 캐시 영역·키 설계 / TTL·TTI·eventual / 엔트리 상한·사이즈 가이드
- **Q90.** JMeter·k6·Scouter·Grafana를 각각 어디서 썼나요?
  → 장면: [성능 전체 그림][P0] · [AI 1-1][I11] · 키워드: 성능은 JMeter + Scouter / AI는 k6 / nGrinder는 3,400명 건
