## 1. [Human-in-the-loop] interrupt() 메커니즘과 상태 재개(Resume)

### 💡 개념적 정의와 존재 이유

**Human-in-the-loop(HITL)**은 에이전트가 중요한 결정을 내리기 전(예: 결제 실행, 이메일 발송) 실행을 일시 중단하고 사람의 승인을 기다리는 아키텍처 패턴입니다. 이는 에이전트의 환각(Hallucination)으로 인한 사고를 방지하는 **최후의 안전장치(Guardrail)** 역할을 합니다.

### 🛠 내부 동작 메커니즘 (Step-by-Step)

1. **중단(Interrupt)**: 노드 내부에서 `interrupt()` 함수가 호출되면, LangGraph는 현재 상태를 체크포인트에 즉시 저장하고 실행 스택을 비우며 제어권을 사용자에게 반환합니다.
2. **대기(Persistence)**: 상태는 영속성 계층(예: PostgreSQL)에 저장되어 서버가 재시작되어도 유실되지 않습니다.
3. **업데이트(Update)**: 사용자는 중단된 상태를 확인하고 필요한 데이터를 수정하거나 승인 정보를 입력합니다.
4. **재개(Resume)**: `Command(resume=...)`를 통해 메시지를 보내면, 엔진은 체크포인트에서 상태를 복구하여 중단된 지점부터 실행을 이어갑니다.

### 🏗 텍스트 아키텍처 다이어그램

```text
[Agent Loop] --> (Node: Payment) -- [interrupt 호출] --> [Checkpoint DB 저장]
                                                              |
[Client App] <---------- [400 Pending Response] --------------+
      |
[User Approval] -- [Command(resume=True) 전송] --> [Checkpoint 로드] --> [결제 완료]
```

## 2. [Streaming] LangGraph Async Streaming & Event Filtering

### 💡 개념적 정의와 존재 이유

사용자는 에이전트의 전체 답변이 완성될 때까지 기다리는 것을 원치 않습니다. **Streaming**은 LLM이 생성하는 토큰이나 에이전트의 내부 작업 단계(Node update)를 실시간으로 클라이언트에 전달하는 기술입니다.

### 🛠 내부 동작 메커니즘

1. **.astream()**: 그래프의 각 노드가 완료될 때마다 업데이트된 전체 상태(State)나 노드의 반환값을 스트리밍합니다.
2. **.astream_events()**: 가장 강력한 방식으로, 토큰 단위(on_chat_model_stream)부터 도구 호출, 노드 시작/종료 등 그래프 내부의 모든 이벤트를 세밀하게 스트리밍합니다.
3. **네임스페이스 필터링**: 서브그래프나 특정 노드에서 발생하는 이벤트만 골라내어 클라이언트에 전송함으로써 불필요한 데이터 전송량을 줄입니다.

## 3. [Concurrency] 비동기 동시성 제어 및 병목 해결

### 💡 개념적 정의와 존재 이유

에이전트가 여러 도구를 호출할 때 순차적으로 처리하면 응답 시간이 기하급수적으로 늘어납니다. **비동기 동시성 제어**는 의존성이 없는 작업들을 병렬로 실행하여 전체 처리량(Throughput)을 높이는 전략입니다.

### 🛠 내부 동작 메커니즘

1. **병렬 노드 실행**: 그래프 구조상 선후 관계가 없는 노드들은 LangGraph 엔진에 의해 자동으로 병렬 실행됩니다.
2. **노드 내부 병렬화**: 하나의 노드 안에서 `asyncio.gather()` 등을 사용해 여러 API 호출이나 DB 쿼리를 동시에 수행하고 결과를 합산(Reduce)합니다.
3. **병합(Reduction)**: 병렬 작업들의 결과가 동일한 상태 키를 업데이트할 때, 미리 정의된 **Reducer** 함수를 통해 안전하게 데이터를 병합합니다.

## 4. [Hands-on] 3주차 개념 검증 통합 실습 코드

```python
import asyncio
import operator
from typing import Annotated, TypedDict, Literal
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import Command, interrupt

# 1. 상태 정의 (병렬 결과 합산을 위한 Reducer 활용)
class AdvancedState(TypedDict):
    input: str
    results: Annotated[list[str], operator.add] # 결과를 리스트로 누적
    approval: bool

# 2. 비동기 동시성 노드 (병렬 도구 호출 모사)
async def tool_a(state: AdvancedState):
    await asyncio.sleep(1) # 지연 시간 모사
    return {"results": ["Tool A completed"]}

async def tool_b(state: AdvancedState):
    await asyncio.sleep(1)
    return {"results": ["Tool B completed"]}

# 3. Human-in-the-loop 노드
def human_approval(state: AdvancedState):
    print("--- Human Approval Node: Waiting for Input ---")
    # interrupt()를 호출하여 실행 중단. 클라이언트에서 resume 값을 보내야 재개됨.
    decision = interrupt({"question": "작업 결과가 만족스러운가요?", "data": state["results"]})
    return {"approval": decision.get("approved", False)}

def router(state: AdvancedState) -> Literal["process_final", "end"]:
    if state["approval"]:
        return "process_final"
    return "end"

def process_final(state: AdvancedState):
    return {"results": ["Finalizing the process..."]}

# 4. 그래프 구성
builder = StateGraph(AdvancedState)
builder.add_node("tool_a", tool_a)
builder.add_node("tool_b", tool_b)
builder.add_node("human_approval", human_approval)
builder.add_node("process_final", process_final)

# START -> [tool_a, tool_b] (병렬 실행) -> human_approval
builder.add_edge(START, "tool_a")
builder.add_edge(START, "tool_b")
builder.add_edge(["tool_a", "tool_b"], "human_approval")

builder.add_conditional_edges("human_approval", router)
builder.add_edge("process_final", END)

# 체크포인터 연결 (HITL 필수)
memory = MemorySaver()
app = builder.compile(checkpointer=memory)

# 5. 실행 및 스트리밍 확인
async def run_example():
    config = {"configurable": {"thread_id": "3-week-test"}}
    initial_input = {"input": "Run parallel tasks", "results": [], "approval": False}

    print("\n[Step 1] 병렬 실행 및 중단 발생 확인")
    # .astream_events를 사용해 내부 이벤트를 스트리밍 확인 (version v3 권장)
    async for event in app.astream_events(initial_input, config, version="v3"):
        if event["event"] == "on_chain_stream":
            print(f"Event: {event['name']} - {event['data'].get('chunk')}")

    # 현재 상태 조회 (interrupt 상태인지 확인)
    state = await app.aget_state(config)
    if state.next:
        print(f"\n현재 대기 중인 노드: {state.next}")
        
        print("\n[Step 2] Human Resume (승인 전송)")
        # Command(resume=...)를 통해 중단된 지점부터 재개
        async for event in app.astream_events(Command(resume={"approved": True}), config, version="v3"):
            if event["event"] == "on_chain_stream":
                print(f"Event: {event['name']} - {event['data'].get('chunk')}")

if __name__ == "__main__":
    asyncio.run(run_example())
```

## 5. [K8s & Production] 프로덕션 환경의 실무 장애 및 트러블슈팅

### ⚠️ 장애 시나리오: 롱러닝(Long-running) 루프의 고착 상태 (Stuck State)

쿠버네티스 환경에서 `interrupt()` 상태로 수 시간 대기 중인 에이전트 세션이 있다고 가정해 봅시다. 그 사이 Deployment 업데이트로 Pod가 재시작되면, 인메모리 대기열에 있던 스트리밍 연결이 끊기고 사용자는 에이전트가 죽었다고 판단합니다. 또한, 특정 노드에서 비동기 호출 병목으로 인해 좀비 프로세스가 발생하면 해당 Pod의 리소스를 고갈시킵니다.

### ✅ 플랫폼 엔지니어의 조치 사항: 상태 복원 및 타임아웃 관리

1. **상태 재구축(State Reconstruction)**: Pod 재시작 후 사용자가 다시 접속하면, `thread_id`를 기반으로 외부 DB(Postgres)에서 최신 체크포인트를 읽어와 정확히 `interrupt` 지점부터 다시 렌더링되도록 프론트엔드와 싱크를 맞춥니다.
2. **Readiness Probe 연동**: 비동기 병목으로 인해 특정 Pod의 이벤트 루프 지연 시간이 임계치를 넘으면, K8s Readiness Probe를 실패(False)로 반환하여 해당 Pod로 새로운 트래픽이 유입되지 않도록 격리합니다.
3. **Stuck Loop 탐지**: 수 일간 진전이 없는 루프를 감지하는 별도의 크론잡(CronJob)을 운영하여, 일정 시간 경과 시 상태를 `Failure`로 강제 업데이트하고 알람을 발생시킵니다.

## 6. [Self-Diagnosis] 개념 검증용 자가 진단 질문

1. **(HITL)** `interrupt()`가 호출된 노드 내부의 로컬 변수들은 Pod가 재시작된 후 `Command(resume=...)`로 재개될 때 그대로 유지되는가? 아니라면 이유는 무엇인가?
2. **(Streaming)** `.astream()`과 `.astream_events()`의 가장 결정적인 차이점은 무엇이며, 대규모 트래픽 환경에서 `on_chat_model_stream` 이벤트를 필터링해야 하는 이유는 무엇인가?
3. **(Concurrency)** 두 개의 노드가 병렬로 실행되어 동일한 상태 키(예: `score`)를 동시에 업데이트하려고 할 때, 데이터 유실을 방지하기 위해 `TypedDict` 정의 시 반드시 포함해야 하는 요소는 무엇인가?

---

<details>
<summary><b>[3주차 해설 및 정답 확인]</b></summary>

1. **정답**: 유지되지 않습니다. `interrupt()`는 실행 스택을 비우고 상태(State)만 체크포인터에 직렬화하여 저장합니다. 따라서 노드 내부의 일반 지역 변수는 사라지며, 오직 그래프의 `State`에 저장된 값들만 재개 시 복원됩니다.
2. **정답**: `.astream()`은 노드 단위의 최종 결과값만 보여주지만, `.astream_events()`는 토큰 하나하나까지 포함된 세밀한 이벤트를 제공합니다. 대규모 트래픽 시 모든 중간 이벤트를 전송하면 네트워크 오버헤드가 크므로, 클라이언트에 필요한 정보(예: 최종 응답 토큰)만 골라내는 필터링이 필수적입니다.
3. **정답**: 해당 키에 **Reducer 함수**가 지정되어야 합니다. 기본값은 'Last-write-wins'이므로 나중에 끝난 노드가 앞선 노드의 결과를 덮어씁니다. `operator.add`나 커스텀 합산 함수를 `Annotated`를 통해 지정해야만 두 노드의 결과가 안전하게 병합됩니다.

</details>
