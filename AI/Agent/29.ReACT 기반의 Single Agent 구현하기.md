# [ReACT 기반의 Single Agent 구현하기]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 ReACT(Reasoning + Acting) 패턴의 구조적 본질과 에이전틱 루프
대형 언어 모델(LLM)을 사내 정보 시스템과 유기적으로 결합하여 특정 목표를 완전 자율적으로 자동화하고자 할 때, 단순히 단발성 대화를 나누거나 일방향적인 답변을 생성하는 방식은 복잡한 다단계 비즈니스 요구사항을 처리하는 데 있어 한계에 봉착합니다. 이를 타개하기 위해 추론(Reasoning)과 행동(Acting)을 결합하여 당면 과업을 종결할 때까지 반복 순환 동작하는 단일 에이전트의 표준 아키텍처로 ReACT 패턴이 널리 활용되고 있습니다.
*   **추론(Reasoning)과 생각(Thought)의 역할**: 에이전트는 최초에 사용자의 거시적인 질문이나 명령을 입수하면, 곧바로 최종 답변을 내리는 확률 연산을 전개하지 않고, 현재 상황을 면밀히 인지하여 목표 달성을 위한 구체적인 하위 태스크를 논리적으로 세분화하고 계획을 수립(Planning)하는 고유한 생각 단계를 먼저 거칩니다.
*   **행동(Acting)과 도구 호출(Tool Call)**: 수립된 행동 계획에 의거하여, 에이전트 외부에 구비된 특화 기능 API 또는 파일 입출력 스크립트 등의 도구(Tools)를 정형 인입 규격을 채워 호출(Function Calling)하는 물리적 액션 단계를 전개합니다.
*   **결과 관찰(Observation)과 피드백 연쇄**: 도구 구동이 최종 완료되어 호스트로부터 유입된 출력 스트림(stdout)이나 정량 데이터셋 등의 결과 피드백을 단기 기억 콘텍스트 내에 수입 연접시킵니다.
*   **자율 자가 성찰(Self-Correction) 및 루프 순환**: 인입된 피드백을 분석하여 목표 달성을 위한 지식이 충분한지 성찰하고, 부족하다고 판단되면 다시 Reasoning 단계로 돌아가 쿼리 어휘를 세부 개선한 뒤 툴 호출을 반복적으로 감행하는 자율 순환 오케스트레이션 루프를 영위합니다.

### 1.2 LangGraph를 통한 ReACT 아키텍처의 상태(State) 설계 및 제어 제어선
ReACT 아키텍처의 가장 치명적인 인프라적 위협은 비결정론적으로 동작하는 대규모 모델의 추론 판단 흐름으로 인해 루프 도중 제어권을 완전히 상실하고 무한히 자원을 갉아먹다 다운되거나 이탈(Divergence)하는 현상입니다. LangGraph는 전체 실행 파이프라인을 노드(Nodes)와 엣지(Edges)로 구성된 상태 그래프(State Graph)로 모델링함으로써 에이전트의 오케스트레이션 제어 주권을 엔지니어에게 온전히 반환합니다.
*   **MessagesState 기반의 무결 상태 추적**: 그래프를 구성하는 각 컴포넌트들은 `TypedDict` 스키마 규격 하에 선언된 `messages` 상태 채널을 매개로 삼아 양방향 데이터 전이를 전개합니다. 이 메시지 이력 배열 상에는 모델이 출력해낸 AIMessage와 도구 노드가 생성해낸 ToolMessage가 자동으로 누적 연접(`add_messages` 리듀서)되어 보존되며, 이는 무거운 비상태성 API를 상태성(Stateful) 동적 가동 인프라로 격격히 전환시키는 안전 지탱 기저가 됩니다.
*   **call_model 노드와 should_continue 조건부 엣지의 유기적 매핑**:
    *   **call_model 노드**: 시스템 명령 프롬프트(System Message)와 상태 메모리에 누적 적재되어 있는 히스토리를 융합하여 기저 LLM에 디코딩 추론을 투과시킵니다.
    *   **should_continue 조건부 엣지**: call_model을 투과해 반환된 AIMessage 내부를 판독하여 `tool_calls` 필드가 채워져 있다면 제어 흐름을 `tools`(ToolNode) 노드로 리라우팅하고, 필드가 전무하면 최종 정답에 무결히 수렴하였다고 간주해 `__end__`(END) 노드로 라우팅하여 루프를 안전하게 강제 기각 수축합니다.

### 1.3 가용 도구(Tool) 명세 표준화와 llm.bind_tools(tools) 바인딩 수렴
에이전트가 정상적으로 동작하려면 자신이 언제 어떤 도구를 가동해야 하는지 그 스키마 구조를 가중치 표상 공간 상에 완벽하게 각인 인지하고 있어야 합니다.
*   **@tool 데코레이터를 이용한 JSON Schema 자동 빌드**: 파이썬으로 작성된 함수의 이름, 입력 매개변수 구조 타입, 그리고 상세 가이드 Docstring 정보를 LangChain 컴파일러가 파싱하여 LLM이 직접 대조 해석할 수 있는 엄격한 규격의 JSON Schema 데이터 구조로 역전치 변환합니다.
*   **llm.bind_tools(tools) 바인딩 메커니즘**: 바인딩이 성사되면 모델은 대화 턴 개시 이전에 가용 도구들의 목록과 사용 목적 설명서(Tool Catalog Manifesto)를 시스템 프롬프트 바로 뒤에 기본 콘텍스트 버퍼 영역으로 마운트 수입합니다. 이를 통해 무조건적인 텍스트 '상상 생성'을 셧다운하고, 수량 변수나 질문 의미를 분석하여 적합한 툴 인자 포맷에 맞춘 매개변수 바인딩을 정밀하게 결정지어 줍니다.
*   **실습 도구 설계의 물리적 기동 특징**:
    *   **search(query: str)**: 로컬 인메모리 상에 매핑된 사전 정의 기술 자료를 대조하여 최신 지식 파편을 고속 회수하는 모사 검색 도구.
    *   **calculator(expression: str)**: 비정형 수식 연산의 사칙 수학 논리를 로컬 파이썬 인터프리터 런타임 상에서 직접 가동하여 정량 피드백을 완전 복구하는 수치 계산 도구.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 ReAct 기반 AI 에이전트의 종단간(End-to-End) 데이터 흐름 및 상태 전이도
아래 아키텍처 흐름도는 사용자 질문의 인입 시점부터 에이전트 내부의 call_model 노드가 Reasoning을 수립하고, 조건부 엣지 라우팅을 거쳐 도구 노드(Acting)를 무결 실행한 뒤, 누적된 Observation 피드백을 단기 메모리에 병입 연접해 가며 최종 응답에 무결 수렴하는 종단간 데이터 흐름을 묘사합니다.

```
[사용자 복합 질문 인입 (User Question)]
       │
       ▼ [State: MessagesState 메시지 초기화]
[call_model 노드 가동 (Reasoning)] ◄───────────────────────────────────────────┐
  - SYSTEM_PROMPT + state["messages"] 융합 연산                                  │
       │                                                                       │
       ▼ [AIMessage 출력]                                                       │
[should_continue 조건부 엣지 판독]                                             │
  - AIMessage 내부에 tool_calls 필드가 존재하는가?                              │
       ├─────────────────────────────────────────┐                             │
       ▼ [YES: 도구 호출 분기 전치]               ▼ [NO: 루프 조기 종결 분기]    │
[tools 노드 실행 (Acting)]                  [최종 정답 텍스트 출력]             │
  - ToolNode([search, calculator]) 구동      - 사용자 전송 준비                  │
       │                                         │                             │
       ▼ [Observation 획득 및 State 적재]         ▼                             │
[ToolMessage 생성 및 누적 업데이트] ─────────────► [END]                         │
  - state["messages"]에 결과 추가 연접 후 리턴                                  │
       └───────────────────────────────────────────────────────────────────────┘
```

### 2.2 ReACT 순환 루프 상에서의 컨텍스트 제어와 VRAM 연산 최적화
단일 에이전트가 복합 조회를 수행하며 계획-행동-관찰 루프를 5회 이상 다회차로 지속 연쇄 가동하면, 누적 적재되는 Thought 정보와 도구 피드백(Observation) 텍스트가 컨텍스트 윈도우 크기를 극도로 팽창시켜 치명적인 VRAM 포화(Out Of Memory) 병목을 유발합니다.
*   **어텐션 포화 및 정합 파라미터 유실 병목**: 프롬프트 대역폭이 불필요한 노이즈로 오염되면, 어텐션 가중치 점수가 사방으로 뭉개지면서 정작 다음 루프 단계에서 툴 명세를 엄격히 준수해야 하는 JSON Schema 생성 지침이나 핵심 규칙 토큰들의 기여도가 $0$에 가깝게 수축됩니다. 이는 툴 매개변수 문자열을 엉뚱하게 깨진 형태로 환각 출력해 시스템을 다운시키는 치명적인 런타임 중단 예외를 초래합니다.
*   **VRAM 연산 대역폭 사수를 위한 물리 제어 가이드**: 
    *   **엄밀한 온도 제어 (`0.0` 구속)**: 온도를 0으로 구속하여 동일 상태에 대한 도구 선택과 변수 할당의 안정성(Deterministic Path)을 완벽 수호해야 루프 도중 예측 불가능한 이탈 확률을 통계적으로 완전 박멸시킵니다.
    *   **컨텍스트 오프 로딩(Context Off-loading)**: 툴 실행 결과 획득한 수만 줄짜리 대규모 텍스트 데이터의 원시 스택 전체를 프롬프트 버퍼에 직접 밀어 넣지 않고, 로컬 영속 디렉토리에 격리 파일로 박제 오프로딩한 뒤, 컨텍스트 상에는 파일의 핵심 매트릭스 힌트만을 동적 슬라이딩 전치시키는 정합 캐싱 장치를 결합 적용해야 VRAM 연산 제곱 오버헤드 $O(T^2)$를 상수의 대역폭 내로 영구 구속할 수 있게 됩니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반 ReACT Single Agent 구현 소스코드
다음 소스코드는 파일 생성이나 시스템 라이브러리 연동 없이도 완벽하게 자율적인 Reasoning(추론) 및 Acting(도구 조작) 순환 제어를 달성하는 실전 ReACT Single Agent의 파이썬 마스터 스크립트 표준 규격입니다.

```python
import os
import operator
from typing import Annotated, Literal
from typing_extensions import TypedDict
from dotenv import load_dotenv

# LangChain 및 LangGraph 핵심 API 수입
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode

# 1. 시스템 구동 환경 변수 세팅
load_dotenv()
if not os.getenv("OPENAI_API_KEY"):
    os.environ["OPENAI_API_KEY"] = "your-openai-api-key"

# 2. 에이전트 가용 도구 표준 명세 정의 (@tool 데코레이터 빌드)
@tool
def search(query: str) -> str:
    """
    주어진 쿼리로 정보를 검색합니다.
    최신 정보나 사실 확인이 필요할 때 사용하세요.
    """
    # 로컬 가상 지식 DB 시뮬레이션 매핑
    mock_results = {
        "LangGraph": "LangGraph는 LangChain에서 만든 에이전트 워크플로우 프레임워크입니다. StateGraph를 사용하여 복잡한 에이전트 로직을 구현할 수 있습니다.",
        "ReACT": "ReACT는 Reasoning과 Acting을 결합한 에이전트 패턴으로, LLM이 추론과 행동을 번갈아 수행합니다."
    }
    
    for key, value in mock_results.items():
        if key.lower() in query.lower():
            return value
    return f"'{query}'에 대한 검색 결과: 관련 정보를 찾지 못했습니다."

@tool
def calculator(expression: str) -> str:
    """
    수학 표현식을 계산합니다.
    예: "2 + 3 * 4" 와 같은 수학 식을 입력으로 받습니다.
    """
    try:
        # 안전 격리되지 않은 실 서비스에서는 AST 파싱 또는 격리 컨테이너 런타임 구동 권장
        result = eval(expression)
        return f"{expression} = {result}"
    except Exception as e:
        return f"계산 오류: {str(e)}"

# 도구 바인딩용 리스트 객체화
tools = [search, calculator]

# 3. 에이전트 상태(State) 정의
# 직접 정의하여 상태 데이터 흐름을 추가 제어할 수 있는 TypedDict 레이아웃
class AgentState(TypedDict):
    messages: Annotated[list, operator.add]
    iteration_count: int  # 필요 시 루프 상한 컷오프를 강제하기 위한 상태 인자 추가

# 4. 모델 호출 노드 및 조건부 엣지 구현 (ReACT Core)
llm = ChatOpenAI(model="gpt-4.1-mini", temperature=0)
llm_with_tools = llm.bind_tools(tools)

SYSTEM_PROMPT = """You are a helpful AI assistant with access to tools.
Use the available tools to answer user questions accurately.
Think step by step and use tools when needed.
Always respond in Korean."""

def call_model(state: MessagesState):
    """LLM을 호출하여 추론 및 도구 호출 결정"""
    print("---🧠 REASONING (모델 호출 및 추론)---")
    messages = [SystemMessage(content=SYSTEM_PROMPT)] + state["messages"]
    response = llm_with_tools.invoke(messages)
    return {"messages": [response]}

def should_continue(state: MessagesState) -> Literal["tools", "end"]:
    """도구 호출 필요 여부 판별 라우팅"""
    last_message = state["messages"][-1]
    
    # 모델 출력 내부에 구체적인 tool_calls 명세가 할당되어 있다면 Acting 분기 전치
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        print("---🔧 ACTING (도구 호출 필요 감지)---")
        return "tools"
    
    # 도구 호출이 필요 없다면 최종 수렴 상태로 간주하고 END로 방출
    print("---✅ COMPLETE (태스크 무결 종결)---")
    return "end"

# prebuilt ToolNode 인스턴스화
tool_node = ToolNode(tools)

# 5. 상태 그래프(StateGraph) 조립 및 컴파일
workflow = StateGraph(MessagesState)

# 노드 추가 등록
workflow.add_node("call_model", call_model)
workflow.add_node("tools", tool_node)

# 정적 엣지 연결
workflow.add_edge(START, "call_model")

# 조건부 엣지 매핑
workflow.add_conditional_edges(
    "call_model",
    should_continue,
    {
        "tools": "tools",
        "end": END
    }
)

# 도구 노드 구동 완료 후 다시 생각 판단(Reasoning)으로 역회귀 연접
workflow.add_edge("tools", "call_model")

# 최종 무결 작동 실행기 컴파일 완성
react_agent = workflow.compile()
print("✅ ReACT 에이전트 시스템 컴파일 완료!")
```

### 3.2 핵심 아키텍처 제어 파라미터 매핑 분석
- **`temperature=0.0` 매핑**: 도구 선택 및 매개변수 바인딩 단계의 확률 분포 오차율을 기하학적으로 완전히 회수 소멸시키기 위한 필수 파라미터 세팅입니다. 온도가 영이 아닌 값으로 설정되면, 모델이 매 루프 반복 도중 미세하게 오타 섞인 JSON 구문이나 이미 시도해 에러 피드백을 받은 가짜 변수명 재생산하여 연산 루프 전체를 파멸적인 무한 데드락 상태로 영구 고착시키기 때문에 반드시 온도를 0으로 구속 통제해야 합니다.
- **`add_messages` 리듀서를 통한 상태 갱신 자동화**: call_model 노드가 생성한 AIMessage와 tools 노드가 실행 캡처해 반환한 ToolMessage(Observation)는 MessagesState 내부에서 자동으로 슬라이싱 머징(Merge)되어 축적됩니다. 이 정교한 리듀서 동기화 덕분에, 에이전트 아키텍처는 과거의 턴 이력을 수동으로 포맷팅하거나 텍스트를 연접(Append) 갱신해 주는 보일러플레이트 코드 한 줄 없이도, 이전 툴 실행 관찰 결과에 밀착 제정합된 최상의 다단계 Reasoning 판단 능력을 영위해 나갈 수 있습니다.
