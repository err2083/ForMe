# [CodeAct 에이전트와 격리된 샌드박스 실행 아키텍처]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 CodeAct와 전통적인 Function Calling의 패러다임 전환과 유연성 트레이드오프
전통적인 AI 에이전트 시스템에서 외부 환경에 영향을 미치는 액션(Action)은 주로 **정적 Function Calling(함수 호출)**에 구속되어 있었습니다. 개발자가 도구의 이름, 입력 매개변수 구조를 JSON Schema로 엄격히 규격화해 기저 언어 모델에 바인딩하면, 모델이 질문 맥락을 분석하여 필요한 매개변수를 추출해 내는 방식입니다. 이 방식은 실행 경로가 고도로 제약되어 있어 동작의 예측 가능성과 안정성을 완벽히 보장할 수 있다는 시스템적 강점을 지닙니다. 그러나 사전에 명시적으로 선언되지 않은 신규 API 호출이나 동적인 비즈니스 규칙 변화에는 유연하게 대응할 수 없는 치명적인 한계를 동반합니다.

**CodeAct(Code-Execution as Action) 패턴**은 이러한 정적 경계를 완전히 도파하여, 에이전트의 액션 자체를 **"실시간으로 실행 코드를 자동 생성하고 실행(Code-execution)하는 것"**으로 재정의합니다. 
*   **유연성(Flexibility)의 극대화**: 미리 정의된 정적 도구 라이브러리 없이도, 에이전트는 기저 LLM의 범용적인 언어 추론 및 코딩 성능에 기반하여 새로운 정렬 알고리즘을 즉석에서 작성하거나 복잡한 정규 표현식을 도출해 낼 수 있습니다.
*   **복잡한 연산 및 제어 흐름의 동적 처리**: 단순한 매개변수 치환을 넘어, 에이전트 스스로 중첩 루프(Nested Loops), 조건부 런타임 분기, 복잡한 예외 처리(Try-Except) 등의 프로그래밍 연산을 수반하는 복합 태스크를 제한 없이 설계하여 가동할 수 있습니다.
*   **대용량 데이터 변환과 파이프라인 자율 수립**: 원시 데이터 로그나 대형 CSV 파일이 유입될 때, 수백 번의 개별 API 요청을 연쇄 가동하여 컨텍스트 대역폭을 낭비하는 대신, 단 한 번의 판다스(Pandas) 데이터 프레임 쉘 스크립트 실행으로 메모리 내에서 대규모 가공 처리를 완수합니다.

### 1.2 로컬 exec()의 파멸적 취약성과 클라우드 격리형 E2B 샌드박스 아키텍처의 필연성
CodeAct 패턴을 실현하는 가장 원초적이고 빠른 구현체는 로컬 런타임 상에서 파이썬의 내장 함수인 `exec()` 또는 `eval()`을 직접 가동하는 **로컬 REPL(Read-Eval-Print Loop) 도구**입니다. 하지만 이 기조는 프로덕션 비즈니스 환경에서 인프라 전체를 붕괴시킬 수 있는 치명적인 보안 무력화 위협을 영구적으로 내포합니다.
*   **쉘 주입 및 호스트 OS 권한 장악 위협**: 사용자가 에이전트 프롬프트에 악의적인 명령을 주입하거나(Prompt Injection), 가동 중인 코드가 외부 패키지 모듈을 은밀히 이식하여 호스트 OS의 시스템 명령을 가동하는 경우(`__import__('os').system('rm -rf /')`), 메인 호스트 디렉토리 내의 파일이 영구 파괴되거나 데이터베이스 기밀 토큰이 외부로 유실되는 대재앙이 초래됩니다.
*   **시스템 자원 고갈(DoS) 및 교란 상황**: 루프 탈출 조건이 누락된 무한 루프 코드나, VRAM/RAM 가상 메모리 스택 전체를 잠식하는 메모리 포이즈닝 스크립트가 빌드 및 실행될 경우, 물리 머신의 가용 하드웨어 자원이 즉각 고갈되어 서비스 전체가 정지 상태에 수렴하게 됩니다.

이러한 물리적 붕괴 위협을 완벽히 격리 우회하기 위해, 엔터프라이즈 에이전트 인프라와 서비스는 **E2B(Environment to Build)와 같은 클라우드 격리형 MicroVM 샌드박스 아키텍처**를 의무 장착하여 통합합니다.
*   **초고속 격리 가상 머신(Secure SandboxVM)**: 약 150ms 내외의 극히 짧은 레이턴시 동안 호스트 운영체제와 완벽하게 망 격리 및 리소스 커널 격리가 수립된 가상 인프라 컨테이너를 동적으로 부팅합니다.
*   **커널 및 물리 자원 제약 관리**: 샌드박스 내부에서 어떠한 파괴적이거나 오작동하는 임의의 코드가 가동되더라도, 그 영향 범위는 즉시 휘발 소멸될 가상 디바이스 디렉토리 범위 내로 안전하게 제한 구속됩니다. 호스트 머신의 시스템 콜 전송 흐름은 인프라 하드웨어 하이퍼바이저 수준에서 철저하게 방어 정화됩니다.
*   **지속성(Persistence)을 갖춘 대화 상태 보존**: 내장된 Jupyter 서버 커널이 샌드박스 상에 영속 실행되어, 첫 번째 턴에서 선언한 데이터 변수나 판다스 데이터 프레임 상태 매트릭스가 다음 턴의 연쇄 실행 세션 간에도 흐트러짐 없이 유지되도록 이끌어 줍니다.

### 1.3 상태 그래프 직접 제어(StateGraph)와 상위 추상화 API(create_agent)의 제어 주권 격차
CodeAct 에이전트를 실현하는 소프트웨어 개발 설계 방식은 크게 LangGraph의 로우레벨 `StateGraph` 구조 설계와, 최상위 도구 추상화 프레임워크가 제공하는 `create_agent` 패키징 모델로 명확하게 이원화 분수령을 이룹니다.

*   **StateGraph 직접 제어 (로우레벨 제어 주권 수호)**:
    개발자가 `START -> call_model -> tools -> call_model -> END` 형태의 상태 천이 노드와 조건부 분기 엣지를 명시적인 파이썬 클래스 및 함수 수준에서 유기적으로 핸드코딩합니다. 이 구조 하에서 에이전트의 작동 흐름은 완벽하게 예측 가능하고 투명하게 시각화(Mermaid PNG)되며, 도중 예외 상황이나 특정 컴파일 에러 발생 시 상태 리듀서(Reducer) 세부 조작이나 메모리 보존 영역 디버깅을 미세 튜닝하여 비결정론적 동적 에이전틱 루프를 완전히 장악 통제할 수 있습니다.
*   **create_agent 추상화 API (신속한 프로토타이핑 엑셀러레이터)**:
    LangChain 또는 모델 SDK 라이브러리 상단에서 한 줄의 함수 선언만으로 자율 ReAct 루프 전체를 자동 오케스트레이션하여 구동시켜 줍니다. 계획 수립과 도구 바인딩 호출 감지, 오류 발생 시 동적 백트래킹(Self-Correction) 연쇄 처리가 내장 엔진 이면의 블랙박스 레이어에서 알아서 수행되므로 개발 생산성이 비약적으로 증진됩니다. 그러나 다단계 루프 도중 특정 지점에서 런타임 제어 인입 가이드라인을 강제 마운트하거나, 상태 텐서의 정밀 제어를 가동해야 할 때 미세 개입 통로가 차단되어 고도화 디버깅이 사실상 불가능하다는 트레이드오프가 수반됩니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 CodeAct 자율 에이전트의 종단간(End-to-End) 데이터 흐름 및 상태 전이도
아래 아키텍처 흐름도는 사용자가 입력한 거시적 분석 태스크로부터 에이전트가 최적의 해결 논리 코드를 자율 작성하고, 격격히 차단된 E2B 클라우드 샌드박스 런타임에 인입 기동하여, 얻어진 출력 결과와 시스템 트레이스 피드백을 단기 메모리에 머징 연접하며 완결 답변을 완성하는 전 과정의 유기적 데이터 전이 파이프라인을 묘사합니다.

```
[사용자 거시적 분석 지시 인입 (User Target Query)]
  - "netflix_titles.csv 분석 후 연도별 콘텐츠 시각화 차트를 png로 저장해줘"
       │
       ▼ [State: MessagesState 세션 초기화 완료]
[call_model 노드 기동 (Reasoning & Code-Generation)] ◄─────────────────────────┐
  - SYSTEM_PROMPT + state["messages"] 기반 LLM 프리필 추론 연산                 │
  - 대상 CSV 분석에 필요한 최적의 pandas & matplotlib 스크립트 자율 설계          │
       │                                                                       │
       ▼ [AIMessage 출력: tool_calls 감지]                                      │
[should_continue 조건부 엣지 판독 레이어]                                       │
  - 생성된 코드 블록 매개변수를 E2B 가상 샌드박스 툴로 리라우팅 전치                  │
       │                                                                       │
       ▼ [E2B e2b_code_interpreter 툴 호출]                                    │
[격리된 클라우드 가상 샌드박스 VM 구동 (Physical Action)]                          │
  - sandbox.files.write() 로컬 CSV 파일 VM 디바이스 디렉토리에 선제 가용 마운트   │
  - sandbox.run_code(generated_code) 동기화 파이썬 프로세스 물리 부팅            │
  - stdout / stderr 스트림 캡처 및 바이너리 이미지 디스크 격리 저장              │
       │                                                                       │
       ▼ [Observation 데이터 확보]                                              │
[ToolMessage 생성 및 누적 업데이트] ───────────────────────────────────────────┘
  - VM 가동 피드백 수집: "matplotlib 차트가 vis_result.png 로 정상 저장됨"
  - state["messages"] 에러 유무 확인 후 다음 추론 루프로 피딩 역회귀
       │
       ▼ [최종 정답 도달 확인: tool_calls 부재 시 수렴 상태 전이]
[final_output 디코딩 및 사용자 전송 반환]
  - 샌드박스 디바이스 디렉토리에서 vis_result.png 이미지 base64 인출 후 로컬 복구 저장
  - 최종 정제 분석 텍스트 출력 완수
       │
       ▼
     [END]
```

### 2.2 대규모 코드 가동 세션에서의 파일 오프로딩(Context Off-loading) 및 VRAM 최적화
CodeAct 에이전트가 판다스를 이용한 탐색적 데이터 분석(EDA)이나 대형 파일 입출력 다단계 코딩 루프를 거듭 구동하게 되면, 샌드박스로부터 리턴되는 대용량 중간 원시 텍스트 로그, 엑셀 덤프 리스트, 바이너리 이미지 픽셀 텐서 정보들이 프롬프트 입력 영역 맨 아래에 무제한 누적 연접되는 가혹한 컨텍스트 부패(Context Rot) 병목을 마주하게 됩니다.
*   **어텐션 맵 붕괴 및 VRAM 연산 폭증**: 입력 토큰 길이 $T$가 점진적으로 팽창함에 따라 VRAM 하드웨어 소요 연산 공간 복잡도는 $O(T^2)$를 그리며 기하급수적으로 수직 상승합니다. 이로 인해 모델의 제한된 어텐션 에너지 자원이 불필요한 날것의 원시 CSV 라인 텍스트 찌꺼기에 사방 분산 포화되어, 다음 루프 단계에서 모델이 준수해야 할 엄격한 시스템 코딩 지침이나 파일 접근 경로명 등의 핵심 시스템 프롬프트 토큰들을 망각(Lost in the Middle)하여 도구 선택 판단이 영구 탈조되는 위협이 유발됩니다.
*   **파일 오프로딩(Context Off-loading)을 통한 최적화 메커니즘**:
    CodeAct 아키텍처는 수만 토큰 크기를 뛰어넘는 원시 데이터를 LLM 입력 콘텍스트에 직접 연접 적재하지 않습니다. 대신, 원시 리스트와 바이너리 미디어 파일 전체를 가상 파일 시스템 디스크(E2B VM 디렉토리)에 `home/user/netflix_titles.csv`와 같은 격리 파일 형태로 안전하게 가두어 둡니다.
*   **초경량 메타 정합 텐서 전이 정책**:
    에이전트 단기 메모리 프롬프트 버퍼에는 오직 파일의 상대적 보관 경로, 컬럼 헤더 이름, 데이터의 기본 스칼라 행 수 등의 한 단락짜리 핵심 의미 메타 매트릭스 정보만을 축약 적재하여 전이시킵니다. 이 물리적 이원화 오프로딩 파이프라인 덕분에, 입력 토큰의 총량은 상수의 골디락스 대역폭 내로 완벽히 묶여 유지되며, 트랜스포머의 어텐션 포화 부하가 원천 소멸되어 최종 답변의 사실 무결 정합성을 완벽하게 보존해 냅니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반의 로컬 REPL CodeAct 에이전트 시스템 구현
다음 소스코드는 파일 생성이나 시스템 라이브러리 연동 없이도, 완벽하게 자율적인 파이썬 코드 생성(Reasoning) 및 `sys.stdout` 인터셉트 기반의 로컬 런타임 코드 실행(Action) 루프 전체를 제어하는 단일 오케스트레이터의 실전 파이썬 프로덕션 구현 표준 스크립트입니다.

```python
import os
import sys
from io import StringIO
from typing import Annotated, Literal
from typing_extensions import TypedDict
from dotenv import load_dotenv

# LangChain 및 LangGraph 최신 API 수입
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode

# 1. 런타임 환경 세팅 및 API Key 영점 조절
load_dotenv()
api_key = os.getenv("OPENAI_API_KEY", "MOCK_KEY_FOR_SAFETY")

# 2. 로컬 실행을 위한 Python REPL 도구 설계 (AST 사전 가드레일 레이어 권장)
@tool
def python_repl_tool(code: str) -> str:
    """
    입력된 파이썬 코드를 로컬 가상 환경 인터프리터 상에서 실행하고 stdout 출력 결과를 반환합니다.
    데이터 수치 연산, 정렬, 문자열 정제 등의 다양한 로직 처리에 자율 기동하십시오.
    
    Args:
        code: 실행할 원시 파이썬 소스코드 문자열
    """
    # 호스트 표준 출력을 캡처하기 위한 StringIO 버퍼 스위칭
    old_stdout = sys.stdout
    captured_output = StringIO()
    sys.stdout = captured_output
    
    try:
        # 안전한 빌트인 함수 목록만을 격리 매핑한 가상 글로벌 네임스페이스 구성
        safe_globals = {"__builtins__": __builtins__}
        exec(code, safe_globals)
        output = captured_output.getvalue()
        return output if output.strip() else "코드가 성공적으로 실행되었으나 반환된 stdout 출력 결과가 비어 있습니다."
    except Exception as e:
        # 런타임 실행 중 발생한 구문/논리 에러 트레이스백 피드백 복구
        return f"실행 실패 - 에러 타입: {type(e).__name__} | 상세 메시지: {str(e)}"
    finally:
        # 캡처 스위칭 해제 및 표준 출력 복원
        sys.stdout = old_stdout

# 도구 바인딩용 컨테이너화
repl_tools = [python_repl_tool]

# 3. CodeAct 에이전트 의사결정 브레인 모델 컴파일 (temperature 결정화)
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.0, openai_api_key=api_key)
llm_with_repl = llm.bind_tools(repl_tools)

# 4. 에이전트가 코드를 무결하게 빌드하도록 강제하는 마스터 지침 프롬프트 설계
CODEACT_SYSTEM_MANIFESTO = """당신은 주어진 복잡한 문제를 해결하기 위해 스스로 최적의 파이썬 코드를 정밀 설계하고 직접 실행하는 최고 성능의 CodeAct 에이전트입니다.

행동 강령 지침:
1. 사용자의 요구사항을 심층 분석하여 하위 연산 계획들을 자율적으로 정립하십시오.
2. 해결에 필수적인 파이썬 코드 블록을 설계하고, 'python_repl_tool' 도구를 사용하여 실행하십시오.
3. 코드 작성 시 결과 확인을 위해 반드시 print() 구문을 포함하여 표준 출력을 방출하십시오.
4. 실행 결과 유입된 stdout 피드백(Observation)에 에러가 존재한다면 즉시 자가 수정(Self-Correction)하여 코드를 전면 재빌드 실행하십시오.
5. 반드시 정제된 한국어로 답변의 요점을 간결하고 논리적으로 증명하여 완수하십시오."""

def call_codeact_model(state: MessagesState):
    """LLM을 기동하여 현재 상태 이력 분석 및 코드 실행 판단"""
    print("\\n---🧠 CODEACT REASONING (코드 생성 및 계획 수립)---")
    messages = [SystemMessage(content=CODEACT_SYSTEM_MANIFESTO)] + state["messages"]
    response = llm_with_repl.invoke(messages)
    return {"messages": [response]}

def should_continue_loop(state: MessagesState) -> Literal["execute_code", "terminate_loop"]:
    """도구 호출 필요 여부 판독 분기 조건부 엣지"""
    last_msg = state["messages"][-1]
    
    # 모델 출력 결과 내부에 구체적인 tool_calls 명세가 주입되어 있다면 코드 실행 노드로 전치
    if hasattr(last_msg, "tool_calls") and last_msg.tool_calls:
        print("---🔧 CODEACT ACTION (E2B/로컬 코드 실행 전치)---")
        return "execute_code"
    
    # 더 이상의 코드 가동 필요 없이 수렴 정답 도달 판단 시 루프 종결 END 방출
    print("---✅ CODEACT COMPLETE (태스크 수렴 종결)---")
    return "terminate_loop"

# 5. LangGraph 상태 머신 컴파일 및 시각화용 노드 빌딩
workflow = StateGraph(MessagesState)

# 독립 기동 노드 등록
workflow.add_node("call_codeact_model", call_codeact_model)
workflow.add_node("execute_code", ToolNode(repl_tools))

# 그래프 간 이동 엣지 결합
workflow.add_edge(START, "call_codeact_model")

# 조건부 엣지 매핑을 통해 ReAct 순환 루프 설계
workflow.add_conditional_edges(
    "call_codeact_model",
    should_continue_loop,
    {
        "execute_code": "execute_code",
        "terminate_loop": END
    }
)

# 도구 노드 실행 완료 후 다시 생각 판단(Reasoning)으로 피딩 회귀
workflow.add_edge("execute_code", "call_codeact_model")

# 복합 컴파일 수행
codeact_agent = workflow.compile()
```

### 3.2 E2B 샌드박스 기반의 격리형 데이터 분석 워크플로우 분석
실제 상용 서비스나 사내 데이터 분석 인프라에 CodeAct를 전개할 때는 위의 로컬 가상 구현을 탈피하여, E2B SDK의 `Sandbox` 객체 기능을 융합 매핑합니다.

```python
from e2b_code_interpreter import Sandbox

@tool
def e2b_code_interpreter_tool(code: str) -> str:
    """
    E2B 클라우드 가상 보안 샌드박스 내부의 독자적인 Jupyter 커널 상에서 파이썬 코드를 실행하고 
    변수 상태가 영속 보존되는 실행 결과 로그를 즉시 캡처하여 반환합니다.
    """
    # 런타임 보안 세션이 수립된 MicroVM 인스턴스에 즉각 접속 가동
    # 실제 연동 시 sandbox 객체는 싱글톤이나 세션 관리자로 유지보수 가동
    sandbox = Sandbox.create()
    execution = sandbox.run_code(code)
    
    output_parts = []
    # 1. 셀 내의 마지막 반환값 표현식 캡처
    if execution.text:
        output_parts.append(execution.text)
    # 2. 실행 프로세스 표준 출력 스트림 캡처
    if execution.logs.stdout:
        output_parts.append("".join(execution.logs.stdout))
    # 3. 런타임 에러 트레이스백 캡처
    if execution.error:
        output_parts.append(f"런타임 오류 발생: {execution.error.name} - {execution.error.value}")
        
    return "\\n".join(output_parts) if output_parts else "코드가 성공적으로 가동 완료되었습니다."
```
- **상태 영속 보존(Session Keep-Alive)**: `e2b_code_interpreter_tool` 내부의 `sandbox` 인스턴스는 단일 대화 스레드 동안 사멸하지 않고 활성 상태가 유지됩니다. 따라서 사용자가 1차로 데이터셋을 업로드한 뒤 다른 질문으로 "저장된 데이터를 기반으로 분기 시각화 차트를 그려달라"고 연속 질의하여도, 에이전트는 이미 Jupyter 커널 메모리에 적재되어 있는 데이터 프레임 텐서를 즉각 재활용하여 연속성 높은 추론 분석을 완수해 냅니다.
