# [MoA(Mixture of Agents)로 AI 답변 종합하기]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 Mixture of Agents (MoA) 패턴의 아키텍처적 본질과 분산 협업 구조
단일 거대 언어 모델(LLM)이 복잡하고 다각적인 분석 태스크를 홀로 처리할 때 발생하는 '인지적 과부하'와 '단일 관점 편향'을 타개하기 위한 아키텍처 패턴으로 **Mixture of Agents (MoA)**가 부각되고 있습니다. 
*   **MoA의 핵심 사상**: MoA는 여러 독립적인 하위 전문 에이전트(Proposers/Analysts)를 병렬로 배치하여 서로 다른 관점이나 영역의 정보를 탐색 및 생성하게 하고, 이를 하나의 중앙 수렴기(Aggregator)가 취합·정제하여 단일 초고품질 응답을 도출하는 융합형 추론 아키텍처를 표방합니다.
*   **다관점 리서치(Multi-perspective Research)의 분리**: 실무 금융 조사 태스크를 예로 들면, 동일한 기업에 대해 시장 동향(Market Trend), 잠재적 위험(Risk), 신사업 기회(Opportunity)라는 서로 직교하는 관점을 지닌 3개의 에이전트가 병렬로 가동됩니다. 이는 단일 에이전트가 세 가지 관점을 동시에 분석할 때 범하기 쉬운 누락이나 특정 주제 편향을 원천 배제하는 '관심사 분리(Separation of Concerns)' 원칙을 엄밀히 실현합니다.

### 1.2 LangGraph에서의 병렬 노드 실행(Fan-Out / Fan-In)과 동적 수렴 제어
LangGraph는 선형 체인을 넘어 순환(Cycle)과 병렬 처리를 직관적으로 제어할 수 있는 저수준 상태 머신을 제공하여 MoA 패턴의 완벽한 런타임 제어 오케스트레이션을 보증합니다.
*   **정적 Fan-Out & Fan-In의 물리적 전이**: 사용자의 질의가 인입되는 초기 상태(MoAState)로부터 3개의 독립적인 노드(`market_research`, `risk_research`, `opportunity_research`)로 제어권이 동시 분기(Fan-Out)됩니다. 각 노드는 자신에게 인가된 고유의 시스템 메시지와 분석 역할을 가지고 독립적인 추론 및 도구 연산 세션을 개진합니다.
*   **수렴 제어선(Fan-In)과 Aggregator의 역할**: 병렬로 동작한 하위 에이전트들의 독립적인 보고서 텍스트들이 각각의 지정 필드(`market_report`, `risk_report`, `opportunity_report`)에 완벽하게 적재될 때까지 시스템은 대기하며, 모든 보고서가 채워진 상태 텐서가 완성되는 시점에 한해 `aggregator` 노드로의 동기식 병합 수렴(Fan-In)이 강제 실행됩니다. Aggregator 노드는 기저 LLM을 고성능 편집장(Editor-in-Chief) 페르소나로 마운트하여, 관점 간의 중복된 중언부언을 정제 통합하고, 정보 간 충돌이 있을 경우 논리적 양비론을 상술함으로써 정보 무결성을 지닌 단일 완성형 보고서(`final_answer`)를 디코딩 생성합니다.

### 1.3 EXA Search API 기반 시맨틱(Neural) 웹 검색 및 전송 미들웨어의 설계
현대 정밀 지식 인프라에서 단순 키워드 매치 기반의 BM25 검색이 지닌 한계(동의어 누락, 스팸 노이즈 유입)를 우회하기 위해, 고차원 의미 표상 공간에서의 벡터 유사도 매핑에 기반한 EXA Search API를 RAG 검색기로 기동합니다.
*   **rps(Rate Per Second) 및 재시도(Retry) 거버넌스 미들웨어**: 병렬 에이전트가 동시에 웹 검색 도구(`exa_search`)를 타격할 때 유발되는 API 초과 호출 오류(429 Too Many Requests)와 네트워크 일시 단절을 방지하기 위해 도구 전단에 견고한 미들웨어를 장착합니다.
    *   **ToolCallLimitMiddleware**: 최근 1초 내의 도구 호출 상한(RPS) 및 스레드 풀 크기를 동적 제약하여 인프라 트래픽을 정밀 스케줄링합니다.
    *   **ToolRetryMiddleware**: API 실패 감지 시 지수 백오프(Exponential Backoff, 예: `backoff_factor=2.0`, `initial_delay=1.0s`)를 동반한 자동 재시도 루프(최대 3회)를 가동하여 런타임 수명 주기의 영속성을 방어합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 MoA 금융 조사 워크플로우의 종단간(End-to-End) 데이터 흐름 및 상태 전이도
아래 흐름도는 단일 기업명 쿼리로부터 3대 리서치 노드가 분기하여 EXA 시맨틱 웹 API를 병렬 구동하고, 관점별 부분 텍스트를 메모리에 개별 적재한 뒤 Aggregator 노드를 거쳐 완전한 금융 보고서 구조체로 수렴하기까지의 전 과정 텐서 흐름을 묘사합니다.

```
[사용자 타겟 기업명 입력 (user_input: "삼성전자")]
       │
       ▼ [State: MoAState 생성 초기화]
[Fan-Out: 병렬 분기 발생] ────────────────────────────────────────────────────────┐
       │                                         │                                 │
       ▼                                         ▼                                 ▼
[market_research 노드]                    [risk_research 노드]             [opportunity_research 노드]
 - exa_search 시맨틱 검색                  - exa_search 시맨틱 검색           - exa_search 시맨틱 검색
 - 산업/시장 동향 분석                      - 규제/지정학 리스크 분석          - 핵심 성장 촉매 분석
       │                                         │                                 │
       ▼                                         ▼                                 ▼
[market_report 갱신]                      [risk_report 갱신]               [opportunity_report 갱신]
       │                                         │                                 │
       └─────────────────────────────────────────┼─────────────────────────────────┘
                                                 ▼ [Fan-In: 동기식 수렴 발생]
                                          [aggregator 노드 가동]
                                           - 3대 분석서 편집장 융합 정제
                                           - 중복 병합 및 논리 모순 조율
                                                 │
                                                 ▼ [final_answer 상태 작성]
                                               [END]
```

### 2.2 No-Share 메모리 격리와 메시지 패싱(Message Passing)을 통한 VRAM 최적화
전형적인 멀티 에이전트 세션에서 범하기 쉬운 치명적 오류는 모든 에이전트가 단일 전역 메시지 이력(`List[BaseMessage]`)을 물리적으로 공유하게 설계하는 것입니다.
*   **전역 메시지 공유의 병목 인과관계**: 3개의 에이전트가 각각 EXA 웹 검색을 통해 수천 자 분량의 원시 html 텍스트와 하이라이트 문장을 메시지 이력에 무제한 누적 적재하면, 최종 병합 단계에서 컨텍스트 윈도우의 임계치(Context Window Limit)가 수십만 토큰에 육박하게 됩니다. 이는 트랜스포머의 계산 복잡도 $O(T^2)$에 의거하여 기하급수적인 VRAM 폭주와 TTFT 성능 하락을 촉발합니다.
*   **No-Share 격리 및 텍스트 캡슐화 설계**:
    MoAState는 각각의 관점 보고서 필드(`market_report`, `risk_report`, `opportunity_report`)를 문자열 형태로 독립 캡슐화합니다. 병렬 노드들은 자신만의 아주 좁고 깨끗한 단기 메모리 윈도우에서 LLM 추론을 독립 실행한 뒤, 오직 최종 요약 정제된 텍스트 결과(Result)만을 상위 상태 변수로 전달(Message Passing)합니다. 이 구조적 분리 덕분에, 최종 Aggregator 노드에 인입되는 입력 컨텍스트 버퍼 크기는 수십만 토큰에서 5,000토큰 미만으로 극적으로 선형 압축되며, VRAM 연산 제곱 오버헤드를 완벽히 박멸하는 물리적 하드웨어 이점을 보장합니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반 MoA 금융 조사 워크플로우 소스코드
다음 소스코드는 LangGraph의 병렬 분기/합성 사상과 EXA Search API 및 호출 제한 미들웨어를 시스템 프로덕션 표준 규격에 맞게 설계하여 무결 가동하는 파이썬 스크립트입니다.

```python
import os
import math
from typing import Dict, Any, List, TypedDict
from dotenv import load_dotenv

# LangChain 및 LangGraph 핵심 API 수입
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
from langchain.agents import create_agent
from langchain.agents.middleware import ToolCallLimitMiddleware, ToolRetryMiddleware
from langchain_core.tools import tool
from langgraph.graph import StateGraph, START, END

load_dotenv()
api_key = os.getenv("OPENAI_API_KEY", "MOCK_KEY_FOR_SAFETY")
exa_api_key = os.getenv("EXA_API_KEY", "MOCK_EXA_KEY_FOR_SAFETY")

# =====================================================================
# 1. EXA Search API 표준화 및 수치적 미들웨어 바인딩
# =====================================================================

@tool
def exa_search_tool(query: str, num_results: int = 3) -> str:
    """
    EXA API를 통하여 웹 상의 최신 시맨틱 검색을 수행합니다.
    검색어에 가장 인접한 핵심 정보 블록과 요약 하이라이트를 고해상도 인출합니다.
    """
    # 실무 환경에서는 exa_client.search_and_contents() 타격
    # 여기서는 정량적 응답 시뮬레이터 가동
    mock_responses = {
        "삼성전자 시장점유율": "2025년 기준 삼성전자의 글로벌 D램 메모리 시장 점유율은 약 44.5%로 업계 1위를 공고히 유지하고 있으며, 파운드리 부문은 12.3%의 점유율로 TSMC에 이어 2위를 기록 중입니다.",
        "삼성전자 규제 리스크": "미-중 반도체 패권 갈등에 따른 미 행정부의 첨단 장비 반도체 수출 제한 조치 및 관세 정책 다변화가 주된 외부 거시 리스크 요인으로 작용하고 있습니다.",
        "삼성전자 성장 동력": "AI 인프라 급증에 따른 6세대 HBM4 제품의 공급망 진입 및 고성능 CXL 메모리 표준 주도가 차세대 주성장 촉매로 평가받고 있습니다."
    }
    
    for key, val in mock_responses.items():
        if key in query:
            return f"[EXA_RESULT] 쿼리: {query} | 결과: {val}"
    return f"[EXA_RESULT] 쿼리: {query} | 최신 반도체 시장 동향 및 고성능 메모리 수요 추이 분석 완료."

# 초당 호출 수(RPS) 스케줄링을 위한 제한 제약선 인프라 마운트
exa_limit_middleware = ToolCallLimitMiddleware(
    tool_name="exa_search_tool",
    thread_limit=3,   # 동시 병렬 스레드 상한
    run_limit=5       # 초당 최대 호출 수(RPS) 5회 규제
)

# API 일시 단절 및 429 과부하 복원을 위한 백오프 리트라이 장치 마운트
exa_retry_middleware = ToolRetryMiddleware(
    max_retries=3,
    backoff_factor=2.0,
    initial_delay=1.0
)

# =====================================================================
# 2. 전역 상태 구조 및 분점 리포트 격리 필드 정의
# =====================================================================
class MoAState(TypedDict, total=False):
    user_input: str          # 목표 조사 대상 (예: "삼성전자")
    market_report: str       # 시장 분석 에이전트 생성 보고서
    risk_report: str         # 리스크 분석 에이전트 생성 보고서
    opportunity_report: str  # 기회 탐색 에이전트 생성 보고서
    final_answer: str        # Aggregator가 통합 편집한 종합 보고서

# =====================================================================
# 3. 3대 분점 전문가 에이전트 및 Aggregator 구현
# =====================================================================
analyst_llm = ChatOpenAI(model="gpt-4.1-mini", temperature=0.0, openai_api_key=api_key)

# 3.1 시장 분석 에이전트 노드
market_agent_core = create_agent(
    model=analyst_llm,
    tools=[exa_search_tool],
    system_prompt="당신은 최고의 시장 분석 전문가입니다. 대상 기업의 시장 규모, 점유율, 최근 실적을 exa_search_tool을 적극 구동해 팩트 위주로 분석하십시오.",
    middleware=[exa_limit_middleware, exa_retry_middleware]
)

def market_research_node(state: MoAState) -> Dict[str, Any]:
    print("---📊 [NODE] RUNNING MARKET RESEARCH ---")
    query = state["user_input"]
    result = market_agent_core.invoke({"messages": [HumanMessage(content=f"{query} 시장점유율 및 실적 분석")]})
    return {"market_report": result["messages"][-1].content}

# 3.2 리스크 분석 에이전트 노드
risk_agent_core = create_agent(
    model=analyst_llm,
    tools=[exa_search_tool],
    system_prompt="당신은 정밀 리스크 위험 평가관입니다. 기업이 직면한 글로벌 규제, 거시 경제 위협, 공급망 병목을 exa_search_tool로 검색하여 사실 입각 분석하십시오.",
    middleware=[exa_limit_middleware, exa_retry_middleware]
)

def risk_research_node(state: MoAState) -> Dict[str, Any]:
    print("---⚠️ [NODE] RUNNING RISK RESEARCH ---")
    query = state["user_input"]
    result = risk_agent_core.invoke({"messages": [HumanMessage(content=f"{query} 규제 및 거시경제 리스크 분석")]})
    return {"risk_report": result["messages"][-1].content}

# 3.3 기회 탐색 에이전트 노드
opportunity_agent_core = create_agent(
    model=analyst_llm,
    tools=[exa_search_tool],
    system_prompt="당신은 미래 성장 동력 발굴관입니다. 기업의 신기술 사업 기회, 촉매 이벤트, 투자 매력도를 exa_search_tool을 기동하여 예리하게 분석하십시오.",
    middleware=[exa_limit_middleware, exa_retry_middleware]
)

def opportunity_research_node(state: MoAState) -> Dict[str, Any]:
    print("---🚀 [NODE] RUNNING OPPORTUNITY RESEARCH ---")
    query = state["user_input"]
    result = opportunity_agent_core.invoke({"messages": [HumanMessage(content=f"{query} 성장 동력 및 미래 기회 분석")]})
    return {"opportunity_report": result["messages"][-1].content}

# 3.4 Aggregator (통합 및 모순 교정 노드)
aggregator_llm = ChatOpenAI(model="gpt-4.1", temperature=0.2, openai_api_key=api_key)

def aggregator_node(state: MoAState) -> Dict[str, Any]:
    print("---✍️ [NODE] RUNNING AGGREGATOR ---")
    topic = state["user_input"]
    market = state["market_report"]
    risk = state["risk_report"]
    opportunity = state["opportunity_report"]
    
    compilation_prompt = (
        f"당신은 글로벌 투자 보고서의 수석 편집장입니다. 아래의 세부 분석가들의 보고서를 기반으로 "
        f"중복 문장을 전량 소거하고 모순 요소를 정합 조율하여, 최고 품질의 [{topic}] 금융 조사 보고서를 완성하십시오.

"
        f"### 1. 시장 분석 파트:
{market}

"
        f"### 2. 리스크 분석 파트:
{risk}

"
        f"### 3. 기회 탐색 파트:
{opportunity}

"
        f"출력은 소제목을 갖춘 마크다운 형식으로 작성하십시오."
    )
    
    response = aggregator_llm.invoke([HumanMessage(content=compilation_prompt)])
    return {"final_answer": response.content}

# =====================================================================
# 4. StateGraph를 통한 병렬 오케스트레이션 조립 및 컴파일
# =====================================================================
workflow = StateGraph(MoAState)

# 노드 등록
workflow.add_node("market_research", market_research_node)
workflow.add_node("risk_research", risk_research_node)
workflow.add_node("opportunity_research", opportunity_research_node)
workflow.add_node("aggregator", aggregator_node)

# START에서 3개 노드로 Fan-Out (병렬 동시 시작)
workflow.add_edge(START, "market_research")
workflow.add_edge(START, "risk_research")
workflow.add_edge(START, "opportunity_research")

# 3개 노드에서 aggregator로 Fan-In (모든 연산 완료 후 수렴)
workflow.add_edge("market_research", "aggregator")
workflow.add_edge("risk_research", "aggregator")
workflow.add_edge("opportunity_research", "aggregator")

# 종단선 설정
workflow.add_edge("aggregator", END)

# 물리 컴파일 완성
moa_financial_agent = workflow.compile()
print("✅ MoA 금융 조사 워크플로우 그래프 빌드 완료!")
```

### 3.2 아키텍처적 제어 매개변수와 성능 지표 매핑 분석
- **`total=False` 지정을 포함한 독립적 상태 필드 매핑**:
  - `MoAState` 선언 시 `total=False` 지정을 통해 3개 독립 노드의 병렬 연산 완료 시점에 전체 키셋(Keyset)의 무결 보존을 강제하지 않고, 해당 노드의 보고서 필드만 부분 업데이트(Delta Update)하도록 설계합니다. 이는 상태 전이의 무결성을 보증하고 동시성 충돌을 미연에 사수합니다.
- **Aggregator의 `temperature=0.2` 설정 기조**:
  - 하위 분석가들의 보고서를 취합할 때 모델의 온도가 높게 책정되면, 원문 보고서에 명시되지 않은 허구의 시장 전망 수치나 기적의 투자 시나리오를 창작해 내는 환각(Hallucination)이 급격히 증가합니다. 따라서 온도를 0.2 이하의 낮은 결정론적 범위로 구속 제어하여 팩트 기반의 문장 소거 및 구조적 정합성만을 엄격히 달성하도록 규제합니다.

이때 발생하는 물리적 재앙은 다음과 같습니다:
1) **어텐션 확률 희석**: 정답 도출에 핵심적인 시스템 명령 지침문 토큰 $i$의 기여 비중인 $	ext{softmax}(\mathbf{scores})_i$가 수만 개의 무관한 검색 본문 노이즈 토큰 분모항에 파묻혀 $0$에 극단적으로 수축(Attention Saturation)합니다. 이로 인해 최종 취합 단계에서 수치 오정합이나 환각 답변을 범하게 됩니다.
2) **하드웨어 과부하**: 연산량이 9배 이상 기하급수적으로 폭증하여 GPU VRAM 점유량이 임계점을 초과하고, 서빙 응답 속도(TTFT)가 가혹하게 저하됩니다.

1) **ToolCallLimitMiddleware를 통한 RPS 병목 동결**: 토큰 리프레시 버킷(Token Bucket) 또는 슬라이딩 윈도우 카운터 알고리즘을 툴 실행 제어기 전단에 이식합니다. 병렬 스레드가 아무리 일시에 실행을 지시해도 미들웨어는 동시 처리 가용 풀 크기를 `thread_limit=3`으로 구속하고, 최근 1초 내 누적 카운트를 감시하여 호출율이 임계인 `run_limit=5`에 육박 시 나머지 스레드를 비동기 대기 큐(Queue)에 잠시 홀드(Suspend)시킴으로써 트래픽을 상시 하한 마진 아래로 강제 균등 정렬합니다.

   $$	ext{Delay}(n) = 	ext{initial\_delay} 	imes (	ext{backoff\_factor})^{n-1} \pm 	ext{jitter}$$
   매회차 실패 시 지연 시간을 기하급수적으로 늘려 외부 서버의 물리적 복원 여유 시간을 제공하고, 미세한 무작위 변수(Jitter)를 가산하여 병렬 스레드 간의 재호출 동기화 충돌을 기하학적으로 흐트러뜨림으로써, 다중 에이전트 환경의 동시성 트래픽 안전망을 백퍼센트 완수합니다.
