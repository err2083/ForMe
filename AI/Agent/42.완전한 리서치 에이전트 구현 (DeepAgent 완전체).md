# [완전한 리서치 에이전트 구현 (DeepAgent 완전체)]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 DeepAgent 통합 아키텍처의 당위성과 3대 핵심 구성요소
대규모 언어 모델(LLM) 기반의 AI 에이전트가 단순 단발성 질의응답을 넘어 수십 회 이상의 도구 가동과 브라우징, 데이터 정제 등을 동반하는 복잡한 장기 실행 과업(Long-Running Tasks)을 자율적으로 수행하게 될 때, 기존의 단순 ReACT 단일 그래프 구조는 급격한 추론 및 메모리 붕괴 현상에 직면합니다. 이러한 시스템 병목을 원천 도파하고 인간 전문가 수준의 연속 실행 능력을 확보하기 위해, 계획(Planning)·컨텍스트 오프로딩(Context Off-loading)·컨텍스트 격리(Context Isolation)를 하나의 유기체로 융합한 **DeepAgent 통합 아키텍처**가 등장하였습니다.
*   **TODO 관리 레이어 (Planning)**: 복잡하고 광범위한 사용자 요청을 의미론적 마일스톤으로 즉시 분할 정복하고, 매 실행 단계 직후 계획의 유효성을 실시간 재평가(Recitation) 및 덮어쓰기(Overwriting)하여 에이전트가 길을 잃는 인지적 목표 이탈(Mission Drift) 현상을 상시 방어합니다.
*   **로컬 파일 시스템 레이어 (Context Off-loading)**: 도구를 거치며 수집된 대규모 원시 HTML, PDF 파싱 로그, 검색 덤프 데이터셋 등을 영속 디스크(WORKSPACE_DIR = Path("./agent_workspace"))로 고속 오프로딩하여, 메인 에이전트가 가벼운 메모리 대역폭만으로 추론을 영위할 수 있도록 보조하는 VRAM 구원 인프라입니다.
*   **격리형 서브 에이전트 레이어 (Context Isolation)**: 세부 업무 단위별로 완벽히 격리된 독립 세션 그래프를 실시간 런타임에 동적으로 스레드 인가(task)하여, 이전 작업의 잔여 로그가 현재 작업의 인자 정합성을 훼손하는 상호 간섭(Cross-Contamination)을 방지하는 보안 경계선입니다.

### 1.2 create_agent(수동 구현) vs create_deep_agent(내장 라이브러리) 비교
개발자는 학습 목적과 세부 정밀 튜닝 사양에 따라 컴포넌트를 수동 설계하는 로우레벨 방식과, 검증된 엔터프라이즈 모범 설계 템플릿을 한 줄의 API 호출로 즉시 전개하는 하이레벨 라이브러리 방식을 목적에 맞춰 취사선택할 수 있습니다.
*   **수동 구현 (`create_agent`)**: 내부 오케스트레이션 메커니즘을 상세히 디버깅하고, `InjectedState`나 `Command(update=...)` 인터페이스를 동적으로 커스터마이징하여 사내 특화 비즈니스 로직에 결합해야 할 때 유용합니다. 개발자가 `write_todos`, `read_todos`, `ls`, `read_file`, `write_file` 등의 도구 수명 주기를 일일이 컴파일해야 하므로 보일러플레이트 코드가 증가합니다.
*   **내장 라이브러리 (`create_deep_agent`)**: 수동으로 빌드해야 하는 TODO, 파일 시스템, 서브 에이전트 오케스트레이션, 자동 콘텍스트 오프로딩 및 대용량 출력 축소 장치가 완전히 하나의 표준 규격으로 패키징되어 즉각 기동됩니다.
*   **고급 인프라 기능 지원**: `create_deep_agent`는 샌드박싱 환경 상에서 실제 운영체제 명령을 투과시키는 `execute`(셸 실행) 도구, 영구 메모리 상태를 지속 동기화하여 세션이 끊겨도 동일 맥락을 이어가는 `AGENTS.md` 장기 기억(Long-term Memory) 연동 백엔드를 추가 비용 없이 인프라 레벨에서 원천 제공합니다.

### 1.3 전략적 성찰 도구(think_tool)와 인지 제어선 설계
심층 조사를 자율 영위하는 에이전트의 또 다른 위험은 정보 수집의 종결 지점을 스스로 판독하지 못하고, 유사한 검색어 조회를 무한 반복 가동하여 귀중한 API 요금과 추론 레이턴시를 낭비하는 무한 루프입니다. DeepAgent는 이를 통제하기 위해 매 도구 사용 직후 강제 호출되는 **전략적 성찰 도구(think_tool)**를 주축으로 삼아 인지 제어선 설계합니다.
*   **현재 수집 지식 가치 평가**: "현재까지 web_search를 통해 획득해 파일에 격리 보관한 지식이 무엇인가?"를 LLM 스스로 정량 리마인드합니다.
*   **미지 지식의 갭(Gap) 평가**: "사용자가 최종 원하는 비교표나 아키텍처 분석서를 작성하기에 여전히 결핍된 데이터 조각(예: 활용 사례, 상세 벤치마크 점수)이 무엇인가?"를 성찰합니다.
*   **Stop or Go 자율 의사결정**: 정보가 충분하다고 임계치(Threshold) 판정이 날 경우, 추가 검색을 즉시 정지하고 로컬 파일의 정보들을 융합 및 정제하여 최종 레포트를 작성하는 결정론적 행동 수렴 단계로 안전하게 진입시킵니다.

## 2. 데이터 흐름 및 컨텍스트 관리 매커니즘

### 2.1 DeepAgent 완전체의 종단간(End-to-End) 데이터 흐름 및 상태 전이도
아래 아키텍처 흐름도는 사용자의 대과업이 인입된 시점부터 메인 에이전트가 TODO 계획을 수립하고, 다중 격리형 서브 에이전트(task)를 병렬 가동하며, EXA 검색 데이터를 파일 디스크에 오프로딩한 후, `think_tool`의 지능형 제어선 통제를 거쳐 최종 무결한 레포트(`comparison_report.md`)로 도출되기까지의 종단간 데이터 흐름을 묘사합니다.

```
[사용자 복합 리서치 요청 인입]
  - "LangChain과 LangGraph를 비교하고 결과를 'comparison_report.md'로 저장해 줘."
       │
       ▼ [State: DeepAgentState 개시]
[메인 에이전트 (Main Agent: Supervisor)]
  - 1단계: write_todos 도구 호출 → "1. LangChain 리서치", "2. LangGraph 리서치", "3. 비교 보고서 작성" TODO 저장
       │
       ▼ [병렬 위임 결정: 2개 task 도구 병렬 송출 (asyncio.gather)]
┌──────────────────────────────────────┐ ┌──────────────────────────────────────┐
│ [task 1: \"research-agent\" 위임]       │ │ [task 2: \"research-agent\" 위임]       │
│  - isolated_messages = [{            │ │  - isolated_messages = [{            │
│      \"role\": \"user\",               │ │      \"role\": \"user\",               │
│      \"content\": \"LangChain 조사\"   │ │      \"content\": \"LangGraph 조사\"   │
│    }]                                │ │    }]                               │
│       │                              │ │       │                              │
│       ▼ [EXA Search API 타격]        │ │       ▼ [EXA Search API 타격]        │
│ [web_search 도구 가동]               │ │ [web_search 도구 가동]               │
│  - 로컬 디스크 격리 쓰기 가동           │ │  - 로컬 디스크 격리 쓰기 가동           │
│  - search_langchain_2026.md 영구 보존│ │  - search_langgraph_2026.md 영구 보존│
│  - VRAM 어텐션 포화 원천 차단        │ │  - VRAM 어텐션 포화 원천 차단        │
│  - 초경량 힌트 요약문만 부모에게 복귀   │ │  - 초경량 힌트 요약문만 부모에게 복귀   │
└──────────────────┬───────────────────┘ └──────────────────┬───────────────────┘
                   │                                        │
                   ▼ [Command(update=...) 델타 회수]        ▼ [Command(update=...) 델타 회수]
[메인 에이전트 (Main Agent: Supervisor) 상태 병합 수렴] ◄────┘
  - state[\"todos\"] 갱신: 리서치 태스크 2개 completed 처리
  - state[\"messages\"]에는 단 2개의 컴팩트한 리서치 요약 스니펫만 적재하여 VRAM 제곱 오버헤드 완벽 정복
       │
       ▼ [자가 성찰 레이어 가동]
[think_tool 호출 (자가 성찰 및 의사결정)]
  - 수집된 파일들의 힌트 데이터를 분석하여 갭이 완전 수축되었는지 대조 성찰
  - "추가 리서치 불필요. 보고서 작성 결정 (Stop)" 의사결정 수립
       │
       ▼ [파일 시스템 기반 최종 융합 가동]
[read_file / write_file 도구 호출]
  - `read_file`로 로컬 디스크에 이탈 보존된 2개 원시 지식 파일 상세 정독
  - 고밀도 융합 연산을 통해 `comparison_report.md` 최종 작성 및 디스크 쓰기 영속화
       │
       ▼ [최종 계획 무결 종결]
[write_todos 호출 및 사용자 최종 보고]
  - 모든 TODO를 완료(completed)로 덮어쓰고, 최종 성공 메시지를 사용자에게 송출
```

### 2.2 파일 백엔드(Storage Backend) 설계와 데이터 지속성
DeepAgent는 파일 시스템 기반의 영속성 수준에 따라 세 가지 서로 다른 독립형 백엔드 레이어를 매핑하여 인프라를 정밀 제어할 수 있도록 옵션을 모델링합니다.
*   **상태 기반 백엔드 (`StateBackend`)**: LangGraph의 세션 `State` 데이터 버퍼 영역에 가상 파일 딕셔너리(`files`)를 임베딩하여 가동하는 기본 에뮬레이팅 방식입니다. 세션과 수명을 같이하므로 휘발성 임시 데이터나 일회성 샌드박스 테스팅 목적에만 부합하며, 대용량 파일 적재 시 결국 상태 직렬화(Serialization) 부하를 가중시킵니다.
*   **파일 시스템 백엔드 (`FilesystemBackend`)**: 가상 파일 시스템의 쓰기 이벤트를 호스트 컴퓨터나 에뮬레이팅되는 microVM 내의 실제 로컬 디스크 디렉토리(예: `./agent_workspace/`)로 전치 매핑하여 영속 박제하는 인프라 실전 규격입니다. 에이전트가 비정상적으로 사멸하거나 호스트 컨테이너가 교체되더라도 디스크 마운트를 유지하므로 고도의 신뢰성 있는 장기 실행 CI/CD 및 CLI 업무 자동화를 지탱해 줍니다.
*   **메모리 저장 백엔드 (`StoreBackend`)**: LangGraph Store 백엔드 API와 다이렉트 연동하여, 다중 대화 스레드 및 다른 사용자 간의 세션 장벽을 뛰어넘어 특정 데이터 아키텍처와 인프라 스키마를 영구 공유 및 동기화할 수 있는 영속 레이어입니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 및 deepagents 라이브러리를 활용한 DeepAgent 완전체 구현 소스코드
다음 소스코드는 `deepagents` 라이브러리의 핵심 내장 기능을 가동하여 Custom EXA Search(`internet_search`) 도구를 결합하고, TODO 목록 관리, 로컬 디스크 파일 영속 보존, 서브 에이전트 격리 위임 파이프라인을 단 몇 줄로 선언하여 무결한 비교 보고서를 생성하는 최상급 완성형 파이썬 마스터 스크립트 표준 규격입니다.

```python
import os
from typing import Literal
from dotenv import load_dotenv
from exa_py import Exa
from deepagents import create_deep_agent
from deepagents.backend import FilesystemBackend
from langgraph.checkpoint.memory import MemorySaver

# 1. 시스템 구동 환경 변수 로딩
load_dotenv()
if not os.getenv("OPENAI_API_KEY"):
    os.environ["OPENAI_API_KEY"] = "your-openai-api-key"
if not os.getenv("EXA_API_KEY"):
    os.environ["EXA_API_KEY"] = "your-exa-api-key"

# 2. EXA Search API 기반 최적화 검색 엔진 도구 정의
exa_client = Exa(api_key=os.environ["EXA_API_KEY"])

def internet_search(
    query: str,
    max_results: int = 5,
    topic: Literal["general", "news", "finance"] = "general"
) -> str:
    """웹에서 정보를 시맨틱하게 실시간 검색합니다.
    
    Args:
        query: 검색할 대상 명확한 질문이나 키워드 명세
        max_results: 반환받을 결과물의 최대 갯수
        topic: 검색 타겟 범주 분류
    """
    try:
        # EXA API 고밀도 시맨틱 탐색 호출
        results = exa_client.search_and_contents(
            query=query,
            num_results=max_results,
            text={"max_characters": 2000},
            highlights={"num_sentences": 3}
        )
        
        # 검색 결과의 하이라이트 요약본만 프롬프트 버퍼로 안전하게 회환
        highlights = []
        for i, r in enumerate(results.results[:3], 1):
            row = f"{i}. {r.title}"
            if r.highlights:
                row += f" - {r.highlights[0][:100]}..."
            highlights.append(row)
            
        return "🔍 [EXA 검색 엔진 요약]:\n" + "\n".join(highlights)
        
    except Exception as e:
        return f"검색 연산 치명적 실패: {str(e)}"

# 3. 고성능 기술 리서치 전문가 지침 정의
RESEARCH_INSTRUCTIONS = """당신은 전 세계의 AI 기술과 시스템 인프라 아키텍처를 분석하는 전문 수석 리서처입니다.
철저하고 무결한 팩트 체크를 바탕으로 독창적이고 논리적인 고순도 비교 보고서를 완성하는 것이 임무입니다.

기본적으로 인터넷 검색 도구(internet_search)를 가동하여 최신 정보를 입수할 수 있으며,
방대한 지식의 인입으로 컨텍스트가 오염되거나 부패하지 않도록 다음 인프라 도구를 결합 설계하십시오:
- write_todos / read_todos: 계획 수립 및 복기 암송
- ls, read_file, write_file, edit_file: 디스크 오프로딩
- task: 격리형 서브 에이전트 위임 (예: 복합 비교 시 개별 대상을 서브 에이전트에게 동시 격리 위임)
- think_tool: 성찰 및 정합성 검증 루프 제어

반드시 한국어로 정갈하고 전문적인 톤앤매너로 답변 및 레포트를 최종 작성하십시오."""

# 4. create_deep_agent를 통한 완전형 오케스트레이션 빌드 (인프라 자동 결합)
filesystem_workspace = FilesystemBackend(root_dir="./agent_workspace")
memory_checkpoint = MemorySaver()

deep_agent = create_deep_agent(
    model="openai:gpt-4o",  # 최상위 오케스트레이션 역량이 뛰어난 GPT-4o 세팅
    tools=[internet_search],
    system_prompt=RESEARCH_INSTRUCTIONS,
    backend=filesystem_workspace,  # 로컬 디스크 파일 영속 백엔드 바인딩
    checkpointer=memory_checkpoint,  # 시간 여행 디버깅 및 세션 유지를 위한 체크포인터
```

### 💡 1번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
트랜스포머의 셀프 어텐션(Self-Attention) 연산은 입력 시퀀스의 길이 $T$에 대해 $O(T^2)$의 시간 및 공간 복잡도를 가지므로, 대화와 도구 실행 결과가 누적될수록 VRAM 소모량이 기하급수적으로 폭증합니다. 뿐만 아니라, 어텐션 가중치를 계산하는 소프트맥스(Softmax) 수식:
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
에서 분모의 크기에 비례하여 토큰 수가 늘어남에 따라 정작 보존해야 하는 시스템 지침 및 도구 스키마 명세에 정렬되어야 할 어텐션 확률 점수의 확률 질량(Probability Mass)이 물리적으로 넓게 흩어져 희석(Lost in the Middle)됩니다. 이로 인해 모델이 도구의 정합 매개변수 타입을 망각하고 엉뚱한 환각을 출력하는 컨텍스트 부패가 유발됩니다.
<br><br>
이 인프라 병목을 무력화하기 위해 <code>FilesystemBackend</code>는 <b>컨텍스트 오프로딩(Context Off-loading)</b> 필터 기법을 실행합니다. web_search 등에서 수집한 메가바이트 규모의 날것 데이터셋(Raw Response) 전체를 LLM의 입력 프롬프트 메모리에 직접 연접하지 않고, 로컬 영속 디스크 디렉토리에 파일로 즉시 격리 이탈 기재합니다. 그리고 디코더 버퍼에는 파일의 경로 힌트(예: <code>"search_results_langchain_2026-08-22.md"</code>)와 초경량 메타 요약 정보(Highlights)만 회환하여, 연산 복잡도를 상수의 대역폭 내로 엄격하게 구속 통제합니다. 이를 통해 $O(T^2)$ 연산 부하를 항시 청정 임계값 이내로 영구 동결시켜 VRAM 자원을 안전하게 구호 수호합니다.
</p>
