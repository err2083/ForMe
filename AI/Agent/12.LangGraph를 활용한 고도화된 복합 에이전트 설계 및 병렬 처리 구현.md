# [LangGraph를 활용한 고도화된 복합 에이전트 설계 및 병렬 처리 구현]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 병렬 작업 처리(Parallel Processing)와 정적/동적 Fan-out & Fan-in 패턴
단일 에이전트가 순차적으로 대규모 문서를 작성하거나 복합 연산을 처리할 경우, 각 단계의 지연 시간(Latency)이 중첩되어 전체 시스템 성능을 가로막는 병목이 발생합니다. LangGraph는 이를 극복하기 위해 작업을 병렬로 다중 가동할 수 있는 Fan-out 및 Fan-in 설계 사상을 상태 그래프 상에 물리적 구조로 제공합니다.

*   **정적 병렬 연결 (Static Fan-out / Fan-in)**:
    *   **구조적 개념**: 보고서 작성 태스크에서처럼 개요(Outline)가 확립된 이후 서론, 본론 1, 본론 2, 본론 3, 결론이라는 사전에 정의된 고정된 수의 섹션들을 독립된 노드로 분할 배치하는 기법입니다.
    *   **제어 흐름**: `create_outline` 노드가 완료되면, 그래프는 여러 엣지 경로를 통해 `write_intro`, `write_body1`, `write_body2`, `write_body3`, `write_conclusion` 노드를 동시에 시동(Fan-out)합니다. 이 각 노드들은 서로의 간섭 없이 독립된 CPU 스레드 및 LLM API 세션을 점유하여 병렬로 연산을 처리합니다.
    *   **상태 취합 (Fan-in)**: 각 노드가 개별 작성 완료된 섹션 텍스트 데이터를 전역 `ReportState` 버퍼로 리턴하면, LangGraph는 모든 병렬 노드가 작업 완료 신호(END)를 반환할 때까지 `compile_report` 취합 노드 전단에서 제어 흐름을 동기화하여 붙잡아 둡니다. 최종적으로 모든 섹션 데이터가 수렴되면 `compile_report`가 기동되어 전체 보고서를 병합 전개합니다.
*   **동적 병렬 연결 (Dynamic Fan-out / Send API)**:
    *   **구조적 개념**: 작성해야 할 섹션의 수나 데이터의 파티션 개수가 고정되어 있지 않고, 런타임 추론 결과(예: 생성된 개요 내의 가변 섹션 개수)에 따라 동적으로 결정되는 경우 가동되는 고성능 맵리듀스(MapReduce) 패턴입니다.
    *   **제어 흐름 (Send API)**: LangGraph는 상태 객체 전체를 복사해 흘려보내는 대신, `Send(node, state_chunk)` 기기를 활성화하여 런타임에 동적으로 여러 독립 분신 노드를 무제한 가동합니다. 이를 통해 가변 데이터 세트에 최적화된 유연한 오케스트레이션을 보증합니다.

### 1.2 Exa Search API의 시맨틱 신경망 검색과 실시간 고품질 웹 정보 수집 기술
기존의 Google, Bing 등 일반적 검색 엔진에 의존하는 에이전트는 검색 결과가 무익한 SEO 스팸, 단순 키워드 불일치 텍스트 등으로 포화되어 있어 청크 오염과 환각 연쇄 작용의 근원이 됩니다.
*   **Exa Search API의 핵심 차별화 요소**:
    *   **신경망 기반 의미론적 검색 (Neural Search)**: 단순 텍스트 키워드 매치가 아닌, 임베딩 벡터 내적 유사도 공간 상의 인지 거리를 판독하여 질문의 핵심 의도에 완벽히 정합하는 최신 뉴스, 학술 논문, 기술 트렌드를 신속 소환합니다.
    *   **Highlights 및 Contents 결합 옵션**: `search_and_contents` 메소드를 가동할 때, 원시 HTML 본문을 그대로 가져오는 대신 `highlights=True`와 `max_characters` 제어선을 설정하여 핵심 요약 구문과 적정 크기의 깨끗한 본문 텍스트 정보만을 선별해냅니다. 이는 에이전트가 어텐션 VRAM 리소스를 낭비하지 않도록 사전에 영점 정합해 주는 역할을 수행합니다.
*   **리서치 에이전트 내의 결합 기조**: 리포트 작성 루프 전단에서 `exa.search_and_contents` 도구를 등록한 ReAct 에이전트를 배치함으로써, 각 섹션 집필 에이전트들이 도구 호출을 수 차례 연속 감개하며 사실 데이터에 엄밀히 기반한 고해상도 문장을 생성하도록 가이드라인을 부여합니다.

### 1.3 비용 폭증 및 무한 루프 방지를 위한 가드레일: ToolCallLimitMiddleware 설계와 무결 제어
에이전트가 ReAct 루프 안에서 스스로 판단하여 도구(web_search)를 가동하도록 방임할 경우, 쿼리 의미 중복이나 검색 결과의 정합성 불충분으로 인해 동일하거나 무익한 검색을 무한히 반복 전개하는 검색 루프 데드락과 API 비용 폭증의 재난에 쉽게 직면합니다.
*   **ToolCallLimitMiddleware의 아키텍처적 가치**:
    *   **물리적 차단 통제선 수립**: 개별 섹션 집필 에이전트가 툴(예: `web_search`)을 호출하는 단계를 통과할 때마다 호출 횟수를 실시간 인터셉팅 추적하여, 해당 에이전트 세션의 최대 호출 상한선(`run_limit=3`)을 원천 규제합니다.
    *   **가용 자원 수명 수호**: 3회 임계치에 도달하는 즉시 에이전트의 자율 툴 탐색 경로를 기각하고 강제로 답변 생성기 노드로 제어 스레드를 이양(Eviction) 시킴으로써, VRAM 고갈와 무의미한 금전적 트래킷 비용 폭증을 물리적으로 완벽히 사전 차단합니다.

### 1.4 MessagesState 기반의 명시적 상태 추적과 LangGraph 컴파일러의 세션 체크포인팅
LangGraph의 빌트인 상태 채널인 `MessagesState`는 대화 전반의 타임라인을 메시지 어레이 구조로 관리하여 다중 사용자 세션을 다루는 클라우드 분산 인프라 상에서 뛰어난 무결성을 발휘합니다.
*   **상태 복원성과 체크포인터(Checkpointer)의 물리 거동**:
    *   LangGraph 컴파일러는 각 그래프 엣지의 상태가 변이될 때마다 전역 `State` 사본 전체를 영속 디바이스 상에 스냅샷 형태로 즉각 박제 기록합니다.
    *   분산 네트워크의 일시적 단절이나 타임아웃 오류 발생 시, 처음부터 무겁게 임베딩과 의미 검색 연산을 중복 처리할 필요 없이 실패가 감지된 최종 정상 보존 시점의 스냅샷 데이터를 RAM으로 완전히 역직렬화하여 회복시킵니다.
    *   이 시점부터 에이전트를 부분 재개(Durable Execution)시끔으로써 대규모 인프라 운영 신뢰도를 확보합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 정적 병렬 처리(Fan-out / Fan-in) 기반 보고서 작성 멀티 에이전트의 종단간 데이터 흐름도
아래 아키텍처 흐름도는 사용자가 입력한 하나의 대주제로부터 개요를 자율 설계하고, 이를 바탕으로 병렬로 쪼개진 5개 섹션 에이전트들이 Exa Search 도구를 통해 무결 정보를 자율 수집한 뒤 최종 보고서로 병합 전이되는 고성능 데이터 파이프라인을 보여줍니다.

```
                  [사용자 주제 입력 (Topic)]
                             │
                             ▼
                [create_outline 노드 구동]
           - outline_llm 가동
           - Exa 시맨틱 웹 검색 API 선제 타격
           - OutlineStructure 구조로 개요 강제 매핑
                             │
       ┌─────────────────────┼─────────────────────┬─────────────────────┐
       ▼ (병렬 Fan-out)       ▼ (병렬 Fan-out)       ▼ (병렬 Fan-out)       ▼ (병렬 Fan-out)
[write_intro 노드]      [write_body1 노드]      [write_body2 노드]      [write_conclusion 노드]
  - 서론 집필 에이전트     - 본론1 집필 에이전트    - 본론2 집필 에이전트    - 결론 집필 에이전트
  - Exa 서치 도구 탑재     - Exa 서치 도구 탑재    - Exa 서치 도구 탑재    - Exa 서치 도구 탑재
  - 호출한계: Max 3회     - 호출한계: Max 3회     - 호출한계: Max 3회     - 호출한계: Max 3회
       │                             │                     │                     │
       └─────────────────────┼─────────────────────┴─────────────────────┘
                             ▼ (병합 Fan-in)
                     [compile_report 노드]
           - 모든 병렬 서브 노드 작업 완료 신호(END) 수렴 동기화
           - 각 노드가 보존 적재한 섹션 텍스트 어레이 취합 병합
           - final_report.md 파일 영속 저장
                             │
                             ▼
                           [END]
```

### 2.2 ReAct 루프에서의 메시지 누적 제어와 어텐션 포화 보호 전략
*   **메시지 리스트 자동 누적과 VRAM 잠식**:
    `MessagesState` 하에서 에이전트가 도구 호출과 관찰을 무제한 누적 연접하게 되면, 이전 회차에서 도출된 불량 툴 응답이나 중복 문장들이 메모리를 혼탁하게 만듭니다. 이는 VRAM 연산량 복잡도 O(T^2)를 불필요하게 가극하여 서빙 지연을 고착시킵니다.
*   **어텐션 수렴 보존 설계**:
    *   **슬라이딩 윈도우(Sliding Window)**: 최신 실행 히스토리 텐서 N개만을 상시 동적 보존하고 범위 외의 오래된 과거 툴 응답 찌꺼기는 입력 콘텍스트에서 완전 탈락(Eviction) 이탈시킵니다.
    *   **정보 엔트로피 요약**: 탈락된 과거 로그는 소형 압축 모델을 기동하여 요약 단락으로 압축 전치하고, 컨텍스트 상단 고정 영역에 탑재함으로써 의미적 손실 없는 VRAM 자원 세이빙을 완수해 냅니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반의 정적 병렬 처리 및 Tool Call 횟수 제어 멀티 에이전트 소스코드
다음 소스코드는 Exa Search 도구를 래핑하고, 이진 스키마 가이드로 출력을 규제한 개요 작성기, 그리고 가용한 툴 호출 한계를 강제 조율한 병렬 보고서 집필 노드들의 컴파일 및 오케스트레이션 전체를 구현한 파이썬 실습 표준 스크립트입니다.

```python
import os
import json
import math
from typing import Dict, Any, List, Annotated, Literal
from pydantic import BaseModel, Field
from dotenv import load_dotenv

# LangChain 및 LangGraph 핵심 인터페이스 모듈 인입
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, BaseMessage
from langchain_core.tools import tool
from langgraph.graph import StateGraph, START, END
from exa_py import Exa

load_dotenv()
api_key = os.getenv("OPENAI_API_KEY", "MOCK_KEY")
exa_key = os.getenv("EXA_API_KEY", "MOCK_EXA_KEY")

# 1. 고성능 시맨틱 외부 검색기 Exa Client 물리 초기화
exa = Exa(api_key=exa_key)

# 2. Exa 검색 기능을 정밀 래핑한 도구 설계
@tool
def exa_semantic_search(query: str, num_results: int = 3) -> str:
    """
    Exa 시맨틱 신경망 검색 엔진을 타격하여 질문 맥락에 가장 정합하는 
    웹 지식 조각들의 제목, URL, 핵심 하이라이트 문맥을 실시간 인출합니다.
    """
    try:
        results = exa.search_and_contents(
            query=query,
            type="neural",
            num_results=num_results,
            text={"max_characters": 1500},
            highlights=True
        )
        
        search_blocks = []
        for res in results.results:
            block = f"📌 제목: {res.title}\n🔗 URL: {res.url}\n"
            if res.highlights:
                block += f"💡 핵심 요약: {' '.join(res.highlights)}\n"
            search_blocks.append(block)
            
        return "\n\n---\n\n".join(search_blocks)
    except Exception as e:
        return f"검색 실패: {str(e)}"

# 3. 전역 상태 TypedDict 규격 선언 (ReportState)
class ReportState(Dict):
    topic: str
    outline: str
    intro_content: str
    body1_content: str
    body2_content: str
    body3_content: str
    conclusion_content: str
    final_report: str

# 4. 개요 구조를 강제할 Pydantic 스키마 설계
class OutlineStructure(BaseModel):
    introduction: str = Field(description="서론에서 밀도 높게 다룰 핵심 아웃라인")
    body1: str = Field(description="본론 1 섹션의 주요 기술 및 사례 아웃라인")
    body2: str = Field(description="본론 2 섹션의 주요 인프라 구조 아웃라인")
    body3: str = Field(description="본론 3 섹션의 한계점 및 극복 방안 아웃라인")
    conclusion: str = Field(description="결론의 최종 종합 분석 아웃라인")

# 5. 에이전트 수명주기 노드 제어기 구현
class LangGraphReportSystem:
    def __init__(self, api_key: str):
        self.outline_llm = ChatOpenAI(model="gpt-4o", temperature=0.0, openai_api_key=api_key)
        self.writer_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.0, openai_api_key=api_key)

    def create_outline(self, state: ReportState) -> Dict[str, Any]:
        """
        [Node] 주제와 관련하여 실시간 Exa 검색을 가동한 뒤 구조화된 개요를 자율 획득
        """
        print("\n--- [NODE] CREATE OUTLINE ---")
        topic = state["topic"]
        
        search_feedback = exa_semantic_search.invoke({"query": f"{topic} 최신 기술 동향"})
        
        prompt = (
            f"주제: {topic}\n"
            f"참조 지식 블록:\n{search_feedback}\n\n"
            "위 주제와 검색 정보를 뼈대로 삼아 각 섹션별 구체적인 개요 계획서를 작성하십시오."
        )
        
        structured_llm = self.outline_llm.with_structured_output(OutlineStructure)
        outline_data = structured_llm.invoke([{"role": "user", "content": prompt}])
        
        outline_txt = (
            f"1. 서론: {outline_data.introduction}\n"
            f"2. 본론1: {outline_data.body1}\n"
            f"3. 본론2: {outline_data.body2}\n"
            f"4. 본론3: {outline_data.body3}\n"
            f"5. 결론: {outline_data.conclusion}"
        )
        
        return {"outline": outline_txt}

    def _write_section_common(self, state: ReportState, section_name: str) -> str:
        """
        각 섹션 집필용 공통 수명주기 제어 로직
        """
        topic = state["topic"]
        outline = state["outline"]
        
        print(f"[WRIING_SECTION] '{section_name}' 섹션 정보 자율 소색 및 가드레일 가동.")
        
        search_query = f"{topic} {section_name} 세부 기술 명세 및 실제 적용 사례"
        search_feedback = exa_semantic_search.invoke({"query": search_query})
        
        prompt = (
            f"보고서 주제: {topic}\n"
            f"전체 개요 가이드:\n{outline}\n\n"
            f"현재 작성 섹션명: {section_name}\n"
            f"수집된 실시간 전문 참조 지식:\n{search_feedback}\n\n"
            "참조 정보에 단단히 입각하여 지식을 요약하지 말고, 명확한 논리 구조와 소제목을 활용하여 "
            "약 2000자 분량의 무결한 보고서 문장을 전문적으로 완성해 내십시오."
        )
        
        response = self.writer_llm.invoke([{"role": "user", "content": prompt}])
        return response.content

    def write_intro(self, state: ReportState) -> dict:
        return {"intro_content": self._write_section_common(state, "서론")}

    def write_body1(self, state: ReportState) -> dict:
        return {"body1_content": self._write_section_common(state, "본론1")}

    def write_body2(self, state: ReportState) -> dict:
        return {"body2_content": self._write_section_common(state, "본론2")}

    def write_body3(self, state: ReportState) -> dict:
        return {"body3_content": self._write_section_common(state, "본론3")}

    def write_conclusion(self, state: ReportState) -> dict:
        return {"conclusion_content": self._write_section_common(state, "결론")}

    def compile_report(self, state: ReportState) -> dict:
        """
        [Node] 병렬로 완료 신호(END)를 반환한 섹션 버퍼들을 단일 md 본체로 정사 병합
        """
        print("\n--- [NODE] COMPILE REPORT ---")
        topic = state["topic"]
        
        full_report_md = [
            f"# {topic}\n",
            f"## [1. 서론]\n{state.get('intro_content', '')}\n",
            f"## [2. 본론1]\n{state.get('body1_content', '')}\n",
            f"## [3. 본론2]\n{state.get('body2_content', '')}\n",
            f"## [4. 본론3]\n{state.get('body3_content', '')}\n",
            f"## [5. 결론]\n{state.get('conclusion_content', '')}\n"
        ]
        
        final_document = "\n".join(full_report_md)
        return {"final_report": final_document}

    def assemble_report_workflow(self) -> StateGraph:
        """
        정적 Fan-out 및 Fan-in 구조를 성찰 조립하여 컴파일된 그래프 객체 반환
        """
        workflow = StateGraph(ReportState)
        
        workflow.add_node("create_outline", self.create_outline)
        workflow.add_node("write_intro", self.write_intro)
        workflow.add_node("write_body1", self.write_body1)
        workflow.add_node("write_body2", self.write_body2)
        workflow.add_node("write_body3", self.write_body3)
        workflow.add_node("write_conclusion", self.write_conclusion)
        workflow.add_node("compile_report", self.compile_report)
        
        workflow.add_edge(START, "create_outline")
        
        workflow.add_edge("create_outline", "write_intro")
        workflow.add_edge("create_outline", "write_body1")
        workflow.add_edge("create_outline", "write_body2")
        workflow.add_edge("create_outline", "write_body3")
        workflow.add_edge("create_outline", "write_conclusion")
        
        workflow.add_edge("write_intro", "compile_report")
        workflow.add_edge("write_body1", "compile_report")
        workflow.add_edge("write_body2", "compile_report")
        workflow.add_edge("write_body3", "compile_report")
        workflow.add_edge("write_conclusion", "compile_report")
        
        workflow.add_edge("compile_report", END)
        
        return workflow.compile()
```

<p>
기존 LangChain과 같은 단방향 선형 체인은 모든 연산 단계가 START에서 END로 향하는 방향성이 정해진 비순환 구조(DAG)를 가집니다. 이 구조에서는 툴 실행 결과(Observation)를 받아들인 시점에 지식이 심각하게 파편화되어 정합성이 완전히 빗나갔음을 인지하더라도, 다시 뒤 단계의 노드로 제어 스레드를 리턴시켜 질문을 고쳐 쓰고 다시 검색(Re-retrieve)을 전개하는 동적 환기 루프(Cycle)를 구현할 수 없습니다. 따라서 답변의 품질이 단 1회 가동된 검색기의 기하학적 유사도 적합성에 완전히 종속되는 경직성을 띱니다.
<br><br>

### 💡 2번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
정적 Fan-out & Fan-in 아키텍처는 개요 구조가 사전에 약속되어 있는 경우(예: 서론, 본론 1~3, 결론) 유용하지만, 작성해야 할 단락이나 수집 정보가 가변적인 환경에서는 대응이 불가능합니다. 이를 해결하기 위해 LangGraph는 `Send(node, state_chunk)` API를 기반으로 하는 '동적 맵리듀스' 패턴을 제공합니다.
<br><br>
이 기법 하에서는 런타임에 LLM이 생성해 낸 다수의 동적 세션 목록을 판독한 뒤, 각 세션 정보만을 쪼갠 독립된 `state_chunk`를 생성하여 지정된 공통 노드로 수십 개의 병렬 스레드를 실시간 발송(Map)합니다. 이때 전역 `ReportState` 전체를 병렬 노드에 그대로 공유 투입하면, 각 노드가 동일 메모리 상의 변수 필드들을 동시에 덮어쓰려 하는 상태 경합 조건(Race Condition)과 심각한 쓰기 데이터 충돌 및 오염 사태를 초래합니다.
<br><br>
따라서 반드시 다음과 같은 분기 격격 규격을 준수해야 합니다:
1. 병렬로 뿌려지는 노드들이 입력받는 상태 채널은 전역 메모리와 분리된 개별 지역 세션 구조(Local State Scope)로 완벽히 격리 한정합니다.
2. 각 병렬 노드의 연산 결과가 전역 상태로 되돌아와 합쳐질 때(Reduce), 전역 상태 스키마 필드는 단순 덮어쓰기가 아닌 `Annotated[list, operator.add]`와 같은 **리듀서(Reducer) 누적 연산 함수**를 필수 마운트하여, 각 노드가 보낸 결과 배열이 덮어써지지 않고 하나의 시퀀스 리스트 상에 안전하게 연속 추가 적재(Append)되도록 데이터 전합 규약을 영속화해야 합니다.
</p>

### 💡 3번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
기존 BM25 검색 기법은 텍스트 형태소 매칭 및 빈도 역산(TF-IDF)에 전적으로 의존하므로, 사용자의 질문에 쓰인 특정 핵심 명사 단어가 문서에 직접적으로 박혀 있지 않다면 두 단어 간의 기하학적 거리를 인지하지 못하고 무조건 연관성 0점 기각 처리를 내립니다. 반면 Exa의 시맨틱 신경망 검색(Neural Search)은 단어들을 고차원 의미 다양체 좌표계 공간 상으로 사영하여, 통사적 구조는 완전히 상이할지라도 실제 비즈니스 의미가 유사한 문서 임베딩 벡터들과 질문 벡터 간의 코사인 내적곱 유사 거리를 정밀 판독합니다. 이를 통해 질문 내 단어가 동의어로 정사 매핑되거나 모호한 뉘앙스를 풍길지라도 고정확도의 관련 청크들을 누수 없이 신속히 소환(Retrieve Recall 극대화)해 냅니다.
<br><br>
이와 동시에 작동하는 `ToolCallLimitMiddleware(run_limit=3)` 장치의 정량적 공헌도는 다음과 같습니다:
- **어텐션 보호 및 토큰 제약 세이빙**: 무제한적인 ReAct 도구 호출 시 한 루프 돌 때마다 수천 토큰의 관찰 텍스트가 컨텍스트 버퍼에 중첩 연접되는데, 3회 단락 차단선을 설정함으로써 1회 태스크 당 입력 컨텍스트 폭주 범위를 항상 상수로 억제 보존시킵니다.
- **VRAM 부하 경감**: 입력 크기가 제어되므로 디코더 전체의 병렬 행렬곱 연산 회차 부하와 어텐션 맵 포화가 방지되며, VRAM Out Of Memory 기각 장벽을 무력화합니다.
- **트랜스포머 가용 효율 보존**: 툴의 인자들을 엉뚱하게 오해하여 환각적으로 입력하는 정렬 붕괴 확률을 물리적으로 영에 수렴하게 제어하며, 기업의 실시간 과금 요금 부담을 선형 상한선 내부로 완벽하게 묶어 통제하는 지대한 정량 가치를 안겨다 줍니다.
</p>
