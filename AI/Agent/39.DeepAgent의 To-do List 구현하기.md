# [DeepAgent의 To-do List 구현하기]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 Long-running Agent와 미션 드리프트(Mission Drift)의 인지적 한계
- **장기 실행 에이전트와 컨텍스트 부패 (Context Rot)**: 거대언어모델(LLM)이 장시간에 걸쳐 복잡하고 무거운 과업을 완전 자율적으로 수행하는 장기 실행(Long-running) 환경으로 진입할수록, 시스템은 '컨텍스트 부패(Context Rot)'라는 물리적 임계 장벽에 봉착하게 됩니다. 예를 들어, 대표적인 자율 에이전트인 Manus AI의 경우 하나의 거대한 목표를 완수하기 위해 평균 50회 이상의 도구 호출(Tool Calls)을 실행합니다. 이 과정에서 도구 실행 결과, 원시 덤프 로그, 중간 파싱 데이터가 메시지 이력에 지속적으로 축적(Append)되면서 컨텍스트 윈도우가 기하급수적으로 팽창합니다.
- **미션 드리프트(Mission Drift)의 원인**: 컨텍스트가 극도로 비대해지면 기저 트랜스포머 모델의 어텐션 가중치(Attention Weight) 분포가 희석되고 왜곡됩니다. 이로 인해 에이전트는 대화 초기 단계에서 사용자가 하달한 궁극적인 시스템 지침이나 핵심 비즈니스 규칙을 잊어버리고, 지엽적인 오류 복구 루프에 매몰되거나 아예 엉뚱한 대화 흐름으로 탈조하는 '미션 드리프트(Mission Drift)' 현상을 겪게 됩니다.
- **Claude Code의 계획 모드(Plan Mode)와 TodoWrite 도구**: Anthropic의 차세대 코딩 에이전트인 Claude Code는 이러한 인지적 한계를 정면으로 돌파하기 위해 작업 실행 전에 먼저 '계획 모드(Plan Mode)'를 구동합니다. 에이전트는 동작을 시작하기 전, 자신의 시스템 프롬프트 가이드라인과 결합된 전용 도구인 `TodoWrite`를 기동하여 전체 태스크를 논리적이고 세분화된 TODO 목록으로 구조화하여 선제 선언합니다. 각각의 TODO 아이템은 짧고 구체적인 작업 설명을 담은 `content`와 현재 진행 상태를 나타내는 `status` (pending, in_progress, completed)라는 명확한 속성 정보를 바인딩하여 관리됩니다.
- **암송(Recitation) 패턴을 통한 어텐션 재정렬**: Manus AI와 같은 지능형 에이전트들은 매 도구 가동 턴이나 하위 마일스톤이 종료되는 오프셋 시점에 TODO 목록을 지속적으로 다시 작성(Rewrite)하고 자가 검토(Read)하는 '암송(Recitation) 패턴'을 적용합니다. 이는 컨텍스트 버퍼의 가장 말단(최신 입력 위치)에서 자신의 단기·장기적 목표 상태를 모델 프롬프트 디코딩 영역에 강제로 다시 노출시킴으로써, 부패된 어텐션 맵을 정화하고 초기 미션에 대한 집중도와 추론 정합성을 상시 최고 밀도로 유지시키는 특화된 컨텍스트 엔지니어링 전략입니다.

### 1.2 LangGraph와 DeepAgentState 설계 및 상태 오버라이딩(Overwriting) 기법
- **관심사 분리 기반의 DeepAgentState 구성**: 장기 태스크를 영속적으로 조율하기 위해 LangGraph 기반의 상태 관리 스키마는 다음과 같은 3대 핵심 채널 필드를 포함하는 `DeepAgentState` 구조체로 정의됩니다.
  - `messages`: 에이전트와 사용자, 도구 노드 간에 왕래한 양방향 대화 및 호출 데이터 이력입니다. `add_messages` 리듀서를 활용하여 이전 턴의 정보 위에 신규 메시지 오브젝트를 슬라이싱 머징(Merge)하여 점진적으로 축적합니다.
  - `todos`: 현재 진행 중인 마일스톤 계획과 각 항목별 해결 상태 정보를 정밀 보존하는 Todo 딕셔너리 어레이입니다.
  - `files`: 디스크 파일의 경로 정보와 상태 메타데이터를 저장하는 가상 파일 시스템 딕셔너리로, 점진적 업데이트를 지원하는 `file_reducer` 함수와 연계하여 영속성을 수호합니다.
- **계획 재평가를 강제하는 상태 오버라이딩(Overwriting) 사상**: 일반적인 메시지 채널과 달리, `todos` 필드는 누적 연접 리듀서(`add_messages` 등)를 할당하지 않고, 새로운 TODO 데이터가 입력될 때마다 **이전 리스트 전체를 무조건 덮어쓰기(Overwrite)** 하도록 아키텍처를 유도합니다. 
  - 특정 항목의 `status`를 `in_progress`에서 `completed`로 단순 토글 변이할 때조차 전체 리스트를 완전 갱신 형태로 전이시키는 이유는, LLM으로 하여금 '전체 계획의 유효성'을 턴마다 원점에서 다시 읽고 판단하도록 만들기 위함입니다. 
  - 이를 통해 모델은 고착화된 정적 계획에 매몰되지 않고, 중간 도구 실행 실패나 예상치 못한 예외 데이터를 발견했을 때 스스로 TODO 목록을 재고하여 불필요한 단계를 제거하거나 새로운 복구 태스크를 동적으로 삽입하는 유연한 임기응변 능력을 획득하게 됩니다.

## 2. 도구 및 에이전트 인플로우 구현 설계

### 2.1 TODO 관리 도구의 구체적 구현 및 시스템 프롬프트(XML 가이드라인)
- **write_todos와 read_todos의 상호 보완성**: 에이전트가 자신의 마일스톤 계획을 수립하고 추적할 수 있도록 `write_todos`와 `read_todos`라는 두 가지 대칭형 도구를 제공합니다.
  - `write_todos`: LLM이 Pydantic 또는 TypedDict 형식으로 전달한 신규 계획 리스트를 인가받아 상태 상의 `todos` 필드를 전체 갱신하고, 변경 사항이 반영되었음을 추적 가능한 `ToolMessage` 오브젝트를 생성하여 대화 메시지 이력에 연접합니다.
  - `read_todos`: 에이전트가 장기 작업 도중 문맥적 피로를 느낄 때 자율적으로 호출하며, 현재 상태 딕셔너리에 적재되어 있는 최신 `todos` 정보를 정형 마크다운 스트링으로 빌드하여 반환합니다. 이를 통해 모델의 인-컨텍스트 버퍼를 최신 정합 상태로 강제 동기화시킵니다.
- **InjectedState와 Command를 통한 동적 상태 제어**:
  - `InjectedState`를 사용하면 에이전트가 도구를 명시적으로 호출할 때 자신의 전체 상태(State) 데이터셋을 인자로 구구절절 채워 넣지 않아도, 런타임 프레임워크가 백엔드 메모리 상의 `DeepAgentState` 인스턴스를 도구 함수 내부로 자동 주입(Injection)해 줍니다. 이는 모델이 도구를 다룰 때 불필요한 매개변수 바인딩 오인식 확률을 제로로 차단합니다.
  - `Command` 객체는 도구의 비결정론적 실행 결과를 그래프 제어 레이어에 전달할 때 사용됩니다. `Command(update={"todos": todos, "messages": [...]})`를 반환하면, 그래프 프레임워크는 해당 딕셔너리를 가로채서 상태를 원자적으로 업데이트하고 가상 스레드 동기화를 수행합니다.

### 2.2 To-do 기반 자율 리서치 가이드라인 (System Prompt XML)
```xml
<To-do-Instructions>
  당신은 To-do 리스트 기반으로 장기 복잡 태스크를 자율 완수하는 마스터 엔지니어링 에이전트입니다.
  다음의 엄격한 가이드라인과 5단계 워크플로우 제어 절차를 한 치의 오차도 없이 엄격히 수행하십시오.

  <Workflow-Process>
    1. 태스크 개시 즉시 사용자의 요청을 정밀 분석하고, write_todos 도구를 시동하여 구체적인 마일스톤 To-do 계획을 최소한의 오버헤드로 수립하십시오.
    2. 계획에 설계된 To-do 항목 중 오직 단 하나의 항목만 'in_progress' 상태로 가동하고, 다른 복합 연구 태스크는 원자적 처리를 위해 하나의 단락으로 타이트하게 묶어 관리하십시오.
    3. 지정된 하위 과업을 정상 완수할 때마다 즉시 write_todos를 재호출하여 완료 상태('completed')로 변이하십시오.
    4. 다음 단계를 개시하기 전, read_todos 도구를 활용해 최신 계획 상태를 엄숙히 자가 성찰 및 복기(Recitation)하여 미션 드리프트를 물리 방어하십시오.
    5. 어떠한 난관이나 예외를 만나더라도 모든 To-do의 상태가 'completed'로 안전하게 수렴할 때까지 이 자기 루프 프로세스를 무한 재귀 반복하십시오.
  </Workflow-Process>
</To-do-Instructions>
```

## 3. 실전 가동형 전체 시뮬레이션 파이썬 코드

아래 파이썬 스크립트는 가상 환경이나 물리 장비 없이도 완벽히 동작하며, `InjectedState`와 `Command` 제어 패브릭을 탑재하여 `write_todos`와 `read_todos`를 자율 구동하는 LangGraph 기반 To-do 에이전트의 완성도 높은 실전 스펙입니다.

```python
import os
from typing import Annotated, Literal
from typing_extensions import TypedDict, NotRequired
from dotenv import load_dotenv

# LangChain 및 LangGraph 코어 모듈 수입
from langchain_core.messages import SystemMessage, HumanMessage, ToolMessage
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool, InjectedToolCallId
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode
from langgraph.prebuilt import InjectedState
from langgraph.types import Command

# 1. 시스템 동작 환경 설정 및 키 체크
load_dotenv()
if not os.getenv("OPENAI_API_KEY"):
    os.environ["OPENAI_API_KEY"] = "your-openai-api-key"

# 2. Todo 작업 단위 구조체 정의
class Todo(TypedDict):
    content: str
    status: Literal["pending", "in_progress", "completed"]

# 3. 확장 에이전트 상태 스키마 설계
class DeepAgentState(MessagesState):
    """메시지 이력 자동 누적 기능에 계획 보존용 todos 필드를 바인딩한 마스터 상태"""
    todos: NotRequired[list[Todo]]

# 4. To-do 제어 도구 구현 (Command & InjectedState 이식)
@tool(parse_docstring=True)
def write_todos(
    todos: list[Todo], 
    tool_call_id: Annotated[str, InjectedToolCallId]
) -> Command:
    """에이전트의 마일스톤 To-do 목록을 동적으로 생성하거나 최신 상태로 전체 덮어쓰기 갱신합니다.

    Args:
        todos: 갱신할 content와 status를 담은 전체 Todo 객체 목록
        tool_call_id: 프레임워크가 자동 주입하는 고유 도구 호출 식별자
    """
    print(f"\n[🔧 TOOL - write_todos] 계획 덮어쓰기 업데이트:")
    for idx, t in enumerate(todos, 1):
        status_symbol = "✅" if t["status"] == "completed" else "🔄" if t["status"] == "in_progress" else "⏳"
        print(f"   {idx}. {status_symbol} {t['content']} ({t['status']})")
        
    return Command(
        update={
            "todos": todos,
            "messages": [
                ToolMessage(
                    content=f"To-do 목록이 성공적으로 업데이트되었습니다. 현재 목록 크기: {len(todos)}개 항목",
                    tool_call_id=tool_call_id
                )
            ]
        }
    )

@tool(parse_docstring=True)
def read_todos(
    state: Annotated[DeepAgentState, InjectedState],
    tool_call_id: Annotated[str, InjectedToolCallId]
) -> str:
    """에이전트 가상 메모리 상태에서 최신 To-do 목록 전체를 수입하여 포맷팅된 텍스트로 읽어옵니다.

    Args:
        state: 프레임워크가 자동으로 컨텍스트 샌드박스에서 주입해 주는 실시간 에이전트 상태 객체
        tool_call_id: 메시지 연접 트레이싱을 위해 주입되는 도구 호출 식별자
    """
    todos = state.get("todos", [])
    if not todos:
        return "현재 시스템에 등록된 To-do 목록이 존재하지 않습니다."
        
    result_lines = ["\n📋 [현재 To-do 목록 실시간 판독 결과]"]
    for i, todo in enumerate(todos, 1):
        emoji = {"pending": "⏳", "in_progress": "🔄", "completed": "✅"}.get(todo["status"], "❓")
        result_lines.append(f"  {i}. {emoji} {todo['content']} (상태: {todo['status']})")
        
    print("".join(result_lines))
    return "\n".join(result_lines)

@tool(parse_docstring=True)
def virtual_research(query: str) -> str:
    """가상의 웹 지식 검색을 수행하여 핵심 타겟 기술 자료를 획득합니다.

    Args:
        query: 검색할 구체적인 기술적 명세 키워드
    """
    print(f"\n[🔍 TOOL - virtual_research] 키워드 검색 기동: {query}")
    mock_db = {
        "Model Context Protocol": "MCP는 에이전트와 도구를 표준 JSON-RPC 2.0으로 연동하는 범용 충전단자 규격입니다.",
        "To-do List": "To-do 리스트는 에이전트의 Context Rot과 미션 드리프트를 방지하는 최강의 추론 가드레일입니다."
    }
    for k, v in mock_db.items():
        if k.lower() in query.lower():
            return f"[{k} 검색 결과]: {v}"
    return f"'{query}'에 대한 정합 조각을 찾지 못해 일반 웹 크롤러를 통해 백그라운드 수확을 대체 진행했습니다."

# 가용 도구 리스트업
tools = [write_todos, read_todos, virtual_research]
tool_node = ToolNode(tools)

# 5. 모델 바인딩 및 오케스트레이션 노드 설계
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
llm_with_tools = llm.bind_tools(tools)

SYSTEM_PROMPT = """당신은 To-do 리스트를 나침반으로 삼아 자율 질의 해결을 수행하는 엘리트 에이전트입니다.
반드시 사용자의 요청이 유입된 즉시 write_todos 도구를 사용하여 계획을 수립하십시오.
매 단계 행동 수행이 완료될 때마다 read_todos를 통해 상황을 성찰하고 To-do 상태를 꼼꼼하게 completed로 마킹해 나가십시오.
최종 답변은 항상 한국어로 조리 있고 명확하게 제공해야 합니다."""

def call_model(state: DeepAgentState):
    print("\n---🧠 REASONING (모델 추론 및 의사결정)---")
    messages = [SystemMessage(content=SYSTEM_PROMPT)] + state["messages"]
    response = llm_with_tools.invoke(messages)
    return {"messages": [response]}

def should_continue(state: DeepAgentState) -> Literal["tools", "end"]:
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"
    return "end"

# 6. 상태 그래프(StateGraph) 컴파일 조립
workflow = StateGraph(DeepAgentState)

# 노드 등록
workflow.add_node("call_model", call_model)
workflow.add_node("tools", tool_node)

# 정적 엣지 연결
workflow.add_edge(START, "call_model")
workflow.add_edge("tools", "call_model")

# 조건부 엣지 매핑
workflow.add_conditional_edges(
    "call_model",
    should_continue,
    {
        "tools": "tools",
        "end": END
    }
)

# 자율 가동 에이전트 빌드 완료
todo_agent = workflow.compile()
print("✅ To-do 나침반이 탑재된 DeepAgent가 무결하게 컴파일되었습니다!")
```

### [질문 1]

### [질문 2]
LangGraph 상에서 `Command` 객체 반환을 통한 동적 상태 업데이트 및 `InjectedState` 데코레이션이 기존의 정적 워크플로우 엣지 제어와 비교하여 지니는 동적 유연성과 백엔드 원자성(Atomicity) 측면의 이점을 정량적으로 대조 분석하시오.

### 💡 1번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
트랜스포머 아키텍처의 핵심인 셀프 어텐션(Self-Attention)은 입력 시퀀스 쿼리 텐서 $Q$, 키 텐서 $K$, 밸류 텐서 $V$ 간의 유사도를 통해 가중치 행렬을 도출합니다.
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
여기서 시퀀스 길이 $T$가 누적되는 다중 턴 루프(예: 도구 호출 50회 이상 가동)가 지속되면, 컨텍스트 내의 토큰 개수 $T$가 수만 개에 이르게 됩니다. 소프트맥스 분모가 대규모 노이즈 토큰(예: 원시 실행 로그, 장대한 HTML 로우 텍스트 등)으로 인해 $T$ 방향으로 적분 팽창하면, 각 특정 핵심 토큰 $i$ (예: 시스템 프롬프트에 기재된 초기 미션 제약조건)가 가져갈 수 있는 어텐션 가중 확률값 $P(a_i)$는 기하학적으로 $0$에 가깝게 수축하게 됩니다. 이것이 바로 컨텍스트 부패(Context Rot) 및 어텐션 가중치 희석 현상입니다.
<br><br>
이때 To-do 암송(Recitation) 패턴을 가동하여 컨텍스트 윈도우의 가장 최근 인입 지점(시퀀스의 하단 끝)에 `read_todos` 또는 `write_todos`를 통해 고밀도의 목표 정보 마크다운 스니펫을 강제로 재기재하면, 트랜스포머의 인과적 마스킹(Causal Masking) 상에서 가장 최신 쿼리 텐서 $Q_{latest}$가 방금 적재된 To-do 키 텐서 $K_{todo}$와 높은 내적 유사도 점수를 형성하게 됩니다. 결과적으로 소프트맥스 확률 분포가 To-do 목표 영역으로 급격하게 재편향(Attention Re-alignment)되면서 모델은 자신이 궁극적으로 완수해야 할 미션을 다시 한번 강하게 성찰 및 자각하게 되며, 이로써 미션 드리프트 한계를 완벽하게 박멸할 수 있게 됩니다.
</p>
</details>

### 💡 2번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
기존의 정적 그래프 구조에서는 특정 도구가 상태(State)를 업데이트하려면 해당 도구를 전용 노드로 매핑하거나, 도구가 원시 텍스트를 반환하고 부모 노드가 이를 받아서 복잡한 포스트 프로세싱(Post-processing)과 데이터 매핑 보일러플레이트 코드를 거쳐 상태 채널에 병입해야만 했습니다. 이는 런타임 상에서 추가적인 추론 오버헤드와 분기 오인식의 가능성을 포함합니다.
<br><br>
반면, `Command` 객체 반환을 통한 동적 상태 제어 아키텍처는 도구 함수 자체의 내부 연산 영역에서 즉각적인 가상 메모리 변이(State Mutation)를 직접 가동합니다. `Command(update={"todos": todos})`는 프레임워크 수준에서 가로채어져 상태 채널에 원자적(Atomic)으로 direct 쓰기를 수행하므로, 중간 상태 불일치(Race Condition)나 파싱 오류로 인한 그래프 탈조 위험을 수학적으로 무력화합니다. 
또한, `InjectedState`를 통해 메모리 상에 존재하는 상태 인스턴스를 도구의 추론 버퍼에 복잡한 가공 없이 즉시 주입(In-memory Referencing)하므로, 모델이 불필요한 콘텍스트 바인딩 토큰을 생성할 필요가 없어져 VRAM 연산 지연 및 API 대기 대역폭을 비약적으로 보전할 수 있습니다.
</p>
</details>
