# [AI 에이전트가 적용된 서비스와 그 원리]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 ChatGPT의 Agentic 진화와 자율 도구 호출 아키텍처
ChatGPT는 단순한 대화형 서비스를 넘어서 대화 맥락 전체를 판독하여 실시간으로 필요한 외부 도구를 자율 매핑 및 실행하는 현대적 B2C AI 에이전트의 표본입니다.
- **대화 맥락 하의 자율 호출**: 사용자가 질문을 인입시키면 기저 모델은 문맥을 추론하여 웹 검색(Web Search), 이미지 생성(DALL-E), 캔버스 작성, 외부 서드파티 서비스 연동 중 최적의 도구를 자율적으로 호출(Function Calling)합니다. 이 과정에서 사용자의 명시적인 도구 지시 없이도 "맥락적 인과(Contextual Causality)"에 따라 판단을 결정합니다.
- **인프라 통합 가치**: 이는 독립된 인프라 레이어들이 LLM이라는 중앙 제어 판(Brain Core) 하에 통합되어 물리적으로 동작함을 의미하며, 에이전트가 단발성 답변 생성을 포기하고 다단계 상태 전이 흐름을 안정적으로 완수할 수 있는 동력을 제공합니다.

### 1.2 딥리서치(Deep Research) 자율 탐색 에이전트의 재귀적 탐색 및 하위 쿼리 분할
딥리서치(Deep Research)는 OpenAI에서 처음 선보인 이래로 글로벌 초일류 AI 기업(Anthropic, Google, X AI 등)들이 필수 탑재하기 시작한 자율 탐색 에이전트 기술입니다.
- **하위 질의 분류(Sub-Query Classification)**: 사용자가 복잡하고 광범위한 조사 주제를 인입시키면 에이전트는 이를 해결 가능한 최소 단위의 작은 하위 질문(Sub-queries) 세트로 자동 세분화 및 기획합니다.
- **재귀적 탐색(Recursive Exploration)**: 탐색 도구를 통해 1차 검색 결과를 얻으면 결과를 자체 성찰(Self-Reflection)하여 정보의 깊이와 무결성이 검증될 때까지 하위 질문들을 런타임 상에 재귀적으로 확장하며 다단계 순환 탐색 루프를 지속적으로 전개합니다. 이로써 일반 단발성 검색에 비해 고해상도의 논리적 심층 리포트를 자율 빌드할 수 있습니다.

### 1.3 OpenAI Agent 모드와 원격 운영체제 가상화(VM) 인프라
최근 에이전트 구동 지평을 넓힌 핵심 기술은 OpenAI의 'Agent 모드'로 대표되는 웹 브라우저 및 호스트 제어 에이전트입니다.
- **원격 가상 환경 가동**: Agent 모드는 단순 API 조작에 머무르지 않고, OpenAI 측의 원격 클라우드 서버에서 격리된 운영체제(OS) 환경을 에이전트가 직접 부팅하고 독자적으로 기동합니다.
- **인터랙티브 디바이스 제어**: 에이전트는 가상 OS 안에서 웹 브라우징(Headless Browser), 마이크로소프트 오피스 등의 응용 프로그램 가동, 터미널 명령어를 통한 스크립트 빌드 및 프로세스 실행(Code-execution)을 직접 수행합니다. 브라우저 이벤트를 활용해 정형 API가 차단된 레거시 시스템 영역까지 자율 제어함으로써 복합 비즈니스 전 과정을 자동화합니다.

### 1.4 Manus AI의 File System 기반 장기 작업 패러다임과 컨텍스트 오프로딩(Off-loading)
Manus AI는 장기 가동 에이전트(Long-running Agent) 설계의 물리적 한계를 정면 돌파하기 위해 파일 시스템 기반의 작업 제어 패러다임을 확립했습니다.
- **todo.md를 활용한 계획 영속화**: 에이전트는 임무 수신 시 자신의 거시 마일스톤 계획을 `todo.md`라는 파일로 로컬 가상 디렉토리 상에 직접 생성 및 기록합니다. 매 루프(`Plan-Action-Observation`) 단계마다 과업 수행 진척도를 이 파일에 실시간 업데이트(Update)함으로써 일관된 상태 지향성을 영구 보존합니다 [33, 34].
- **컨텍스트 오프로딩(Context Off-loading)**: 도구 연동이나 브라우징 도중 획득한 방대한 원시 텍스트 및 스크립트 전체를 LLM의 VRAM 기반 컨텍스트 윈도우에 연접(Append) 적재하지 않고, `python_script.py`, `data_source.txt`, `report.md` 등의 독립 파일로 가상 디스크(File System)에 격격히 박제 소장합니다 [33, 34]. 추후 추론 루프 시점에는 꼭 필요한 메타 정합 정보만을 컨텍스트에 담고 무거운 원시 정보는 파일에 오프로딩함으로써 모델의 어텐션 포화 및 토큰 윈도우 고갈 위협을 완전히 우회 제어해 냅니다.

### 1.5 Claude Code의 CLI 기반 시스템 제어 및 Skills/MCP를 통한 영속 진화 아키텍처
Anthropic에서 개발한 Claude Code는 개발자 터미널 환경(CLI) 상에서 작동하며 로컬 운영체제를 완벽하게 장악 조작하는 지능형 코딩 에이전트입니다.
- **bash 기반의 시스템 침투 조작**: 에이전트는 CLI 환경에서 `bash` 쉘 제어권을 직접 쥐고 동작하므로, 로컬 파일 탐색, 코드 컴파일러 구동, 유닛 테스트 실행 등을 자율 전개합니다.
- **MCP와 Skills 기반 지속 자율 진화**:
  - **MCP 외부 생태계 연동**: Model Context Protocol(MCP)을 뼈대로 장착하여 슬랙(Slack), 구글 맵스(Google Maps), Exa Search 등 다양한 외부 인프라와 실시간으로 자율 연결 통신합니다 [34, 35].
  - **Skills(스킬)을 통한 연속 학습(Continual Learning)**: 에이전트가 가동 도중 겪은 시행착오 결과나 특화된 도메인 개발 규칙은 로컬 파일 디스크 내의 `Claude.md`를 포함한 스킬(Skill) 블록 파일로 자동 각인 기록됩니다. 이 영속적 스킬 파일은 모델 가중치를 추가로 학습시키지 않고도, 에이전트가 후속 세션 루프를 돌릴 때 실시간 보존형 가이드북으로 판독 적용되어 셧다운 없는 "평생 자율 진화(Continual Adaptation)" 모델을 완수합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 가상화 및 파일 기반 장기 자율 가동 에이전트의 종단간 데이터 흐름도
아래 아키텍처 흐름도는 Manus 및 Claude Code와 같이 파일 시스템 영속 장치 및 브라우징 엔진을 장착한 에이전트 내부에서 입력 쿼리로부터 계획 수립, 도구 가동, 컨텍스트 오프로딩, 그리고 스킬 파일 갱신으로 이어지는 종단간(End-to-End) 데이터 전이 구조를 도식합니다 [33, 34, 35].

```
[사용자 거시 과업 인입]
       │
       ▼ [1단계: Task Planning 및 기록]
[todo.md 생성 및 마운트] ──► 마일스톤 계획 구조화 저장 [33, 34]
       │
       ├─────────────────────────────────────────┐
       ▼ [2단계: Action & Tool 호출]             ▼ [3단계: Context Off-loading]
[Browser / OS CLI 제어]                     [가상 디스크 파일 쓰기 (Write)]
  - API 미지원 레거시 웹 돔 조작 [9]         - 원시 텍스트/파이썬 파일 저장
  - CLI 터미널 내 bash 명령어 실행     - LLM 컨텍스트 윈도우 부하 경감
       │                                         │
       ▼ [Observation 결과 분석]                 ▼
[실행 피드백 획득 (stdout / DOM 캡처)]      [todo.md 상태 업데이트 및 보존]
       │                                         │
       ▼ [자가 성찰 및 분기 평가]                 │
[추론 수렴 검증 (Self-Reflection)]                │
       │                                         │
       ├─────────────────────────────────────────┘
       ▼ [성공 완수 및 학습 지점 도달]
[Claude.md (Skills) 영속 업데이트] ──► 연속 학습(Continual Learning) 달성
       │
       ▼
[최종 결과물 출력 및 사용자 반환]
```

### 2.2 컨텍스트 부담 완화를 위한 파일 오프로딩(Off-loading) 기법의 수치적 기여도
대규모 웹 자동화 분석 태스크를 수행할 때, 돔(DOM) 소스나 원시 텍스트 로그의 양은 평균 5만~10만 단어를 상회하여 기저 LLM의 입력 윈도우 임계치에 이릅니다 [3, 9].
- **어텐션 맵의 물리적 VRAM 포화 곡선**:
  어텐션 스코어의 하드웨어 연산 공간 복잡도는 $O(T^2)$를 따르므로, 입력 토큰 길이 $T$가 2만 토큰에서 10만 토큰으로 5배 팽창할 때, GPU VRAM 내 계산 부하는 **25배**로 기하급수적 수직 팽창합니다. 이는 서빙 레이턴시 단축을 영구 저해하고 모델이 필수 시스템 지시문을 유실하는 문제를 유발합니다.
- **오프로딩을 통한 VRAM 절감 방정식**:
  에이전트가 로컬 디스크 상에 원시 데이터를 격리 파일로 가두고, 추론 입력 텐서 영역에는 핵심 의미 메타 매트릭스 $\tilde{T}$ 만을 취합하여 주입하는 구조를 취할 경우, 입력 토큰 길이는 상수의 수준($\tilde{T} \ll T$)으로 동결 억제됩니다. 이에 따라 메모리 사용 곡선이 안정적인 정상 수평 상태를 유지하게 되며, 어텐션 주의 분배력이 타겟 JSON Schema 인자 포맷에 정밀 수렴해 도구 호출 오작동 확률을 영(0)에 수렴하도록 보장해 줍니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 Manus 패러다임 기반 Plan-Action-Observation 자율 오프로딩 시뮬레이터 스크립트
다음 소스코드는 Manus AI의 전형적인 **`todo.md` 자율 상태 보존, 브라우징 및 엑셀 도구 가동, 수확 정보 디스크 오프로딩(Context Off-loading)** 파이프라인 전체를 프로덕션 설계 관점에서 재구축한 파이썬 에뮬레이터 스크립트입니다.

```python
import os
import json
import requests
from typing import Dict, Any, List

class ManusStyleAgentSimulator:
    def __init__(self, api_key: str, workspace_dir: str = "/workspace/scratch/manus_env"):
        self.api_key = api_key
        self.endpoint = "https://api.openai.com/v1/chat/completions"
        self.model_name = "gpt-4-turbo"
        self.workspace = workspace_dir
        os.makedirs(self.workspace, exist_ok=True)
        
        # 1. Manus의 상태 영속화 핵심 파일 'todo.md' 초기 설계 수립 [33, 34]
        self.todo_path = os.path.join(self.workspace, "todo.md")
        self._write_file("todo.md", "# Manus 자율 실행 계획서\n- [ ] 1. 표적 웹사이트 검색 및 탐색\n- [ ] 2. 영업 이익 데이터 수집 및 엑셀 정렬\n- [ ] 3. 최종 요약본 전달")
        
        # 2. 에이전트 가용 도구 규격 선언
        self.tools_spec = [
            {
                "type": "function",
                "function": {
                    "name": "browser_nav_and_extract",
                    "description": "대상 웹페이지의 돔(DOM) 위상을 분석하여 필요한 텍스트 지식을 정밀 인출합니다.",
                    "parameters": {
                        "type": "object",
                        "properties": {
                            "url": {"type": "string", "description": "진입할 타겟 웹 주소"}
                        },
                        "required": ["url"]
                    }
                }
            },
            {
                "type": "function",
                "function": {
                    "name": "offload_raw_data_to_disk",
                    "description": "대용량 소스 텍스트를 파일 시스템에 격리 저장하여 컨텍스트 윈도우 부담을 오프로딩합니다.",
                    "parameters": {
                        "type": "object",
                        "properties": {
                            "filename": {"type": "string", "description": "저장할 파일명"},
                            "content": {"type": "string", "description": "원시 데이터 전체 텍스트"}
                        },
                        "required": ["filename", "content"]
                    }
                }
            }
        ]

    def _write_file(self, filename: str, content: str):
        path = os.path.join(self.workspace, filename)
        with open(path, "w", encoding="utf-8") as f:
            f.write(content)
        print(f"[SYSTEM::FILE] 디스크 오프로딩 파일 작성 완료: {path}")

    def run_inference_turn(self, conversation: List[Dict[str, Any]]) -> Dict[str, Any]:
        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json"
        }
        payload = {
            "model": self.model_name,
            "messages": conversation,
            "tools": self.tools_spec,
            "tool_choice": "auto",
            "temperature": 0.0 # 의사결정 결정론성 완전 보장
        }
        response = requests.post(self.endpoint, headers=headers, json=payload)
        return response.json()["choices"][0]["message"]

    def execute_long_running_task(self, user_prompt: str):
        """
        Manus의 Plan-Action-Observation 순환 상태 전이 구동기
        """
        conversation = [
            {"role": "system", "content": f"당신은 Manus AI 에뮬레이터입니다. 가용한 도구를 활용해 임무를 완수하고, 매 회차마다 `todo.md` 파일을 수정하여 계획 진척도를 관리하십시오. 대량의 텍스트를 얻을 시에는 반드시 'offload_raw_data_to_disk' 도구를 활용하여 메모리 부하를 줄이십시오."},
            {"role": "user", "content": user_prompt}
        ]
        
        # 1회차: 계획 수립 및 툴 호출 판단
        decision = self.run_inference_turn(conversation)
        conversation.append(decision)
        
        tool_calls = decision.get("tool_calls")
        if tool_calls:
            for call in tool_calls:
                name = call["function"]["name"]
                args = json.loads(call["function"]["arguments"])
                call_id = call["id"]
                
                print(f"[AGENT] 자율 도구 구동 판단 진입 -> {name}")
                if name == "browser_nav_and_extract":
                    # 대용량 웹 문서 수집 시뮬레이션
                    mock_big_html = "ABC_MART_SHOES_DATA_LIST_EXCEL_STRUCTURE_RAW..." * 500
                    
                    # 수집된 로우 데이터를 즉석에서 파일 시스템으로 이탈 저장 (Off-loading)
                    self._write_file("abc_mart_raw.txt", mock_big_html)
                    
                    # todo.md 계획 진행 상태 물리 갱신
                    self._write_file("todo.md", "# Manus 자율 실행 계획서\n- [x] 1. 표적 웹사이트 검색 및 탐색\n- [/] 2. 영업 이익 데이터 수집 및 엑셀 정렬\n- [ ] 3. 최종 요약본 전달")
                    
                    observation = {
                        "status": "DATA_RETRIEVED_AND_OFFLOADED",
                        "offloaded_file": "abc_mart_raw.txt",
                        "summary_meta": "ABC 마트의 러닝화 및 스니커즈 리스트 500행 데이터 수집 완료. 전체 파일은 abc_mart_raw.txt에 오프로딩 격리 보관되었습니다."
                    }
                    
                    conversation.append({
                        "role": "tool",
                        "tool_call_id": call_id,
                        "name": name,
                        "content": json.dumps(observation)
                    })
                    
            # 2회차: 오프로딩 요약 텐서를 수용하여 최종 생성 완수
            final_output = self.run_inference_turn(conversation)
            # 최종 마일스톤 도래에 따른 todo.md 완성 업데이트
            self._write_file("todo.md", "# Manus 자율 실행 계획서\n- [x] 1. 표적 웹사이트 검색 및 탐색\n- [x] 2. 영업 이익 데이터 수집 및 엑셀 정렬\n- [x] 3. 최종 요약본 전달")
            print(f"[SYSTEM::COMPLETE] 태스크가 무결히 완수되었습니다: {final_output.get('content')}")
```

### 3.2 아키텍처적 제어 매개변수와 장기 실행 상태 전이 매핑 분석
- **`todo.md`의 정적 위상 동기화**: `todo.md` 파일은 비결정론적 LLM의 판단 상태가 이탈(Divergence)하여 폭사하는 현상을 원천 방어하는 일종의 **정적 가이드 마운트**입니다 [33, 34]. 만약 루프가 비정상적으로 끊겨 스레드가 파괴되더라도 시스템 복원(Session Recovery) 서버는 디스크 상의 `todo.md`를 우선 복독하여 현재 진행 상한 오프셋 지점부터 파이프라인을 지연 없이 인양 수렴시킵니다.
- **`Claude.md` (Skills)의 우선순위 로딩 제어**: Claude Code 구동 시, 로컬 파일 시스템 최전방에 위치한 `Claude.md`는 시스템 메시지 바로 뒤에 물리적으로 병입(In-Context Injection)되어 임포트됩니다. 이 파일을 통해 개발팀 고유의 무결 가이드 스키마를 로드함으로써, 코드 생성 단계에서 발생할 수 있는 컴파일 규격 에러율을 미연에 획기적으로 낮추어 연쇄 롤백 비용을 제로에 수렴하게 조율합니다.

<p>
딥리서치(Deep Research) 자율 탐색 에이전트의 작동 원리는 고차원 거시 명령어를 루트 노드 $R$로 삼는 **동적 탐색 트리(Dynamic Search Tree)**의 생성 및 순회 프로세스로 모델링됩니다. 사용자가 광범위하고 복합적인 주제를 인입시키면, 시스템 기획 노드는 거시 요구사항을 의미론적 직교성이 수립되는 다수의 하위 질의 $\{q_1, q_2, \dots, q_n\}$로 세분 분할하여 트리 하부의 1차 자식 노드로 배치합니다.
<br><br>
이후 각 하위 쿼리 벡터들은 병렬 하이브리드 리트리벌 채널로 인입되어 실시간 외부 데이터 소스(Web, 학술 DB)를 타격하고, 인출된 피드백 문맥 $O_i$는 단순 텍스트 수용을 기각하고 성찰(Self-Reflection) 조건부 필터를 거치게 됩니다. 이때, 수집된 정보의 깊이가 탐색 종결 임계치(Entropy Threshold)를 넘지 못해 추가적인 불확실성이 감지되는 경우, 에이전트는 기 획득 정보를 기저 삼아 더 정밀화된 새로운 자식 쿼리 $\{q_{i,1}, q_{i,2}, \dots\}$를 하위 디렉토리에 동적으로 재생성하는 **재귀적 순환 탐색(Recursive Exploration)**을 개진합니다.
<br><br>
이러한 거동은 트리 구조의 깊이 우선 탐색(DFS) 및 분기 한정(Branch and Bound) 기법을 의미론적 로짓 공간 상에서 전개하는 것과 기하학적으로 일치합니다. 각 분기 경로마다 획득한 고순도 사실 힌트들을 최종 요약 노드로 역방향 귀속 병합(Post-order Traversal Merger)함으로써, 단발성 검색 시스템이 도저히 소환해 낼 수 없는 다각도 비교 분석 정보 트리를 고해상도로 완벽 수확해 내는 무결 성능을 입증해 냅니다.

### 💡 2번 질문 해설 보기

<summary>상세 해설 확인하기</summary>
<p>
Manus AI의 파일 시스템 기반 컨텍스트 오프로딩(Context Off-loading)은 소프트웨어 가상화와 하드웨어 연산량 통제 사이의 고도의 트레이드오프 설계의 정수입니다. 트랜스포머의 핵심 장치인 셀프 어텐션의 연산은 입력 시퀀스 길이 $T$가 증가할 때 $O(T^2)$의 정수 제곱 배율로 메모리와 연산 부하가 팽창합니다. 대규모 웹 제어 루프가 지속적으로 기동될 때 유입되는 만 자 단위의 원시 HTML 소스나 시스템 bash 에러 메시지를 컨텍스트 상에 직접 누적 축적하면 VRAM은 VRAM 한계를 뚫고 포화 사멸(Out of Memory) 하거나 컨텍스트 손실 장벽을 부딪치게 됩니다 [3, 33, 34].
<br><br>
Manus AI는 가상 디렉토리 상에 `todo.md`와 `task_state.json`을 자율 빌드하여 현재의 마일스톤 실행 맵과 세부 변수 상태를 오직 파일 디스크 디바이스 레벨로만 격리 저장합니다 [33, 34]. 이후 추론을 가동할 때 에이전트는 로우 텍스트 찌꺼기 수만 토큰을 통째로 입력 텐서로 주입하지 않고, 디스크에서 "현재 단계의 계획 진행 사항"과 "수집된 엑셀 경로 명세"를 함축하는 초경량 정제 힌트 텐서 $\tilde{T}$($\tilde{T} \approx \text{상수}$) 만을 입력 풀로 로드하여 전이합니다 [33, 34].

이 구조 하에서 연산 복잡도는 항상 초기의 저차원 곡선 범위($O(\tilde{T}^2)$) 내에서 완벽하게 통제 수렴합니다. VRAM 대역폭 낭비를 90% 이상 물리적으로 절감하면서 셀프 어텐션 맵의 가중치 밀도가 엉뚱한 노이즈 문장에 희석 분산되는 현상을 차단하므로, 결과적으로 에이전트의 도구 바인딩 규격 정합성을 극한의 신뢰 수준으로 사수할 수 있게 되는 정량적 기여를 이룩합니다.
