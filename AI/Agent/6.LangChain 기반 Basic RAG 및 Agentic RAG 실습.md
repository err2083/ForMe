# [LangChain 기반 Basic RAG 및 Agentic RAG 실습]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 OpenAI Assistant와 LangChain RAG의 아키텍처 철학 차이 및 에이전트 제어 주권(Control Sovereignty)
현대 AI 에이전트 시스템을 구축할 때, 지식을 참조하는 방식과 상태 제어의 자유도를 어떻게 설정할 것인가는 아키텍처의 유연성과 유지보수 비용을 결정짓는 핵심적인 분수령입니다.
- **OpenAI Vector Stores API (고도의 추상화와 블랙박스 구조)**: OpenAI는 복잡한 RAG 구축 프로세스를 단순화하여 vector_stores API 형태의 완전 관리형 서비스로 추상화하여 제공합니다. 개발자는 단순히 파일을 업로드하는 것만으로 파일 추출, 청킹, 임베딩, 유사도 검색, 프롬프트 주입에 이르는 전 과정을 자동화할 수 있어 매우 신속하게 프로토타입을 빌드할 수 있습니다. 그러나 이 고도의 편리함 이면에는 엔지니어링 관점의 가혹한 '제어권 상실'이라는 트레이드오프가 존재합니다. 개발자는 문서를 쪼개는 구체적인 청킹 알고리즘(예: 구조 단위 청킹, 겹침 크기 조절), 의미를 사영하는 임베딩 모델의 선택, 벡터 DB 질의 시의 상세한 메타데이터 필터링 조건, 그리고 최종 프롬프트에 RAG 컨텍스트를 주입하는 템플릿 구조를 미세하게 조율할 수 없습니다. 이로 인해 특정 비즈니스 도메인에서 의미 왜곡이나 환각이 발생했을 때 시스템 하부의 개별 컴포넌트를 조작하여 문제를 디버깅하거나 점진적으로 개선하는 것이 원천 불가능합니다.
- **LangChain RAG (컴포넌트 모듈화와 개발자 주권 선언)**: LangChain은 이와 반대로 Document Loader, Text Splitter, Embedding, Vector Store, Retriever 등 RAG 파이프라인의 모든 세부 기저 요소를 완전 모듈화하여 제공합니다. 에이전트 개발자는 이 레고 블록 같은 컴포넌트들을 직접 선택하고 제어함으로써 에이전트 시스템에 대한 완전한 '제어 주권'을 획득합니다. 예를 들어 기업의 고유한 하이브리드 검색 조건이나, 법률/금융 등 전문 도메인에 특화된 사용자 정의 청킹 필터를 직접 설계하여 이식할 수 있습니다. 특히 에이전트가 단순 검색기가 아닌 복합적 추론 루프를 전개하는 Agentic RAG 환경에서, 각 툴이 정보를 가져오고 소모하는 시간과 형식을 코드 레벨에서 밀착 제어할 수 있는 모듈형 아키텍처는 엔터프라이즈급 에이전트 개발의 필수적인 지탱 기저가 됩니다.

### 1.2 2-Step RAG와 Agentic RAG의 제어 흐름(Control Flow) 구조 대조 분석
지식을 RAG 파이프라인을 거쳐 주입하는 메커니즘은 제어 흐름의 성격에 따라 2-Step RAG와 Agentic RAG로 명확히 나뉩니다. 두 아키텍처는 에이전트의 작동 지능, 지연 시간(Latency), 자원 비용 면에서 극명한 상관관계를 보입니다.
- **2-Step RAG (결정론적 검색-생성 단방향 파이프라인)**: 사용자 질문이 인입되는 즉시 관련 문서를 Retriever를 통해 자동 검색하고, 그 결과를 프롬프트에 고정 증강하여 LLM에 전달하는 방식입니다. 흐름이 '검색 -> 생성'의 단방향 전이 구조로 고정되어 있어 단순하고 동작 결과가 매우 예측 가능합니다. 검색에 따르는 추가적인 LLM 추론 비용이 없고 단 1회의 최종 추론 세션만 가동하므로 속도가 빠르다는 시스템적 강점을 지닙니다. 그러나 사용자의 질문이 고도로 추상적이거나 복합적인 다중 분석을 요구하는 경우, 검색 엔진이 1차로 가져온 정보의 정합성이 빗나갔을 때 이를 자율적으로 교정하거나 다른 영역을 재탐색하는 동적 피드백 루프가 원천 결여되어 있어 답변 품질이 검색 정밀도에 완전히 지배당하는 구조적 한계를 보입니다.
- **Agentic RAG (비결정론적 에이전틱 오케스트레이션 루프)**: 기저 언어 모델이 사용자의 질문 해결에 지식 검색이 실제 필요한지 여부를 먼저 스스로 자율 판단합니다. 필요하다고 판단되면 정의된 검색 도구(retrieve_context)를 매개변수와 함께 호출하고, 그 관찰 결과를 수용해 지식이 충분한지 검증한 뒤, 지식이 미흡하면 쿼리를 변형해 추가 검색을 여러 번 전개하는 유연한 다단계 추론을 전개합니다. 질문의 복잡성에 대응하는 지능적 복원력은 극대화되지만, 도구를 호출할지 판단하기 위한 예비 추론 세션과 연속된 다회차 LLM 호출로 인해 지연 시간이 유동적으로 늘어나고 API 트랙잭션 비용이 급속도로 팽창하는 한계를 동반합니다. 따라서 실무 설계 시에는 빠른 답변이 핵심인 단순 Q&A 서비스는 2-Step RAG로 격리하고, 심층적인 연구 분석 보조 및 보안 다중 도구 조작 태스크는 Agentic RAG로 분류 전치하는 이원화 라우팅 설계가 적극 권장됩니다.

### 1.3 RecursiveCharacterTextSplitter 청킹 전략과 에이전트 어텐션 효율의 시스템적 인과관계
트랜스포머 디코더 모델의 입력 콘텍스트 내에서, 에이전트의 상황 파악 정확도를 결정짓는 가장 직접적인 하부 변수는 텍스트 청킹 정책입니다.
- **청킹의 본질적 목표**: 청킹은 단순 파일 분할이 아닌, LLM의 컨텍스트 윈도우 제약을 충족하면서 동시에 개별 정보의 의미적 밀도를 극대화하여 유사도 검색의 정확도를 올리는 엔지니어링 튜닝 영역입니다.
- **RecursiveCharacterTextSplitter의 작동 메커니즘**: 단락 구분자(\n\n), 문장 구분자(\n), 단어 공백(" ") 등 다양한 구분자 목록을 계층적으로 순차 적용하여, 청크가 도달할 목표 크기 내에서 문맥이 최대한 끊어지지 않고 자연스럽게 유지되도록 점진적으로 쪼개 들어가는 지능적 세분화 필터입니다.
- **chunk_size와 chunk_overlap의 어텐션 인과관계**:
  - chunk_size를 너무 작게(예: 150토큰 이하) 잡으면 검색의 정밀도는 일시적으로 향상될 수 있으나, 문장의 선후 연관 관계가 잘려 나가는 문맥 파편화 상태에 빠집니다. 에이전트 콘텍스트에 파편 청크들이 주입되면, 모델은 주어가 누락되거나 동사 결합이 손상된 텍스트를 보고 추론해야 하므로 어텐션 분포가 분산되어 도구 인자 매핑과 인과 관계 해석 상에 심각한 왜곡 오류를 초래합니다.
  - 반대로 chunk_size를 너무 크게(예: 1500토큰 이상) 설정하면 쓸데없는 수치 노이즈와 다른 주제의 문장이 함께 뭉개져 들어오는 정보 희석 현상이 발생합니다. 이는 불필요한 입력 토큰 오버헤드로 인한 비용 상승을 낳을 뿐 아니라, 모델이 꼭 찾아내야 하는 결정적인 단서에 어텐션 가중치를 정확히 집중시키지 못하도록 방해하는 원인이 됩니다.
  - 따라서 청크 경계에서 의미 단절을 복원하기 위해 앞단과 뒷단의 일부 문맥을 의도적으로 중첩시키는 chunk_overlap을 약 20% 비율로 조화롭게 매핑 설계하여 의미적 연결성을 영구 보존해야 합니다.

### 1.4 InMemoryVectorStore와 text-embedding-3-small의 에이전트 단기 상태 매핑
RAG 에이전트를 실시간 가동할 때, 검색 쿼리를 수치 벡터로 전환하고 이를 임베딩 공간에서 탐색하는 장치의 속도와 정합성은 에이전틱 루프의 지연시간에 직결됩니다.
- **text-embedding-3-small 임베딩 사영**: 텍스트를 고차원 공간 상의 의미 좌표 벡터로 사영합니다. 한국어와 영어 전문 문서의 깊은 함의를 신속하게 포착해 내며, 차원의 왜곡 없이 고밀도의 의미적 거리를 표현하는 기하학적 수치 변환기 역할을 완수합니다.
- **InMemoryVectorStore의 단기적 휘발 보존 구조**: 복잡한 서버급 외부 분산 DB 설치 없이, 에이전트 프로세스가 활성화되어 있는 단일 세션 동안 로컬 가상 메모리 공간(RAM) 내부의 경량 정렬 인덱스 상에 문서 벡터셋 전체를 상주시키고 완전 동기식으로 검색을 질의하는 소규모 경량 벡터 보관소입니다. 에이전트가 단기적인 과업을 처리하는 수명주기 동안 백그라운드에서 임시로 생성되었다가 과업이 끝나면 영구 파기되는 성격을 가지므로, 네트워크 대기시간을 사실상 영에 가깝게 소멸시켜 에이전트의 ReAct 추론 레이턴시를 획기적으로 낮추는 물리적 최적화를 보장합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 Agentic RAG 아키텍처 상의 종단간 데이터 흐름 및 상태 전이도
아래 아키텍처 흐름도는 사용자가 입력한 비정형 명령으로부터 에이전트가 자율 판단을 거쳐 가용한 RAG 검색 도구를 기동하고, 그 결과를 획득하여 단기 상태 메모리로 흡수한 뒤 최종 해답에 자율 도달하는 전 과정의 유기적 데이터 전이 파이프라인을 보여줍니다.

```
[사용자 비정형 질문 인입]
       │
       ▼ [에이전트 제어판 진입]
[Agentic RAG 결정론적 프리필(Prefill) 추론]
  - system_prompt + user_messages 결합 버퍼 연산
       │
       ▼ [자율 라우팅 의사결정 (Routing Decision)]
  - 이 쿼리 해결을 위해 학술 논문/외부 사내 검색 도구를 가동해야 하는가?
       ├─────────────────────────────────────────┐
       ▼ [YES: 도구 호출 상태 전이]             ▼ [NO: 즉각 생성 상태 전이]
[retrieve_context(query) 도구 작동]        [기저 파라미터 지식 기반 생성]
       │                                         │
       ├──► 1. 입력 쿼리 임베딩 벡터화             │
       ├──► 2. InMemoryVectorStore 유사 거리 탐색  │
       ├──► 3. 상위 K개 문서 텍스트 & 메타 데이터 인출 │
       │                                         │
       ▼                                         │
[Content & Artifact 데이터 분리 포맷팅]          │
  - content -> 에이전트 단기 컨텍스트 메모리 버퍼 연접  │
  - artifact -> 백그라운드 출처 매핑 인덱스에 별도 격리  │
       │                                         │
       ▼                                         │
[에이전트의 관찰 수용 (Observation Aggregation)]  │
  - 누적 상태: [System Prompt + User Query + Thought + Tool Call + Observation]
       │                                         │
       ▼                                         │
[최종 의사결정 추론 및 생성 (Second Generation)] ◄───┘
  - 주어진 지식을 맥락에 정합 적용하여 무결 언어 생성
       │
       ▼
[출처 메타데이터 결합 완료 답변 사용자 전달]
```

### 2.2 response_format="content_and_artifact" 설정이 주는 구조적 가치와 의미론적 분리
LangChain의 @tool 데코레이터를 이용해 검색 도구를 명세화할 때 제공되는 핵심적인 기능적 고급 설정 중 하나가 바로 response_format="content_and_artifact" 지정입니다.

에이전트가 단순 RAG 도구를 실행하면, 검색 결과 문서 군에는 LLM의 의미 판단에 도움을 주는 실제 문장 텍스트(Content)뿐 아니라, 문서의 보관 경로, 저자, 발행 연도, 신뢰도 등 물리적 관리 목적용인 메타데이터(Artifact) 정보들이 다량 포함되어 있습니다.
- **단순 텍스트 연접의 시스템적 폐해**: 메타데이터 성격의 복잡한 물리 정보까지 전부 하나의 긴 문자열로 병합하여 LLM의 입력 콘텍스트 윈도우에 구겨 넣으면, 무의미한 관리용 파일 패스나 해시값 단어들이 프롬프트의 의미적 탐색 영역을 혼탁하게 물들이는 통사적 오염이 유발됩니다. 이는 곧 트랜스포머의 어텐션 자원을 무의미하게 낭비시켜 생성 품질을 떨어뜨리고, 비용 증가를 초래합니다.
- **Content-Artifact 분리의 아키텍처적 무결성**: 이 형식을 활성화하면 LangChain 엔진은 도구 실행 피드백 중 오직 알짜 문장 성분이 담긴 content 영역만을 LLM 추론을 위한 단기 메모리 텍스트 프롬프트 버퍼 상에 결합 투입합니다. 그리고 복잡하지만 출처 제시에 필수적인 메타데이터 블록(Artifact)은 추론 연산 영역 외부의 안전한 격리 인덱스 저장소 상에 별도로 안전하게 보존시킵니다. 이 물리적 이원화 파이프라인 덕분에, 에이전트 본체 모델은 오직 고순도의 사실 지식 정보 블록에만 어텐션 포화 자원을 백퍼센트 집중할 수 있게 되어, 가장 정밀한 도구 응답 및 출처 표출의 무결성을 동시에 완성할 수 있게 됩니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangChain 기반 Basic RAG & Agentic RAG 시스템 구현 소스코드
다음 소스코드는 파일의 텍스트 파싱 및 RecursiveCharacterTextSplitter 세부 설정, text-embedding-3-small 기반 VectorStore 생성으로 구축된 2-Step RAG 모델과, @tool(response_format="content_and_artifact") 및 create_agent로 유기적으로 결합된 Agentic RAG 모델 전체 오케스트레이션 구동 파이프라인을 PyTorch 딥러닝 코드 없이 순수 시스템 엔지니어링 관점에서 구현한 마스터 실습 표준 스크립트입니다.

```python
import os
import json
from typing import Dict, Any, List, Tuple
from dotenv import load_dotenv

# LangChain 최신 표준 인터페이스 모듈 인입
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_core.documents import Document
from langchain.tools import tool
from langchain.agents import create_agent

# 1. 시스템 구동 환경 세팅 및 API Key 확인
load_dotenv()
api_key = os.getenv("OPENAI_API_KEY", "MOCK_KEY_FOR_SAFETY")

class LangChainRAGSystem:
    def __init__(self, api_key: str):
        self.api_key = api_key
        
        # 2. 임베딩 모델 물리적 인스턴스화
        self.embeddings = OpenAIEmbeddings(
            model="text-embedding-3-small",
            openai_api_key=self.api_key
        )
        
        # 3. 휘발성 고속 인메모리 벡터 데이터베이스 가동
        self.vector_store = InMemoryVectorStore(embedding=self.embeddings)
        
        # 4. 계획 수립 및 의사결정을 수행할 에이전트용 LLM 가동 (온도 완전 결정화)
        self.llm = ChatOpenAI(
            model="gpt-4-turbo",
            temperature=0.0,
            openai_api_key=self.api_key
        )
        
        self.retriever = None

    def ingest_raw_documents(self, raw_documents: List[Dict[str, Any]]):
        """
        문서 로딩 및 계층적 RecursiveCharacterTextSplitter 파티셔닝 파이프라인
        """
        langchain_docs = []
        for doc in raw_documents:
            # 원문 메타데이터 구조 보존 처리
            langchain_docs.append(Document(
                page_content=doc["page_content"],
                metadata=doc["metadata"]
            ))
            
        # 가독성과 어텐션 집중에 최적화된 골디락스 존 세팅
        text_splitter = RecursiveCharacterTextSplitter(
            chunk_size=1000,      # 한 청크당 최대 단어/캐릭터 크기 제약선
            chunk_overlap=200,    # 맥락의 불연속 단절을 복원하기 위한 양방향 버퍼 존
            add_start_index=True  # 원본 파일 상의 시작 오프셋 위치 메타데이터 자동 역추적
        )
        
        # 청크 분할 전개 수행
        split_chunks = text_splitter.split_documents(langchain_docs)
        print(f"[SYSTEM::INGEST] 원본 문서 {len(langchain_docs)}개가 {len(split_chunks)}개의 고밀도 청크로 세분 쪼개졌습니다.")
        
        # 벡터 인덱스에 다차원 사영 적재 처리
        self.vector_store.add_documents(split_chunks)
        
        # Top-4 유사 후보를 가져오는 고속 Retriever 구동기 장착
        self.retriever = self.vector_store.as_retriever(search_kwargs={"k": 4})
        print("[SYSTEM::INGEST] InMemoryVectorStore 내에 임베딩 및 인덱싱이 성공 완료되었습니다.")

    def run_2step_rag(self, query: str) -> Dict[str, Any]:
        """
        결정론적 단방향 2-Step RAG 파이프라인 작동기
        """
        if not self.retriever:
            raise RuntimeError("지식 데이터베이스 인덱스가 적재되지 않아 검색이 불가능합니다.")
            
        # Step 1: 관련 후보 문서 검색 (Retrieval)
        retrieved_docs = self.retriever.invoke(query)
        
        # 문서 내용을 문자열로 합산 결합
        docs_content_block = "\n\n".join(doc.page_content for doc in retrieved_docs)
        
        # Step 2: 결정론적 프롬프트 주입 및 최종 생성 (Generation)
        system_directive = (
            "당신은 주어진 참고 문헌 지식에만 전적으로 구속되어 답변을 출력하는 정밀 정보 봇입니다.\n"
            "추가적인 개인적 상상이나 유추, 환각은 엄격히 사멸 금지합니다. 세 문장 이내로 명확하게 답변하세요.\n\n"
            f"--- [참조 문헌 블록] ---\n{docs_content_block}"
        )
        
        response = self.llm.invoke([
            {"role": "system", "content": system_directive},
            {"role": "user", "content": query}
        ])
        
        return {
            "query": query,
            "answer": response.content,
            "source_metadata": [doc.metadata for doc in retrieved_docs]
        }

# --- Agentic RAG 가동을 위한 고성능 @tool 기기 설계부 ---

_global_system_instance: "LangChainRAGSystem" = None

@tool(response_format="content_and_artifact")
def retrieve_context_tool(query: str) -> Tuple[str, List[Dict[str, Any]]]:
    """
    사내 보존용 특화 기술 백서 및 학술 데이터베이스에 원격 임베딩 접속하여 
    유사도가 높은 상위 청크들의 원문 텍스트와 출처 추적용 메타데이터를 실시간 인출합니다.
    """
    global _global_system_instance
    if not _global_system_instance or not _global_system_instance.retriever:
        return "현재 시스템 검색 엔진이 오프라인 상태입니다.", []
        
    retrieved_docs = _global_system_instance.retriever.invoke(query)
    
    # 1. LLM 추론 영역에 실시간 연접 주입할 텍스트 부분 포맷팅
    content_payload = "\n\n---\n\n".join(
        f"[출처 페이지: {doc.metadata.get('page_number', 'N/A')}]\n{doc.page_content}"
        for doc in retrieved_docs
    )
    
    # 2. 모델 추론 영역 밖의 별도 아티팩트 저장소에 보관할 원본 메타데이터 블록
    artifact_payload = [
        {"page": doc.metadata.get("page_number"), "file_source": doc.metadata.get("file_name")}
        for doc in retrieved_docs
    ]
    
    return content_payload, artifact_payload

class AgenticRAGManager:
    def __init__(self, system_instance: LangChainRAGSystem):
        self.system = system_instance
        global _global_system_instance
        _global_system_instance = self.system
        
        # 에이전트가 자율 조작할 가용 도구 장착 목록 구성
        self.tools = [retrieve_context_tool]
        
        # 에이전트의 목표 지향성 계획 수립 제어 시스템 메시지 설계
        self.system_prompt = (
            "당신은 사내 전문 학술 보고서를 다각도로 연구하고 의사결정하는 AI Agent입니다.\n"
            "반드시 'retrieve_context_tool' 도구를 사용하여 사실 관계를 충분히 수집한 후 답변하십시오.\n"
            "첫 번째 검색 결과가 모호하거나 추가적인 시간 제약 추론이 요구될 경우, "
            "검색 도구의 인자 인입 문구를 기민하게 변형하여 다회차 검색을 자율적으로 수행하십시오.\n"
            "최종 응답은 반드시 한국어로 간결하고 명확하게 논증하여 완수하십시오."
        )
        
        # LangChain의 최신 수립용 create_agent API를 통해 인과 에이전트 엔진 시동
        self.agent = create_agent(
            model=self.system.llm,
            tools=self.tools,
            system_prompt=self.system_prompt
        )

    def dispatch_agentic_task(self, complex_goal: str):
        """
        에이전트에게 장기 작업 명령을 인입하고 스트리밍 데이터 전이 감시
        """
        print(f"\n[AGENT::START] 자율 업무 명령 접수: '{complex_goal}'")
        
        # stream 기능을 통해 내부 의사결정 생각 상태 변화 추적 수렴 (stream_mode="values")
        for event in self.agent.stream(
            {"messages": [{"role": "user", "content": complex_goal}]},
            stream_mode="values"
        ):
            event["messages"][-1].pretty_print()
```

### 3.2 핵심 시스템 설계 규격과 Titans/Confession 파라미터 맵 관계 분석
위 구현 코드 상에서 에이전트 시스템 가동 안정성과 비용 효율을 조율하는 핵심 변수들의 물리적 상관관계를 규정합니다.

- **chunk_size=1000 & chunk_overlap=200 (토큰 균형 최적화)**:
  - **영향 및 원리**: 이 수치 매핑은 RAG의 검색 정확도와 LLM 컨텍스트 전치 비용 간의 최상의 균형점, 즉 골디락스 존을 나타냅니다. 1000자 크기는 하나의 명확한 의미 단위 단락이 온전히 손상 없이 보존되어 기술 임베딩될 수 있는 충분한 부피이며, 200자의 중첩 크기는 페이지가 바뀌거나 섹션이 넘어갈 때 전후 문장의 대명사나 가리키는 지시대상이 잘려 나가는 것을 미연에 효과적으로 중화 및 우회 복원하는 의미적 연결막 역할을 영구 보장합니다.
- **temperature=0.0 (추론 안정화 및 도구 바인딩 강제)**:
  - **영향 및 원리**: 에이전트가 복합 툴 호출 루프를 가동할 때, 검색 도구 retrieve_context_tool의 호출을 명시하는 JSON 또는 인자 포맷의 오차율을 기하학적 확률로 수축시킵니다. 온도가 아주 미미하게라도 풀리면, 모델은 가용 스키마 명세를 임의로 꼬아 생성하거나 존재하지 않는 예외 파라미터를 환각적으로 창작해 내어 시스템을 즉각 중단시키는 런타임 오류를 방출하므로 결정론적 탐색 경로로 완벽 구속하는 것입니다.
- **stream_mode="values" (실시간 상태 피드 전이 감시)**:
  - **영향 및 원리**: 에이전트의 작동 흐름은 비결정론적이므로, 백그라운드에서 어떤 하위 루틴에 갇혀 헤매는지 모니터링하기가 극도로 난해합니다. values 스트리밍 모드는 에이전틱 타임라인 상에 누적 적재되는 대화 히스토리의 텐서 전체 상태 변화를 실시간 전송 출력해 줌으로써, 아키텍트가 에이전트의 오작동 루프 상태를 모니터링 장치에서 조기에 인지하고 차단하는 실시간 모니터링 통제력을 영위할 수 있도록 보증합니다.

<br><br>
반면, LangChain RAG의 모듈러 컴포넌트 아키텍처는 Document Loader, Text Splitter, Embedding, Vector Store, Retriever의 전 단계를 독자적인 독립 모듈로 선언하여 개발자가 명시적으로 수정할 수 있는 완전한 제어 주권을 제공합니다. 개발자는 런타임 질의 시점에 사용자 세션 정보로부터 user_role 보안 토큰을 역파싱하여, 벡터 스토어 질의 객체의 필터 인자 명세로 실시간 강제 인입시킬 수 있습니다.
<br><br>
또한, 임베딩 레이어로 넘어가기 전에 사용자 고유 사전을 추가한 MeCab 형태소 분석기를 소스코드 최전방에 전치 마운트하여 형태소 파생 오인식을 사전 방어하고, 인출된 문서 청크 무리에 대해서도 Cohere, Upstage 등의 고유 한국어 Reranker를 교차 적층함으로써, 하부 인프라 제약 조건에 기민하게 반응하고 진화하는 최상위 에이전트 시스템을 완벽하고 안전하게 영속 설계할 수 있게 만드는 강력한 아키텍처 확장 원동력을 선사합니다.
</p>

### 💡 2번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
트랜스포머 아키텍처에 내장된 셀프 어텐션 연산은 모든 토큰 쌍 간의 양방향 내적 곱셈 및 소프트맥스 거동을 전제로 하므로, 입력 크기가 늘어날수록 입력 토큰 수의 제곱에 비례하는 연산 복잡도를 유발하며 VRAM의 대부분을 물리적으로 잠식시킵니다. 이 상황에서 문서의 경로, 파일 식별 해시값, 등록 날짜 등 의미적 맥락과는 동떨어진 '관리 목적용 정적 메타데이터 블록'까지 전부 단순 문자열 형태로 인출 프롬프트 중간에 섞여 결합되면, 모델의 어텐션 분포 맵 상의 가중치 분모 분산이 불필요하게 비대해지는 '어텐션 포화' 및 'Lost in the Middle' 현상이 급격히 심화됩니다. 즉, 진짜 사실적 의미가 내포된 핵심 문맥 단락 외의 노이즈 토큰들에 어텐션 에너지 자원이 낭비되면서 도구 매개변수를 역추출해 내는 함수 호출 정확도가 붕괴하는 현상이 직결 유발됩니다.
<br><br>
LangChain의 @tool(response_format="content_and_artifact") 가단 이원화 설정은 이 병목을 데이터 전이 인터페이스 수준에서 완벽하게 우회 차단합니다.
1. **의미적 정보의 격리 주입**: 툴 실행기가 유사도 검색을 마쳤을 때, 오직 순수한 실제 지식 문장들만이 content 필드 규격으로 가공되어 모델의 콘텍스트 단기 메모리 윈도우 버퍼로 직접 흐릅니다. 이로 인해 모델의 어텐션 포화 복잡도 입력 크기가 획기적으로 낮게 유지되어 어텐션 가중치의 동적 표상 집중도가 극대화됩니다.
2. **비의미적 정보의 전치 적재**: 검색된 청크의 저자, 생성년도, 파일 출처 등 구조적 메타데이터 성분들은 어텐션 연산 공간 바깥 영역인 artifact JSON 리스트 텐서 상에 안전히 격리 보존 처리됩니다.
3. **출처 매핑 결합**: 에이전트가 고순도의 content만을 참조하여 환각 없이 사실 정합적인 정답 문장을 디코딩 생성하는 단계를 완수하면, 최종 전달 인터페이스 전단에서 백그라운드 오케스트레이터가 격리 적재되어 있던 artifact 배열의 파일명 데이터를 역파싱 인출하여 답변 끝단에 명확한 출처 표식을 실시간 동적으로 덧붙여 결합합니다.
<br><br>
이 정교한 텐서 분리 및 역결합 메커니즘을 설계 가동해야만, LLM 내부 추론 엔진의 연산적 부하를 극한으로 절감하는 것과 프로덕션 환경의 사실 정확도 및 투명한 출처 증명력을 동시에 최고조로 완수할 수 있게 되는 것입니다.
</p>

### 💡 3번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
2-Step RAG는 결정론적인 '인출 단방향 전송' 구조를 가지므로 비결정론적 폭주 가능성이 0%입니다. 반면, Agentic RAG는 LLM의 자율 추론 판단을 제어 골격으로 삼기 때문에, 기저 모델의 확률적 상태 전이에 의해 제어 흐름 상의 심각한 이탈과 루프 교란 현상이 유발됩니다. 대표적인 현상인 '검색 루프 데드락'은 다음과 같이 수립됩니다:
- 에이전트가 "A사의 2024년 영업이익률"을 알고자 툴을 호출해 검색했으나, 해당 PDF 내에 "영업이익률"이라는 단어 대신 "Operating Margin"으로 수치 기재되어 있어 검색에 실패해 Observation 결과가 비어 들어옵니다.
- 모델은 여전히 정보가 부재하다고 판단하여 다음 루프에서도 완전히 동일한 형태의 쿼리 단어인 "2024년 영업이익률"을 계속 도구인자로 반복 작성하여 재질의를 연속 가동합니다.
- 이 비결정적 자율 루프에 갇히면 에이전트는 무한히 자기 자신을 반복 호출하는 물리적 정지에 수렴하여, 단 1회의 세션 기동만으로 수십 회의 LLM API 요금이 과금되고 사용자 세션 스레드는 타임아웃으로 다운되는 과금 폭증 및 서비스 마비 장애로 귀착됩니다.
<br><br>
이를 원천 통제하기 위한 가드레일 레이어의 시스템 엔지니어링 설계 규칙은 다음과 같습니다:
1. **Max Iterations (물리 컷오프 제한선 강제)**: create_agent를 가동하는 상위 에이전트 실행기 레이어 내부에 max_iterations=5 또는 max_execution_time=30과 같은 물리적 단락 조절 장치를 탑재하여, 어떠한 자율 판단 이탈 상황에서도 강제로 추론 연산 루프를 기각 반환시키는 안전 장치를 의무 도입합니다.
2. **동적 이탈 방지 백트래킹 (Dynamic Eviction Backtracking)**: 에이전트가 동일한 도구를 2회 이상 연속 가동하는 것을 탐지하는 추적 필터를 설계합니다. 동일 툴의 2회차 진입 시점부터 시스템은 에이전트의 이전 동일 쿼리 정보를 "동적 금지 목록"으로 규정하고, 시스템 프롬프트의 임시 버퍼 공간에 "경고: 이전 질문은 검색 결과가 무위로 수렴되었으니, 동의어나 영어 표현으로 쿼리 어휘를 다각도로 혁신 변형하여 질의하시오"라는 강제 피드백 콘텍스트를 콘텍스트 맨 뒤에 연접 투입해 주의를 강제로 백트래킹 환기시킵니다.
<br><br>
이 두 중재 인프라를 가동해야만 비결정론적인 에이전틱 RAG의 흐름을 상시 예측 가능하고 재정적으로 지속 가능한 비즈니스 궤도 내로 구속하는 데 성공할 수 있습니다.
</p>
