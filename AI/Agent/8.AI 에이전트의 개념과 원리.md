# [AI 에이전트의 개념과 원리]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 LLM에서 지능형 AI 에이전트로의 패러다임 전환: 인지-추론-행동-관찰 Loop의 시스템화
기존의 대화형 AI는 단순한 입력과 출력 구조를 지닌 비상태성(Stateless) 시스템에 구속되어 있었습니다. 일례로 GPT-3.5 시절의 초기 ChatGPT는 사용자가 인입시키는 입력값(Input)에만 전적으로 의존해 대화 규칙을 도출했으며, 스스로의 판단 하에 더 깊게 생각하거나 출력된 정답을 성찰하는 등의 메커니즘을 영위할 수 없었습니다. 그러나 모델 내부의 논리 추론 성능(Reasoning Capability)이 비약적으로 임계 도파하면서, 단순 대화 수준을 뛰어넘어 자율적으로 작동하는 **지능형 AI 에이전트(AI Agent)** 아키텍처로의 혁신적 전이가 일어났습니다.
- **에이전트 구동 핵심 루프(Cognitive Loop)**: AI 에이전트는 기저 LLM을 고성능 '뇌'로 탑재한 연산 시스템입니다. 에이전트는 거시적인 임무 목표(User Goal)를 하달받으면 단발성 텍스트 생성을 포기하고, **[인지(Perceive) ──► 추론 및 계획(Reason & Plan) ──► 행동(Action) ──► 결과 관찰(Observation)]**이라는 인과적 자율 가동 루프(Agentic Loop)를 연속 전개합니다. 이 루프 속에서 모델은 목표 달성을 위한 구체적인 중간 마일스톤 계획들을 수립하고, 이를 달성하기에 최적인 외부 기기 도구들을 선별하여 함수를 호출(Function Calling)한 뒤, 그 실행 결과로 유입된 피드백을 단기 기억에 동적으로 축적 수용하여 다음 판단 지표로 활용합니다.
- **멀티모달 및 추론의 임계 진화**: GPT-4급 이상 모델에서 나타난 깊은 추론 장치와 GPT-4o를 필두로 한 **멀티모달 인지 역량**은 텍스트를 넘어 이미지, 비디오, 음성 등 다차원 시각 물리 정보를 상태 입력 벡터로 유기적으로 합성하여 에이전트가 현실 인프라 상황에 최적으로 개입하도록 이끌었습니다 [36].

### 1.2 Function Calling과 JSON Schema: 에이전트 액션(Action)의 물리적 전이 인터페이스
에이전트가 단순한 조언용 텍스트 출력을 넘어 외부 시스템에 구체적인 물리적 영향과 상태 변이를 가동하기 위한 핵심 구동 기제는 바로 **Function Calling(함수 호출)**입니다.
- **JSON Schema 기반 도구 제약 및 규격화**: LLM은 훈련 단계에서 획득한 고차원 표상 정렬 규칙에 따라, 자연어로 유입된 질문 문맥을 분석하여 정형화된 JSON이나 Python Dictionary 형식의 의미 구조를 정밀하게 디코딩할 수 있습니다. 에이전트 시스템 컴포넌트는 사용 가능한 외부 도구(Tools)의 이름, 목적 서술문, 그리고 매개변수 구조를 **JSON Schema 규격** 하에 정의하여 모델에 가용 명세(Tool Manifesto)로 사전 각인 주입시킵니다. 
- **형식 가이드라인 및 엄격 매핑 구조**: 모델은 문맥을 판독해 해당 도구가 필수적으로 수행되어야 한다고 판단할 때, 아래의 인터페이스 통제 가이드를 따르는 정밀 구조체를 출력 로짓으로 도출합니다.
  - **문자열(String) 및 스칼라(Scalar)** 매개변수는 규격화된 상태 그대로 지정하며, **리스트(List)와 객체(Object)** 성분들은 JSON 엄밀 구조 포맷을 따릅니다.
  - 문자열 값에 포함된 공백은 인위적으로 제거되거나 잘려나가지 않고 원형 그대로 보존됩니다.
  - 출력된 텍스트 전체가 반드시 완벽한 유효 XML일 필요는 없으며, 파이프라인 후단에 배치된 정규 표현식(Regular Expressions) 파서 필터를 통해 의미 인자값만을 역추출해 돔 및 인프라 호출 매개변수로 안전하게 바인딩합니다.

### 1.3 MCP (Model Context Protocol)와 외부 도구 생태계의 연결성 극대화
모델이 도구와 소통하기 위한 정사 인터페이스가 무수히 난립하면서 발생하는 시스템 파편화 문제를 무력화하기 위해, 현대 에이전트 인프라는 **MCP (Model Context Protocol)** 기술을 전격 수용하여 결합합니다 [36].
- **도구 및 데이터 연동 대역폭의 확장**: MCP는 서로 다른 에이전트 기어들과 다양한 외부 엔드포인트(DB, Web, 코드 샌드박스 등) 간의 연결 통로를 하나의 통일된 통신 표준 프로토콜로 규격 통제하는 엔지니어링 패브릭입니다 [36]. MCP를 장착한 에이전트는 사전에 정의된 도구 스펙의 변화나 DB 아키텍처 사영 구조가 복잡하게 변경되더라도, 시스템 전체를 재컴파일하거나 파인튜닝할 필요 없이 동적으로 새로운 MCP 어댑터 레이어를 통해 외부 인프라 및 도구 생태계와의 연결성을 극한으로 증폭 전개해 냅니다 [36].

### 1.4 실리콘밸리 트렌드: Planning 기반 장기 작업 수행 에이전트(Long-running Agent)와 Code-Execution
현재 글로벌 에이전트 생태계를 관통하는 최첨단 개발 흐름은 백그라운드 상에서 인간 조작자의 지속적 감시 개입 없이 수 시간에서 수 일 이상 지속적이고 독자적으로 목적 과업을 완수해 내는 **장기 작업 수행 에이전트(Long-running Agent)**의 완성입니다.
- **자율 계획 기반 에이전트(Planning-based Agent)**: Manus, Claude Code, Codex 등 실리콘밸리 3세대 에이전트의 전형적 작동 핵심은 LLM의 깊은 논리 추론 지능에 기반한 **Planning(계획 수립) 아키텍처**입니다. 에이전트는 임무 지시를 받으면, 스스로 실현 불가능한 대형 문제를 해결 가능한 아주 작은 미시적 물리 태스크 세트로 잘게 파티셔닝 쪼갠 뒤, 복수 에이전트 간의 상호 검증(Multi-Agent) 및 멀티모달 상태 정합 과정을 유지하며 실행합니다.
- **Code-execution(코드 실행)의 직접 내재화**: 이들은 단순한 외부 API 조회를 과감히 뛰어넘어, 격리된 가상 환경 내에서 파일 시스템에 직접 접속해 파일을 새로 생성하거나(Write), 기존 레거시 원본 코드를 실시간 판독하고(Read), 변경 픽스 사항을 파일에 완전 반영하는 **실질적인 상태 변이(Physical State Mutation)** 능력을 탑재하고 있습니다. 에이전트는 계획 해결을 위한 최적의 실행 코드를 실시간 동적으로 작성한 뒤 이를 실행 샌드박스에 인입시켜 구동 스트림(stdout)과 에러 트레이스 피드백을 실시간 연쇄 수렴(Self-Correction)해 나갑니다.

### 1.5 정보 획득 한계 극복: 웹 브라우저 자동화와 브라우저 에이전트(Browser Agent)
모든 비즈니스 환경이 에이전트와 매끄럽게 통신하기 좋은 깔끔한 REST API나 정형 JSON 인터페이스를 영속 제공하고 있는 것은 아닙니다. 공공기관 포털, 구형 ERP, 폐쇄형 결제망 등 수많은 업무 환경은 여전히 오직 인간 사용자의 화면 조작만을 전제로 설계된 HTML 웹뷰 상태로 운영되고 있습니다.
- **Browser Agent의 물리 작동 원리**: 이러한 정보 획득 경계와 동작 한계를 도파하기 위해 Chrome/Edge 등 헤드리스 브라우저 드라이버를 직접 자율 조작하는 **브라우저 에이전트(Browser Agent, 예: Skyvern의 작동 기조)**가 탄생했습니다. 브라우저 에이전트는 복잡한 웹 페이지 전체의 돔 트리(DOM Tree) 위상을 의미론적 가지치기를 거친 텍스트 트리로 압축 사영해 해석하는 한편, 현재 화면의 고해상도 스크린샷 이미지 픽셀 정보를 동시에 로드합니다. 이 두 데이터 공간의 기하학적 상관관계를 투영 분석함으로써 마우스의 클릭, 스크롤, 문자열 타이핑 등의 구체적인 물리 이벤트를 화면 내 절대 좌표계 상에 실시간 역정합 주입하여 완벽한 자동 우회 수행력을 확보합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 ReAct 기반 AI 에이전트의 종단간(End-to-End) 수명주기 및 데이터 흐름도
아래 아키텍처 데이터 흐름도는 사용자가 입력한 비정형 명령으로부터 에이전트 내부의 Reasoning 장치가 Planning을 수립하고, JSON Schema에 맞춘 파라미터 규격을 디코딩하여 외부 물리 도구 및 파일 실행을 전개한 뒤, 관찰 결과를 다시 피딩하여 최종 목표를 타격하는 전 과정의 동적 전이를 보여줍니다 [35, 37].

```
[사용자 거시적 명령 인입 (User Goal)]
       │
       ▼ [Reasoning / Planning 단계 시동]
[에이전트 마스터 콘텍스트 버퍼 조립]
  - system_prompt + user_messages + tool_catalog [38]
       │
       ▼ [LLM 추론 필터 투과]
[도구 호출 여부 자율 판별]
  - 이 문제 처리를 위해 코드 실행 / 파일 Read/Write / RAG가 필요한가?
       ├─────────────────────────────────────────┐
       ▼ [YES: Action 상태 전이]                 ▼ [NO: 최종 답변 도출 상태]
[Function Calling 매개변수 빌드]          [가중치 기반 언어 생성]
  - JSON Schema 제약에 맞춘 인자 추출        │
       │                                         │
       ▼                                         │
[격리 가상 환경 (MicroVM / Docker 샌드박스)]     │
  - 실제 코드 프로세스 물리 실행             │
  - 파일 입출력 및 stdout / stderr 캡처        │
       │                                         │
       ▼ [Observation 데이터 확보]               │
[외부 피드백 관찰 수집 (Observation)]             │
  - [System Prompt + User Query + Thought         │
     + Tool Call + Observation] 텍스트 연접       │
       │                                         │
       ▼                                         ▼
[자가 검증 및 계획 수정 (Self-Correction)]       [최종 응답 전달 완료]
  - 이 피드백으로 미션이 충분히 해결되었는가?           │
  - NO: 쿼리 재구성 및 다음 루프 기동              │
  - YES: 최종 생성기 노드로 상태 전이                   ▼
       └─────────────────────────────────────────► [END]
```

### 2.2 장기 가동 세션에서의 컨텍스트 요약 및 토큰 관리 전략
AI 에이전트가 Manus나 Claude Code처럼 백그라운드에서 몇 시간 혹은 몇 달간 자율 구동되는 장기 실행(Long-running) 모드를 전개할 때 직면하는 가혹한 시스템 장애 요소는 기저 초거대 언어 모델들이 지닌 입력 토큰 한계(GPT-5.1의 128k, Claude Sonnet 4.5의 200k 토큰 제약)와 어텐션 맵의 기하급수적 계산 비용 상승입니다.
- **순차적 연접으로 인한 컨텍스트 팽창 병목**: 루프를 돌 때마다 생각 로그(Thought), 액션 매개변수(Tool Call JSON), 그리고 대규모 파일 데이터 및 실행 결과 스택(Observation)이 삭제 없이 콘텍스트 풀 하단에 무제한 누적 축적됩니다. 이는 VRAM 연산 대역폭을 급격히 고갈시키며, 정밀 도구 바인딩 판단을 방해하는 어텐션 정렬 붕괴(Lost in the Middle) 현상을 초래합니다.
- **컨텍스트 엔지니어링 및 요약 정책 (Context Engineering)**:
  - **Dynamic Sliding Window**: 필수적인 마스터 명령 시스템 프롬프트(System Manifesto)와 최신 2~3회 차의 도구 실행 핵심 메시지 이력 텐서만을 순수 입력 풀로 슬라이딩 보존하고, 오래된 과거 실행 이력은 입력 영역에서 물리적으로 탈락 이탈(Eviction) 소멸시킵니다.
  - **Hierarchical Summary Core Block**: 소거된 과거 실행 이력 메시지들은 그냥 유실시키는 것이 아니라, 소형 압축 언어 모델을 가동해 "현재까지 에이전트가 도출한 성과 및 발견한 도구 실행 상태 변수 매트릭스"라는 한 단락짜리 핵심 요약 코어 블록으로 동적 축약 압축하여 컨텍스트 최상단 Pinned 영역에 고정 탑재합니다. 이 구조를 가동함으로써 에이전트는 무한한 물리 시간 동안 상태 붕괴나 VRAM 파괴 없이 완벽하게 장기 자율 과업을 수행해 낼 수 있게 됩니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 ReAct 추론 루프 및 JSON Schema 기반 Function Calling 에이전트 소스코드
다음 소스코드는 AI 에이전트의 구동 정수인 **인지-추론-계획-행동-관찰(ReAct)** 동적 루프와, 엄격한 **JSON Schema 매개변수 파싱 및 격리된 임시 파일 입출력(Code-execution) 도구**가 하나의 단일 시스템 오케스트레이터 안에서 완벽히 동기화되어 작동하도록 구현된 파이썬 프로덕션 스크립트입니다.

```python
import os
import json
import re
import tempfile
import requests
from typing import Dict, Any, List, Tuple

# =====================================================================
# 1. 외부 상태 변이를 위한 격리 파일 코드 실행(Code-execution) 도구 설계
# =====================================================================
class IsolatedFileSandbox:
    def __init__(self):
        # 호스트 OS 보호를 위한 격리 임시 폴더 물리 매핑 구축
        self.sandbox_dir = tempfile.TemporaryDirectory(prefix="agent_sandbox_")
        print(f"[SYSTEM::SANDBOX] 격리 실행 샌드박스가 수립되었습니다: {self.sandbox_dir.name}")

    def clean_up(self):
        self.sandbox_dir.cleanup()

    def write_and_execute_python(self, file_name: str, code_content: str) -> Dict[str, Any]:
        """
        [Physical Action Tool] 샌드박스 내부 디렉터리에 코드를 자율 생성(Write)하고 직접 컴파일 구동
        """
        target_path = os.path.join(self.sandbox_dir.name, file_name)
        
        # 1단계: 파일 쓰기(Write) 물리 전이 실행
        with open(target_path, "w", encoding="utf-8") as f:
            f.write(code_content)
            
        # 2단계: subprocess 격리 가동을 통한 코드 실행 전개
        import subprocess
        try:
            run_result = subprocess.run(
                ["python3", target_path],
                capture_output=True,
                text=True,
                timeout=5 # 자원 폭주 무한 데드락 선제 차단
            )
            
            if run_result.returncode == 0:
                return {
                    "status": "SUCCESS",
                    "stdout": run_result.stdout.strip(),
                    "stderr": ""
                }
            else:
                return {
                    "status": "RUNTIME_ERROR",
                    "stdout": run_result.stdout.strip(),
                    "stderr": run_result.stderr.strip()
                }
        except subprocess.TimeoutExpired:
            return {
                "status": "TIMEOUT",
                "message": "코드가 허용 시간 5초 내에 동작을 완수하지 못해 강제 소멸되었습니다."
            }
        except Exception as e:
            return {
                "status": "UNEXPECTED_SYSTEM_FAILURE",
                "message": str(e)
            }


# =====================================================================
# 2. JSON Schema 규격 명세에 대응하는 ReAct 에이전트 제어 엔진
# =====================================================================
class ProductionReActAgent:
    def __init__(self, api_key: str, endpoint: str = "https://api.openai.com/v1/chat/completions"):
        self.api_key = api_key
        self.endpoint = endpoint
        self.model_name = "gpt-4-turbo"
        self.sandbox = IsolatedFileSandbox()
        
        # 에이전트 단기 상태 이력 메모리 (Short-term Context)
        self.state_memory: List[Dict[str, Any]] = []
        
        # JSON Schema를 만족하는 도구 정의서 명세 각인 [37, 38]
        self.tool_schema_manifesto = {
            "name": "write_and_execute_python",
            "description": "격리된 파일 공간 내부에서 직접 파이썬 스크립트 파일을 작성하고 프로세스를 구동하여 연산 결과를 반환받습니다.",
            "parameters": {
                "type": "object",
                "properties": {
                    "file_name": {
                        "type": "string",
                        "description": "생성할 파일의 물리 이름 (예: calculation.py)"
                    },
                    "code_content": {
                        "type": "string",
                        "description": "실행할 완전한 파이썬 소스코드 텍스트"
                    }
                },
                "required": ["file_name", "code_content"]
            }
        }

    def set_system_instructions(self, manifesto_prompt: str):
        self.state_memory.append({
            "role": "system",
            "content": manifesto_prompt
        })

    def _parse_agent_action_using_regex(self, response_text: str) -> Tuple[bool, Dict[str, Any]]:
        """
        정규표현식을 활용하여 XML/JSON 혼합 출력 속에서 물리 도구 호출 인자를 정확히 추출하는 정밀 파서
        """
        # [Action] 블록 안의 JSON 양식을 캡처하는 강력한 정규식 매핑
        action_match = re.search(r"\[Action\]\s*(\{.*?\})", response_text, re.DOTALL)
        if not action_match:
            return False, {}
            
        try:
            json_payload = json.loads(action_match.group(1).strip())
            return True, json_payload
        except json.JSONDecodeError:
            # 엄격 구조 파싱에 실패했을 때, 유동적 예외 정제 시도
            try:
                # 홑따옴표 교체 및 특수 제어문 전처리 복원 시도
                cleaned_json_text = action_match.group(1).replace("'", '"')
                return True, json.loads(cleaned_json_text)
            except:
                return False, {}

    def execute_react_loop(self, user_goal: str, max_turns: int = 5) -> str:
        """
        [Thought -> Action -> Observation -> Re-Plan] 지능형 Loop 전개기
        """
        self.state_memory.append({
            "role": "user",
            "content": user_goal
        })
        
        turn = 0
        while turn < max_turns:
            print(f"\n[AGENT] 자율 추론 및 의사결정 회차: {turn + 1}/{max_turns}")
            
            # Step 1: 현재까지의 상태 메모리를 디코더에 인입해 의사결정 상태 획득
            headers = {
                "Authorization": f"Bearer {self.api_key}",
                "Content-Type": "application/json"
            }
            payload = {
                "model": self.model_name,
                "messages": self.state_memory,
                "temperature": 0.0 # 의사결정 포커스를 일치시키기 위해 영(0)으로 영점 수축
            }
            
            response = requests.post(self.endpoint, headers=headers, json=payload)
            response_data = response.json()
            model_text = response_data["choices"][0]["message"]["content"]
            
            # 모델의 생각을 단기 상태 메모리에 누적 적재
            self.state_memory.append({"role": "assistant", "content": model_text})
            print(f"[Thought/Plan]\n{model_text}")
            
            # Step 2: 정규 표현식 및 파서 기동을 통한 도구 호출 텐서 추출
            has_action, action_payload = self._parse_agent_action_using_regex(model_text)
            
            if not has_action:
                print("[SYSTEM::INFO] 모델이 추가 도구 호출 없이 최종 정답을 전진 수렴 도출했습니다.")
                return model_text
                
            # Step 3: 물리 도구 작동 및 Observation 피드백 연접 [35, 37]
            tool_name = action_payload.get("tool_name")
            tool_args = action_payload.get("arguments", {})
            
            print(f"[SYSTEM::ACTION] '{tool_name}' 물리 장치 기동. 매개변수: {tool_args}")
            
            if tool_name == "write_and_execute_python":
                observation_result = self.sandbox.write_and_execute_python(
                    file_name=tool_args.get("file_name", "temp.py"),
                    code_content=tool_args.get("code_content", "print('Empty code')")
                )
            else:
                observation_result = {"status": "ERROR", "message": f"시스템에 존재하지 않는 무단 도구 '{tool_name}'이 호출되었습니다."}
                
            print(f"[SYSTEM::OBSERVATION] 외부 피드백 수집 완료: {observation_result}")
            
            # 관찰(Observation) 피드백 메시지를 사용자(User) 또는 시스템 역할(System) 템플릿으로 다음 추론 프롬프트에 융합 연접
            self.state_memory.append({
                "role": "user",
                "content": f"[Observation 피드백]\n{json.dumps(observation_result)}"
            })
            
            turn += 1
            
        self.sandbox.clean_up()
        return "최대 추론 루프 허용한도를 도파하여 태스크가 안전 강제 중단되었습니다."
```

### 3.2 핵심 시스템 설계 규격과 Function Calling 제어 파라미터 매핑 분석
구현된 ReAct 에이전트의 안정 가동과 자원 제어를 수호하는 매개변수 간의 유기적 매핑 관계는 다음과 같습니다.

- **`temperature=0.0` (형식 무결성 구속)**:
  - **영향 및 원리**: 에이전트 시스템이 외부 도구 호출을 수행하는 의사결정 지점에 다다랐을 때, `temperature`를 조금이라도 허용하면 모델은 매 실행 세션마다 JSON 포맷의 대괄호, 중괄호 정렬 위치를 바꾸거나 임의의 설명 단어들을 Action 구문 내부로 탈선 주입시키는 혼탁 현상을 범합니다. 이는 정형 파서 모듈의 즉각적인 예외 사망 크래시를 의미하므로 확률 분포 탐색 범위를 zero로 엄격 통제하는 것입니다.
- **정규식 기반 돔/JSON 역추출 필터 (`_parse_agent_action_using_regex`)**:
  - **영향 및 원리**: LLM은 완벽한 원시 JSON만을 정밀하게 출력해 내지 못하고 앞뒤에 "물리적인 코드 실행 결과를 파이썬 스크립트로 도출하겠습니다"라는 식의 부연 설명용 텍스트를 연접해 뿜어내기 십상입니다. 텍스트 전체를 `json.loads`로 밀어 넣으면 100% 포맷 해석 예외 에러가 유발되므로, 오직 구조적인 `[Action]` 헤더 표식을 캡처하는 강력한 정규식을 전치 마운트하여 기하학적 인자 추출 무결성을 방어해 냅니다.

<br><br>
그러나 현실의 초거대 모델이 생성하는 텍스트 전체는 부연 문장 찌꺼기가 앞단과 뒷단에 무작위 섞여 방출되기 때문에, 순수한 `json.loads`를 호출하면 구조 오차 예외로 인해 파서가 런타임에 폭사합니다. 이를 완벽히 방어하기 위해, 에이전트 실행기 후단에는 `\[Action\]\s*(\{.*?\})` 구조의 특정 식별 구획만을 도려내어 유연하게 추출하는 정규 표현식(Regular Expressions) 전처리 파싱 필터의 구축이 필히 의무 마운트되어야 합니다. 
<br><br>
정규식 필터는 모델이 설령 문법적인 실수를 일부 저질러 XML 형태가 오염되었거나 JSON 중괄호 바깥에 마크다운 백틱 문자열이 포함되었더라도, 이를 기하학적 의미 공간 상에서 정밀 캡처 여과하여 물리 실행 인자값만을 안전하게 격격 인출해 내므로, 비결정적으로 요동치는 에이전트의 출력을 결정론적인 인프라 구동 쉘 안으로 매끄럽고 견고하게 안착시키는 시스템 무결 구동을 완수하게 돕습니다.

헤드리스 크롬 드라이버를 조작하는 Browser Agent와 파일 Read/Write 코드 실행 엔진을 다단계 장기 수명주기 동안 백그라운드 운용할 경우, 실시간 유입되는 콘솔 에러 로그 및 웹 DOM 소스, screenshot 멀티모달 이미지 임베딩 벡터값은 프롬프트 버퍼를 포화시켜 어텐션 연산량을 기하급수적으로 폭증시킵니다.
<br><br>
이 토큰 폭주(Token Exploding) 및 입력 공간 포화에 의한 어텐션 정렬 붕괴(Attention Saturation)를 기하학적·정량적으로 통제하기 위한 메모리 감쇄/압축 수렴 엔지니어링의 정밀 규약 설계 가이드는 다음과 같이 수립됩니다:
1. **Dynamic Sliding Window (슬라이딩 메모리 정화)**:
   - 전역 에이전트 `MessagesState`에 누적되는 관찰 피드백 중 오직 최신 $N$회차(실무 설계 기준: $N=2$ 또는 최신 4k 토큰 규모)의 로우 `Observation` 원본 텍스트만을 활성 메모리 풀에 유지시킵니다.
   - 이 임계 한계 범위를 초과하는 오래된 과거 툴 실행 메시지들은 어텐션 계산 연산량 감소를 위해 프롬프트 빌드 단계 전단에서 즉각 물리적으로 배제소거(Eviction) 및 휘발 소멸시켜, 프리필(Prefill) 비용을 $O(\text{Window Size}^2)$ 레벨의 상수 공간 대역 내로 원천 구속시킵니다.
2. **Hierarchical Summary Core Block (계층형 상태 요약 덮어쓰기)**:
   - 휘발 축출되는 모든 과거의 Thought, Action, Observation 메시지들의 누적 의미를 단순히 날려버리지 않기 위해, 소형 고속 언어 모델을 비동기(Asynchronous)로 트리거 가동합니다.
   - 이전 루프까지 도출해낸 "전체 임무 목표 대비 현재까지 달성 완료된 코드 개발 진척율", "확인 완료된 웹 인터페이스 좌표 목록", "샌드박스 내부 유지 변수 상태표"를 500토큰 이내의 조밀한 단일 계층 요약 마크다운 블록($C_{\text{summary}}$)으로 동적 재압축 압축합니다.
   - 이 핵심 요약 블록을 시스템 프롬프트(System Manifesto) 직후 최상단 고정 Pinned 영역 상에 상시 덮어쓰기 업데이트 매핑 처리합니다.
<br><br>
이 이중 메모리 압축 및 제어 장치를 정밀 구현해야만, 에이전트가 며칠 이상 장기 실행을 영위하더라도 물리 토큰 포화 한계선을 절대 초과하지 않는 최고의 하드웨어 연산 가용성과 정밀한 도구 제어 정확도를 동시에 완수할 수 있게 됩니다.
