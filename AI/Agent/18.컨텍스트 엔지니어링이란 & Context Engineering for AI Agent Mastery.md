# [컨텍스트 엔지니어링이란 & Context Engineering for AI Agent Mastery]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 에이전트의 역설: 컨텍스트 부패(Context Rot)와 큐레이션(Curation)의 필연성
대형 언어 모델(LLM)이 단발성 대화를 넘어 스스로 계획을 수립하고 도구를 실행하는 자율 에이전트 시스템으로 진화하면서, 컨텍스트의 과부하는 시스템 성능을 저해하는 가장 치명적인 병목이 되었습니다.
*   **컨텍스트 부패(Context Rot) 현상**: 사용자와의 대화가 길어질수록, 그리고 에이전트가 작동하는 과정에서 첨부 파일 내용, 도구 사용 결과(Observation), 장기 기억(LTM) 이력 등이 누적 적재될수록 모델의 컨텍스트 윈도우는 급격하게 비대해집니다. 이처럼 컨텍스트가 길어질수록 모델은 집중력 저하와 기억력 감퇴를 겪게 되며, 시스템 규칙 준수에 실패하거나 도구 매개변수를 잘못 매핑하는 등 의사결정의 오작동 확률이 기하급수적으로 증가합니다. 이를 '컨텍스트 부패(Context Rot)'라고 부릅니다.
*   **컨텍스트 엔지니어링의 정의**: 단순한 단일 턴 질의 최적화를 다루는 프롬프트 엔지니어링(Prompt Engineering)과 달리, 컨텍스트 엔지니어링(Context Engineering)은 여러 턴에 걸친 복잡한 상호작용 과정에서 에이전트가 올바른 결정을 내릴 수 있도록 **모델에 주입되는 정보 흐름 전체를 정교하게 큐레이션(Curation)하는 고도의 아키텍처 설계 예술이자 과학**입니다.

### 1.2 컨텍스트 엔지니어링의 5가지 핵심 기법 및 균형 모델
에이전트가 받아들이는 정보의 양과 질을 제어하기 위해 시스템 아키텍처 레벨에서 선택할 수 있는 5가지 핵심 제어 수단은 다음과 같이 정립됩니다.
*   **오프로딩 (Offloading)**: 프롬프트에 직접 담기에는 너무 무겁거나 원시적인 지식 상태(Raw Data)를 외부 시스템(예: 로컬 파일 시스템, 임시 데이터베이스)으로 이관하고, 컨텍스트 윈도우에는 최소한의 핵심 식별 정보만 남겨 VRAM 계산량을 상수로 억제합니다.
*   **축소 (Reducing)**: 정보가 유입될 때 중복되거나 무익한 텍스트 찌꺼기를 날려버리고 알짜 흐름만 남기기 위해 압축 또는 요약 알고리즘을 강제 적용합니다.
*   **검색 (Retrieving)**: 모든 배경 지식을 시스템 메시지에 상시 탑재하는 비효율을 거부하고, 오직 당면 태스크를 해결하는 데 필수적인 지식 청크만을 실시간 동적 쿼리를 통해 인-컨텍스트로 선택 소환합니다.
*   **격리 (Isolating)**: 메인 오케스트레이터 에이전트가 모든 복잡한 하위 컨텍스트를 홀로 감당하지 않도록, 관심사 분리(Separation of Concerns) 원칙에 의거해 특화된 서브 에이전트(Sub-agent)에게 독립된 컨텍스트 창을 제공하여 심층 연산을 전치 격리합니다.
*   **캐싱 (Caching)**: 동일한 지식 스키마나 가이드라인이 매 회차 반복 입력되어 토큰 요금이 이중 과금되거나 프리필(Prefill) 병목을 유발하지 않도록 런타임 캐시 레지스트리에 결과를 영속화하여 재사용합니다.

### 1.3 가역적 압축(Compaction)과 비가역적 요약(Summarization)의 아키텍처적 조율
정보를 축소하는 세부 메커니즘은 데이터의 가역성 여부에 따라 명확히 구분되며, 모델의 추론 성능 저하가 시작되는 '부패 전 임계값(Pre-rot Threshold, 보통 128k~200k 토큰)'에 도달하기 전 시스템적으로 트리거되어야 합니다.
*   **가역적 압축 (Compaction)**: 정보 손실률 0%를 보장하는 설계 방식입니다. 예를 들어 에이전트가 `write_file(path, content)` 도구를 가동하여 대규모 파일을 물리 디스크에 기록했을 때, 생성 결과 원문 전체를 프롬프트 로그에 구겨 넣지 않고 오직 `[File written: /path/to/file.txt]` 라는 단 한 줄의 참조 정보(Path Pointer)만 컨텍스트에 남기고 원본 내용은 디스크로 이탈(Offloading)시킵니다.
*   **비가역적 요약 (Summarization)**: 정보 손실 가능성이 존재하는 축약 방식입니다. 대화가 누적되어 어텐션 밀도가 흐려질 때 가동하며, 자유 형식(Free-form)의 밋밋한 텍스트 요약을 전개할 경우 필수 시스템 제약 규칙이 함께 증발하는 오염이 생길 수 있으므로, 반드시 **스키마 기반의 구조화된 요약(Structured Schema Summary)** 정책을 채택해 핵심 마일스톤 변수와 상태 정보만을 안전하게 동적 압축해 나가야 합니다.

### 1.4 Claude Code의 컨텍스트 제어 혁신: Skills 구조와 YAML Frontmatter 매핑
앤트로픽(Anthropic)의 대표적 CLI 코딩 에이전트인 **Claude Code**는 로컬 파일 시스템 제어권을 확보하고 있다는 강점을 활용해 동적 프롬프트 주입과 컨텍스트 최적화를 극한으로 전개합니다.
*   **CLAUDE.md를 통한 기본 가이드 마운트**: 에이전트가 프로젝트를 처음 시작해 대화를 개시하는 즉시 프로젝트 최상단 디렉토리에 마운트된 `CLAUDE.md` 가이드라인 파일을 백그라운드에서 자동 판독하여, 프롬프트에 동적으로 기본 맥락을 자동 인입시킵니다.
*   **Skills(스킬)을 통한 동적 로딩 및 토큰 극적 절감**:
    *   **개념**: 스킬은 에이전트가 특정 전문 작업을 완수하기 위해 수시로 검색하고 메모리에 로드할 수 있도록 Instructions, Scripts, Resources가 패키징된 독립적인 스킬 폴더 구조입니다.
    *   **YAML Frontmatter 트릭**: 메인 에이전트의 상시 시스템 프롬프트(System Prompt) 버퍼에는 각 스킬 파일 최상단에 기재된 극소량의 YAML Frontmatter 핵심 요약 설명(YAML Description)만을 병입 적재합니다. 
    *   **동적 트리거링**: 에이전트 본체는 평소에는 수만 토큰에 달하는 개별 스킬들의 복잡한 세부 명세나 실행 스크립트 코드를 전혀 메모리에 올리지 않고 대화를 전개합니다. 그러다가 특정 전문 작업(예: PDF 파싱, 대규모 DB 마이그레이션)을 실행해야겠다고 판단한 그 시점에 이르러서야 비로소 가상의 `cat /mnt/skills/pdf/SKILL.md` 명령어를 자율 트리거하여 해당 스킬 파일 내부의 무거운 원본 Instruction을 로드해 판독합니다. 이 점진적 탐색 및 조건부 로딩 설계를 통해, 에이전트의 컨텍스트 윈도우 평상시 부하를 90% 이상 절감하면서도 실행 정확도를 극대화할 수 있습니다.

### 1.5 MCP 서버의 폭발적 토큰 증가를 해결하는 "MCP with Code-Execution" 아키텍처
Model Context Protocol(MCP)은 풍부한 외부 API와 도구 생태계를 제공하지만, 실무적인 가동 과정에서 치명적인 컨텍스트 오버헤드를 유발합니다.
*   **MCP의 컨텍스트 비대화(Context Hog) 병목**: 수십, 수백 개의 외부 데이터베이스, API, 터미널 도구 등을 MCP 서버를 통해 에이전트에 노출하게 되면, 각각의 도구 명세(JSON Schema)가 시스템 메시지를 가득 채울 뿐 아니라 툴의 가동 결과로 쏟아져 나오는 수천, 수만 행의 원시 데이터(Raw JSON, DB 덤프)가 컨텍스트 윈도우를 순식간에 Overflow시켜 시스템을 기각 상태로 몰고 갑니다.
*   **Code-execution(코드 실행)을 통한 돌파 메커니즘**:
    *   최근 컨텍스트 엔지니어링 업계에서 화두가 되는 **MCP with Code-Execution** 방법론은, 모든 개별 마이크로 도구를 직접 LLM 콘텍스트 상에 하나하나 바인딩해 호출하는 구조를 포기합니다.
    *   대신, 에이전트가 격리된 가상 머신(MicroVM/Docker) 내부의 코드 실행 환경과 소통할 수 있는 최소한의 코드 API 및 파일 실행 도구만을 콘텍스트에 연결해 둡니다.
    *   에이전트는 대규모 DB 가동이나 다중 API 조회가 필요할 때, 직접 그 작업을 동적으로 처리하는 복잡한 파이썬 스크립트 코드를 즉석에서 작성하여 샌드박스로 전송 구동시킵니다.
    *   **데이터 필터링의 로컬 오프로딩**: 수만 줄의 원시 원천 데이터는 프롬프트 영역으로 유입되지 않고, 격리된 샌드박스 가상 메모리 내에서 실행된 코드 환경 상에서 완벽하게 전처리, 병합, 정렬, 필터링 과정을 거칩니다. 에이전트는 단지 최종 처리되어 기가 막히게 축약된 핵심 결과 분석값과 에러 유무 요약본만을 LLM 컨텍스트 윈도우로 리턴해 수용합니다. 이 접근법을 탑재해야만 무제한에 가까운 외부 MCP 환경의 기능을 컨텍스트 윈도우 폭주 없이 영속적으로 지배 통제할 수 있게 됩니다.

### 1.6 Manus AI의 파일 기반 상태 제어 및 컨텍스트 오프로딩(Context Off-loading)
*   **todo.md 기반의 실시간 상태 동기화**: 글로벌 탑티어 에이전트 서비스인 Manus AI는 계획 수립(Planning)의 일관성을 유지하기 위해 복잡한 대화 이력 텐서 대신 로컬 디렉토리 상에 물리적으로 기록되는 `todo.md` 상태 파일을 핵심 통제판으로 활용합니다. 매 ReAct 루프 시점마다 이 파일 내부의 마일스톤 진척도(`- [ ]` -> `- [x]`)를 물리적으로 갱신 기재함으로써 시스템 동결 시 회복 오프셋 지점으로 사용합니다.
*   **컨텍스트 오프로딩(Context Off-loading)**: 웹 브라우저 자동화나 대량의 스크레이핑 데이터 수확 과정에서 발생하는 장대하고 지저분한 HTML DOM 트리나 텍스트 로그 전체를 모델 어텐션 콘텍스트에 절대 다이렉트로 연접하지 않습니다. 대신 `abc_mart_raw.txt`, `temp_scraped.csv` 등의 형태로 가상 디스크 파일 상에 완전 오프로딩하여 격리 보존시키고, 마스터 에이전트의 대화 버퍼에는 "500행의 정보 수집 완료 및 파일 쓰기 격리 보관 처리됨" 이라는 한 줄짜리 메타 매트릭스 텐서만 주입하여 VRAM 연산 복잡도 $O(T^2)$의 입력 팽창 위협을 기하학적으로 무력화합니다.

### 2.1 파일 오프로딩 및 MCP with Code-Execution 하이브리드 에이전트의 데이터 흐름도
아래 아키텍처 흐름도는 Claude Code의 Skills 선택 로딩 기조와 MCP with Code-Execution 설계가 결합되었을 때, 무거운 데이터가 프롬프트 외부로 어떻게 오프로딩되고 고순도 맥락만 제어판에 인입되는지 보여주는 물리 데이터 흐름입니다.

```
       │
       ▼ [1단계: CLAUDE.md 자동 주입 및 Skills Metadata 로딩]
[MCP 호스트 컨텍스트 버퍼 조립]
  - CLAUDE.md 규칙 병입 주입
  - 가용 스킬 목록(YAML Frontmatter)만 시스템 프롬프트에 콤팩트 탑재 (VRAM 절감)

       │
       ▼ [3단계: MCP with Code-Execution 단계 진입 (핵심 우회망)]
[Code-Execution 샌드박스 가동]
  - 에이전트가 Postgres DB 연결 및 수백만 행 조회를 자율 처리하는 Python 코드 작성 및 송출
       │
       ├─────────────────────────────────────────┐
       ▼ [로컬 격리 샌드박스 내부 고속 연산]       ▼ [컨텍스트 격리 (Isolating)]
[Postgres MCP DB 드라이버 타격 및 쿼리 전개]   [수백만 행의 원시 DB 결과 덤프 데이터]
  - 대용량 데이터 로컬 파일 쓰기 오프로딩      - LLM 컨텍스트로 송출 전면 차단 (VRAM 보호)
  - 파이썬 Pandas를 활용한 고속 전처리 필터링    - 오직 로컬 샌드박스 RAM 영역 내에만 고립 상주
       │                                         │
       ▼                                         ▼
[가역적 압축 결과 도출 (Observation)] ◄───────────┘
  - "Postgres query success: 1,425,000 rows parsed locally. 
     Detected 3 anomalous transaction logs and written to anomalous_tx.csv."
       │
       ▼ [4단계: 최소 정보 기반 최종 의사결정 수렴]
[마스터 에이전트 최종 디코딩]
  - 어텐션 포화와 Lost in the Middle 없이 3개의 이상 로그 정보에만 어텐션 백퍼센트 집중
       │
       ▼

```

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 MCP with Code-Execution 및 Skills 기반 컨텍스트 오프로딩 시뮬레이터
다음 소스코드는 대량의 데이터 처리 시 발생할 수 있는 컨텍스트 윈도우 폭주를 우회하기 위해, **가상의 YAML Frontmatter 스킬 검색 및 동적 Instruction 로드, 그리고 격리된 코드 실행 환경을 활용해 로우 데이터를 로컬에서 처리하고 요약본만 프롬프트 버퍼로 회수**하는 프로덕션 레벨 컨텍스트 제어 파이썬 에뮬레이터 스크립트입니다.

```python
import os
import json
import tempfile
import subprocess
import requests
from typing import Dict, Any, List

class ContextEngineeringAgentSimulator:
    def __init__(self, api_key: str):
        self.api_key = api_key
        self.endpoint = "https://api.openai.com/v1/chat/completions"
        self.model_name = "gpt-4-turbo"
        self.context_history: List[Dict[str, Any]] = []
        
        # 1. 임시 가상 격리 파일 시스템(샌드박스) 환경 구축
        self.sandbox_dir = tempfile.TemporaryDirectory(prefix="secure_context_env_")
        
        # 2. Claude.md 기본 컨텍스트 및 todo.md 마일스톤 생성 (Planning 오프로딩)
        self._write_sandbox_file("CLAUDE.md", "## 개발 가이드라인\n- 출력 보고서는 반드시 정형화된 JSON 형식을 준수해야 한다.")
        self._write_sandbox_file("todo.md", "# 진행 마일스톤\n- [ ] 1. 대용량 로그 파일 스캔 및 필터링\n- [ ] 2. 요약 리포트 최종 수렴")

        # 3. YAML Frontmatter만 노출시킨 초경량 Skills 레지스트리 정의 (VRAM 절감 구조)
        self.skills_registry = {
            "log_parser_skill": {
                "yaml_frontmatter": "name: Log Parser Skill\ndescription: 수만 행의 원시 텍스트 로그를 로컬에서 파이썬으로 가공 분석하는 초경량 가역 스킬.",
                "full_instruction_path": "skills/log_parser_instruction.txt",
                "full_instruction_content": "당신은 Log Parser 전문가입니다. 원시 로그에서 오직 'ERROR' 식별 부호가 담긴 라인만 정규식으로 필터링하여 CSV로 저장한 후, 카운트 결과 요약본(JSON)만 메인 메모리로 보고하십시오."
            }
        }
        
        # 4. 가용 툴 카탈로그 설계: 툴 스펙 자체를 상수로 고정하여 컨텍스트 비대화 방어
        self.tools_schema = [
            {
                "type": "function",
                "function": {
                    "name": "trigger_and_load_full_skill",
                    "description": "YAML 스니펫만 보고 해당 스킬이 필요하다고 확신할 때, 스킬 파일의 무거운 원본 Instruction 전문을 동적으로 런타임에 로드합니다.",
                    "parameters": {
                        "type": "object",
                        "properties": {
                            "skill_key": {"type": "string", "description": "로드할 스킬의 고유 키 식별자 (예: log_parser_skill)"}
                        },
                        "required": ["skill_key"]
                    }
                }
            },
            {
                "type": "function",
                "function": {
                    "name": "execute_code_locally_and_offload",
                    "description": "대용량 외부 가상 DB 질의 및 파일 처리를 안전하게 처리하는 코드를 로컬 가상 쉘에서 구동하고 요약 결과만 수집합니다.",
                    "parameters": {
                        "type": "object",
                        "properties": {
                            "python_code": {"type": "string", "description": "로컬 샌드박스에서 구동될 데이터 전처리 파이썬 코드"}
                        },
                        "required": ["python_code"]
                    }
                }
            }
        ]

    def _write_sandbox_file(self, filename: str, content: str):
        path = os.path.join(self.sandbox_dir.name, filename)
        with open(path, "w", encoding="utf-8") as f:
            f.write(content)
        print(f"[SYSTEM::SANDBOX] 파일 오프로딩 쓰기 성공: {filename}")

    def initialize_system_context(self):
        """
        초기 프롬프트 구성: 무거운 상세 지침을 일절 배제하고 오직 초경량 YAML 스킬 메타와 기본 규정만 인입
        """
        skills_summary_block = "\n---\n".join([
            f"스킬 식별 키: {key}\n{val['yaml_frontmatter']}" 
            for key, val in self.skills_registry.items()
        ])
        
        system_manifesto = (
            "당신은 사내 대규모 시스템 인프라를 분석 제어하는 무결성 에이전트입니다.\n"
            "기본적으로 CLAUDE.md 규정을 따르며, 무거운 연산이나 대량의 데이터 처리가 필요할 경우 "
            "반드시 'execute_code_locally_and_offload' 도구를 활용하여 결과를 로컬에서 분석 요약한 뒤 보고하십시오.\n\n"
            f"--- [사용 가능한 초경량 동적 스킬 목록] ---\n{skills_summary_block}"
        )
        self.context_history.append({"role": "system", "content": system_manifesto})

    def run_inference(self) -> Dict[str, Any]:
        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json"
        }
        payload = {
            "model": self.model_name,
            "messages": self.context_history,
            "tools": self.tools_schema,
            "tool_choice": "auto",
            "temperature": 0.0  # 정밀 도구 매핑 및 스키마 준수를 위해 완전히 결정론적으로 제어
        }
        response = requests.post(self.endpoint, headers=headers, json=payload)
        return response.json()["choices"][0]["message"]

    def dispatch_agentic_loop(self, user_command: str):
        """
        오프로딩 및 동적 스킬 로딩 메커니즘을 전개하는 핵심 오케스트레이터 루프
        """
        self.context_history.append({"role": "user", "content": user_command})
        
        # 가상의 대형 로그 파일(50,000행 모의 데이터)을 사전에 로컬 디렉토리에 조용히 오프로딩 보존
        # 이를 통해 이 수만 줄의 텍스트가 마스터 LLM의 콘텍스트 윈도우에 연접 적재되는 것을 철저히 예방
        mock_giant_log = "INFO::All green\n" * 49999 + "ERROR::FATAL_PG_ACCESS_DENIED_ON_PORT_5432_ANOMALY\n"
        self._write_sandbox_file("giant_system_log.txt", mock_giant_log)
        
        print("\n[AGENTIC_LOOP] 1회차 자율 추론 개시 - 도구 및 동적 스킬 호출 판단")
        decision = self.run_inference()
        self.context_history.append(decision)
        
        tool_calls = decision.get("tool_calls")
        if tool_calls:
            for call in tool_calls:
                name = call["function"]["name"]
                args = json.loads(call["function"]["arguments"])
                call_id = call["id"]
                
                if name == "trigger_and_load_full_skill":
                    skill_key = args.get("skill_key")
                    print(f"[AGENT] '{skill_key}' 스킬 트리거 감지. 디스크로부터 고성능 세부 지침을 동적으로 로딩합니다.")
                    
                    # 수만 토큰에 달할 수 있는 상세 Instruction을 이제야 비로소 가져와 인-컨텍스트에 주입
                    full_instruction = self.skills_registry[skill_key]["full_instruction_content"]
                    observation = {
                        "status": "SKILL_LOADED",
                        "loaded_instruction": full_instruction
                    }
                    self.context_history.append({
                        "role": "tool",
                        "tool_call_id": call_id,
                        "name": name,
                        "content": json.dumps(observation)
                    })
                    
                    # 동적으로 스킬이 로드된 상태에서 2회차 추론 진행 (코드 생성 유도)
                    print("\n[AGENTIC_LOOP] 2회차 자율 추론 개시 - 로컬 코드 전처리 연산 생성")
                    second_decision = self.run_inference()
                    self.context_history.append(second_decision)
                    
                    second_tool_calls = second_decision.get("tool_calls")
                    if second_tool_calls:
                        for s_call in second_tool_calls:
                            s_name = s_call["function"]["name"]
                            s_args = json.loads(s_call["function"]["arguments"])
                            s_call_id = s_call["id"]
                            
                            if s_name == "execute_code_locally_and_offload":
                                python_code = s_args.get("python_code")
                                print("[AGENT] MCP with Code-Execution 실행 시작. 대용량 연산을 샌드박스로 오프로딩합니다.")
                                
                                # 로컬 샌드박스 내부에서 작성된 스크립트 파일을 안전 격리 실행 (컴파일러 가동)
                                run_result = self._physical_sandbox_execute(python_code)
                                
                                self.context_history.append({
                                    "role": "tool",
                                    "tool_call_id": s_call_id,
                                    "name": s_name,
                                    "content": json.dumps(run_result)
                                })
                                
                                # 최종 추론을 통해 무결한 요약 결과 출력 수렴
                                print("\n[AGENTIC_LOOP] 최종 수렴 추론 개시 - 오프로딩된 결과를 받아 최종 보고")
                                final_response = self.run_inference()
                                
                                # 마일스톤(todo.md)을 최종 완료 상태로 갱신 보존
                                self._write_sandbox_file("todo.md", "# 진행 마일스톤\n- [x] 1. 대용량 로그 파일 스캔 및 필터링\n- [x] 2. 요약 리포트 최종 수렴")
                                return final_response.get("content")

        return decision.get("content")

    def _physical_sandbox_execute(self, code: str) -> Dict[str, Any]:
        """
        로컬 샌드박스 내에서 파이썬 코드를 격리 실행하고 결과 메타 데이터만 추출하여 
        어텐션 맵의 포화를 완벽하게 통제
        """
        with tempfile.NamedTemporaryFile(suffix=".py", dir=self.sandbox_dir.name, mode="w", delete=False) as tmp:
            tmp.write(code)
            tmp_path = tmp.name
            
        try:
            # 샌드박스 내의 파일을 안전하게 읽어 처리하도록 스크립트 강제 구동
            result = subprocess.run(
                ["python3", tmp_path],
                capture_output=True,
                text=True,
                timeout=5,
                cwd=self.sandbox_dir.name
            )
            os.unlink(tmp_path)
            
            # 수십만 행의 원문 텍스트는 리턴 정보에서 전면 배제하고 오직 통계 및 결과 요약 메타만 리턴
            return {
                "execution_status": "SUCCESS" if result.returncode == 0 else "FAILED",
                "stdout": result.stdout.strip()[:1000],  # 아웃풋 스트림 길이 한계 구속
                "stderr": result.stderr.strip()
            }
        except Exception as e:
            if os.path.exists(tmp_path):
                os.unlink(tmp_path)
            return {"execution_status": "CRASHED", "error": str(e)}
```

### [질문 3]

### 💡 1번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
다중 MCP 서버를 에이전트 시스템에 대거 등록하면, 각 서버가 제공하는 수십 개에서 수백 개의 도구 기능 명세(JSON Schema)가 시스템 프롬프트 최상단에 상시 정적으로 탑재됩니다. 이로 인해 모델이 당장 사용하지 않는 도구의 이름과 매개변수 데이터까지 수만 토큰 이상을 고스란히 점유하게 되는 '컨텍스트 비대화(Context Hog)' 병목이 유발됩니다. 
<br><br>
이 상태에서 어텐션 맵의 정렬 점수 분배 수식은 다음과 같은 수학적 한계에 부딪힙니다:
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
여기서 소프트맥스 함수는 입력 차원 벡터들의 지수함수적 상대 비율로 동작하기 때문에, 입력 토큰의 총량 $T$가 팽창할수록 소프트맥스의 분모 항인 $\sum_{j=1}^{T} e^{s_j}$ 역시 비대해집니다. 결과적으로 에이전트가 지금 당장 내려야 하는 '올바른 도구 선택 판단 규칙'이 포함된 진짜 중요한 시스템 지침 토큰 $i$에 할당되어야 할 가중치 $\text{softmax}(s_i)$의 값은 기하학적으로 희석되어 $0$에 가깝게 수축 수렴해 버립니다. 이것이 곧 도구 매개변수의 오입력, 포맷 불일치, 그리고 엉뚱한 행동 이탈(Divergence) 장애로 직결되는 수학적 인과관계입니다.
<br><br>
이를 원천 제어하는 'MCP with Code-Execution' 아키텍처는 에이전트가 개별 도구를 직접 인-컨텍스트로 가동하는 것을 전면 금지시킵니다. 대신, 격리된 가상 샌드박스 내부 컴퓨터 환경으로 접근하는 단 한두 개의 '코드 실행 및 파일 쓰기 API'만을 프롬프트 영역에 구속 바인딩해 둡니다. 에이전트가 복잡한 DB 스키마 탐색이나 다중 외부 연결을 완수해야 할 때, 직접 데이터 통제 처리를 수행하는 Python 스크립트를 빌드하여 샌드박스로 전송 구동시킵니다. 
<br><br>
수백만 행의 데이터 조회 덤프와 API 전송 로그는 에이전트 본체의 추론 영역 밖인 가상 머신(MicroVM)의 물리 메모리(RAM) 영역 내에 완벽하게 고립 적재되어 파이썬 Pandas 등을 통해 고속 전처리, 필터링, 정렬 처리를 완료합니다. 에이전트는 단지 가역적 압축의 지표인 "실행 성공: 이상 데이터 3건 검출되어 CSV로 파일 저장 완료" 라는 정형 요약 메타 결과만을 마스터 LLM의 디코더 입력으로 회수합니다. 이 통합 격리 가이드라인을 전개해야만 입력 토큰의 폭발적 팽창을 원천 차단하고 어텐션 집중도를 최고조로 유지하여 프로덕션 에이전트의 구동 신뢰성을 담보할 수 있게 됩니다.
</p>

<p>
Claude Code의 Skills 아키텍처는 YAML Frontmatter 메타데이터와 동적 Instruction 트리거링 메커니즘을 유기적으로 교차 설계한 고성능 컨텍스트 큐레이션 기법입니다. 
<br><br>
이 시스템의 구체적인 작동 원리와 데이터 흐름 대조는 다음과 같이 수립됩니다:
1. **평상시 세션 가동 (콘텍스트 수축 상태)**: 에이전트는 시스템 메시지 공간 상에 가용 스킬들의 이름과 역할만 간략히 적시한 YAML Frontmatter 스니펫(스킬당 불과 100~200 토큰 미만)만을 탑재한 채 극도로 가벼운 프롬프트 상태를 유지하며 사용자와의 casual 대화를 빠르게 처리합니다. 어텐션 포화가 차단되므로 지연시간(TTFT)과 비용이 상수로 제약됩니다.
2. **특화 태스크 돌입 (콘텍스트 동적 팽창 상태)**: 사용자가 "주어진 복잡한 PDF 청구서 파일 양식을 자동 파싱하여 todo.md를 수정해줘"와 같은 전문 지침이 명확히 수반되어야 하는 명령을 인입시키는 시점에 이르러서야, 모델은 Frontmatter 명세를 보고 자신이 `pdf_parser_skill`을 읽어야 한다고 스스로 판단합니다. 이에 따라 자율적으로 격리 쉘에 `cat /mnt/skills/pdf/SKILL.md` 도구 명령을 송출하여 해당 파일 내부의 무거운 원본 Instruction 지침 전문을 그제서야 동적으로 인-컨텍스트에 로드(In-Context Injection)시킵니다.
3. **작업 완료 후 환원 (콘텍스트 수축 상태)**: 해당 작업이 완수되는 즉시, 런타임 상태 제어기는 로드되었던 Skills 이력 텍스트를 메시지 어레이 버퍼 상에서 즉시 제거 소멸(Eviction Pruning)시켜 다시 이전의 저부하 초경량 컨텍스트 슬라이딩 윈도우 규격으로 수축 환원시킵니다.
<br><br>
이 설계 사상은 조급하게 가중치 파라미터를 고정하는 파인튜닝(Fine-Tuning) 기조 대비 다음과 같은 압독적인 실무적 우위를 완수합니다:
- **민첩한 혁신 속도 (Fast Agility)**: 외부 API 스펙이 바뀌거나 새로운 개발 규정이 변경될 때, 막대한 시간과 하드웨어 훈련 비용이 소모되는 미세조정 학습 세션을 거칠 필요 없이 단지 로컬 디바이스 상의 `SKILL.md`나 `CLAUDE.md` 파일 내부의 텍스트 규정 가이드를 편집 수정하는 즉시 모든 에이전트의 지능과 툴 구동 방향을 실시간 동기화하여 진화adapt 시킬 수 있습니다.
- **가중치 고정 위협 차단**: 파인튜닝을 과도하게 적용할 경우 모델의 범용 추론 지능이 상실되거나 특정 도구 매커니즘에 고착화(Overfitting)되어 유연성을 영구 상실하는 장애를 초래하는데, Skills 프롬프트 큐레이션은 본체의 범용 지능을 온전히 수호한 채 런타임 지식 확장성만을 극한으로 조율하는 최선의 엔지니어링 타협점이기 때문입니다.

### 💡 3번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
Manus AI가 장기 구동 과정에서 봉착하는 가혹한 하드웨어 한계는 트랜스포머 아키텍처의 셀프 어텐션 복잡도가 유발하는 연산 비용의 $O(T^2)$ 비선형 급상승 병목입니다. 기존의 단순 RAG 시스템이나 에이전트 설계는 수만 줄에 달하는 웹 크롤링 원시 HTML DOM 소스코드, 대규모 엑셀 파일의 행 데이터 전체를 thought-action 로그 하단에 아무런 필터링 장치 없이 순차적으로 계속 연접 적재(Append to History)하는 설계적 패착을 보였습니다. 이는 어텐션 입력 시퀀스 길이 $T$를 무제한 팽창시켜 어텐션 가중치 점수가 한가운데 박힌 진짜 정답 구문을 읽지 못하고 유실하는 'Lost in the Middle' 장애를 필연적으로 유발합니다.
<br><br>
Manus AI는 이를 파일 시스템 기반의 **'컨텍스트 오프로딩(Context Off-loading)'** 엔지니어링 패러다임을 통해 다음과 같은 연산 정사 구조로 완벽히 제어 분리합니다:
1. ** todo.md의 계획 및 오프셋 동기화**: 장기 구동을 위한 거시 마일스톤 계획과 현재 진행률 변수 상태를 어텐션 컨텍스트 히스토리 어레이에 매번 기록하지 않고, 디렉토리 디스크 상의 `todo.md` 물리 파일에만 실시간 Write 갱신 보존합니다. LLM 추론 영역에는 오직 당면한 미시 태스크 한 단계 정보만 주입되어 메모리 오버헤드를 동결 억제합니다.
2. **원시 정보의 디스크 영속 격리**: 외부 브라우징 작업이나 수만 행의 데이터 수집 시점에 도출되는 대용량 로우 텍스트 덩어리를 마스터 LLM의 VRAM 기반 콘텍스트 버퍼에 단 1바이트도 밀어 넣지 않고, `raw_scraped.txt` 등 독립된 물리 파일로 샌드박스 가상 디바이스 상에 완전 오프로딩하여 박제 보관합니다.
3. **초경량 메타 텐서 주입**: 마스터 LLM의 추론 입력 전단에는 "수집 성공: 5만 자의 DOM 소스가 raw_scraped.txt에 성공적으로 격리 오프로딩 보존되었습니다" 라는 단 수십 토큰 크기의 초경량 메타 식별자(Meta Pointer)만 주입시킵니다.
<br><br>
이 기하학적 파일 기반 분리 설계를 전개할 경우, 입력 토큰 길이 $T$는 턴이 무제한적으로 반복 가동되더라도 기하급수적 팽창 곡선을 완벽히 패스하고 일정한 정상 상수 임계선($\tilde{T} \ll T$) 이하로 타이트하게 동결 구속됩니다. 어텐션 스코어의 연산 부하가 완벽히 통제되며, 가용 VRAM 자원을 오직 당면 JSON Schema 매개변수의 인자 추출 및 자율 계획 수정 연산에만 100% 집중시킬 수 있게 되므로 장기 실행 에이전트의 오작동율을 완전히 무너뜨리는 압도적 정량 가치를 달성하게 되는 것입니다.
</p>
</details>
