# [DeepResearch 아키텍처 알아보기]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 딥리서치(Deep Research)의 정의와 패러다임 전환
- **단발성 검색(Single-turn Retrieval)의 한계**: 기존의 RAG 챗봇이나 단순 검색 에이전트는 사용자가 던진 단일 쿼리에 의존하여 1차 검색 결과만을 요약 제시합니다. 이 방식은 복잡하고 모호하거나 다각도의 비교 분석이 필요한 정보 탐색(예: 특정 시장의 향후 5년 추이 및 위협 분석)에 직면할 때 정보의 깊이가 부족하고 편향된 답변을 도출하는 한계를 보입니다.
- **계획 수립 기반 심층 자율 조사**: 딥리서치는 사용자가 입력한 광범위하고 추상적인 목표 과업을 수신하면, 곧바로 검색을 실행하지 않고 전체 조사 프로세스를 지탱할 "구조적 리서치 계획(Research Plan)"을 자율적으로 기획합니다. 이를 해결 가능한 하위 작업들로 세분 분해하고 단계적 탐색 루프를 가동하는 현대적 자율 탐색 에이전트 기술의 정수입니다.

### 1.2 글로벌 빅테크의 딥리서치 아키텍처 격차 분석: OpenAI o3 vs Anthropic MARS
딥리서치 패러다임을 이끄는 두 양대 산맥은 "단일 추론 모델 내재화"와 "멀티 에이전트 오케스트레이션"이라는 서로 완전히 상반된 구조적 엔지니어링 철학을 기반으로 구현되어 있습니다.

- **OpenAI o3 기반 End-to-End 단일 추론 기조**:
  - **설계 본질**: OpenAI는 o3 등의 고성능 추론 모델(Reasoning Model)이 직접 딥리서치의 모든 라이프사이클(기획, 검색 쿼리 발급, 코드 실행을 통한 데이터 분석, 유효성 검증, 최종 요약)을 별도의 복잡한 상위 제어 프레임워크 없이 스스로 수행할 수 있도록 엔드투엔드(End-to-End) 강화학습(RL) 파인튜닝을 적용했습니다.
  - **구현 특징**: 모델 자체가 내부 "생각의 사슬(Chain of Thought)" 상에서 스스로 도구 호출과 실시간 피드백 성찰을 반복 제어하기 때문에, 복잡한 프레임워크 보일러플레이트 코드 없이 강력하고 일관된 지능형 조사를 보장합니다.
- **Anthropic MARS (Multi-Agent Research System) 기반 협동 기조**:
  - **설계 본질**: Anthropic은 단일 모델의 어텐션 포화 한계를 돌파하기 위해 "역할이 분리된 다중 에이전트 분업체계"에 초점을 맞췄습니다. 총괄 오케스트레이터 역할을 하는 Lead Agent가 여러 하위 Search Sub-agent들과 Citation Sub-agent를 동적으로 스레드화하여 병렬 협업을 전개합니다.
  - **구현 특징**: 하위 작업들이 각각 고유의 독립 컨텍스트 창(Sub-context) 내에서 격리 가동되므로, 대규모 정보 수확 시 메인 모델의 Context Window 부하를 획기적으로 줄이며 분산 연산을 달성합니다.

### 1.3 재귀적 트리 탐색(Recursive Tree Exploration) 및 동적 하위 질의 분류
- **동적 하위 질의 분류 (Sub-Query Decomposition)**: 복잡한 주제가 인입되면, 기획 레이어에서 이를 의미적 직교성이 보장되는 다수의 하위 질문 세트들로 세부 분해합니다.
- **재귀적 심층 탐색 (Recursive Exploration)**: 1차 검색 결과를 얻으면 결과를 자체 성찰(Self-Reflection)하여 정보의 해상도와 사실 무결성이 검증될 때까지 하위 질문들을 런타임 상에 재귀적으로 재생성 및 확장합니다. 이는 데이터 트리 전이(Data Tree Transition) 관점에서 깊이 우선 탐색(DFS) 및 분기 한정(Branch and Bound) 기법을 의미론적 로짓 공간 상에서 전개하는 것과 기하학적으로 완벽히 일치합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 딥리서치 에이전트의 종단간(End-to-End) 데이터 흐름 및 상태 전이도
아래 아키텍처 흐름도는 사용자 과업 수신 단계부터 하위 질의 분해, 재귀적 지식 그래프 수집, Reranking 필터링, 최종 고해상도 리포트 요약 및 출처 매핑으로 수렴되는 종단간 데이터 흐름을 묘사합니다.

```
[사용자 거시적 리서치 과업 인입]
       │
       ▼ [1단계: Task Planning & Decomposition]
[동적 하위 질의 생성 및 계획서 작성] ──► 하위 질문 트리(Sub-Query Tree) 구성
       │
       ├─────────────────────────────────────────┐
       ▼ [2단계: 병렬 재귀 검색 (Recursive Search)]  ▼ [3단계: Context Off-loading]
[이종 검색 엔진 및 API 동시 타격]             [가상 디스크 파일 오프로딩]
  - EXA/Google 웹 검색 쿼리 송출             - 대용량 원시 HTML/덤프파일 격리 저장
  - 1차 수집 지식 피드백 분석                 - LLM 어텐션 포화 및 VRAM 과부하 방지
       │                                         │
       ▼ [자가 성찰 & 깊이 검증 (Self-Reflection)]  │
[정보 해상도가 만족스러운가?]                      │
  - NO ──► 하위 쿼리 동적 추가 및 재귀 회귀      │
  - YES ─┐                                       │
         ▼                                       │
       ├─────────────────────────────────────────┘
       ▼ [4단계: Post-Retrieval Reranking & Curation]
[중간 수집 지식 조각 재정렬 및 교차 매칭] ──► 무의미한 중복 및 노이즈 토큰 영구 이탈 (Eviction)
       │
       ▼ [5단계: 최종 무결 종합 (Synthesis)]
[출처 및 인덱스(Citations) 정밀 바인딩]
       │
       ▼
[고해상도 심층 보고서 배포 및 최종 반환]
```

### 2.2 어텐션 포화 방지를 위한 Curation 기법의 연산 최적화 정량 분석
수백 개의 웹 페이지와 기사들을 재귀적으로 수집하는 과정에서 원시 텍스트 전체를 무제한으로 LLM 프롬프트 버퍼에 직접 누적 적재하게 되면, 치명적인 어텐션 맵 포화(Attention Saturation) 및 컨텍스트 부패(Context Rot) 병목 현상이 발생합니다.

- **VRAM VRAM 연산 기하급수 팽창 곡선**:
  트랜스포머의 어텐션 맵 연산 공간 복잡도는 입력 토큰 길이 $T$에 대해 $O(T^2)$를 따릅니다. 딥리서치 가동 중 누적 수집된 원시 정보가 30k 토큰에서 150k 토큰으로 5배 증가할 때, GPU VRAM 내 계산 부하는 **25배**로 기하급수적 수직 상승하며 레이턴시를 무한히 늘리고 모델의 시스템 지침(System Instructions) 준수율을 급감시킵니다.
- **Reranker와 Token Eviction을 활용한 연산 최적화**:
  - **임베딩 유사도 1차 필터링**: 수집된 수만 개의 청크들을 Reranker(예: Cohere Rerank, BGE-Reranker) 레이어에 인입시켜, 사용자 질문 벡터와의 의미론적 거리가 설정한 임계치(Threshold, 예: 0.65) 이하인 청크들을 1차적으로 완전 기각 처분합니다.
  - **동적 토큰 이탈(Token Eviction)**: 가용 컨텍스트 윈도우 한계 도달 이전에 오래되거나 관련도가 떨어지는 과거 웹 브라우징 DOM 조각들을 슬라이딩 윈도우 방식으로 프롬프트 버퍼에서 영구 소멸시키고, 요약 정제된 핵심 피드백 스키마 텐서 $\tilde{T}$만 남겨 어텐션 복잡도를 항상 정상 작동 하한 범위 내로 엄격히 제한합니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반 딥리서치(Deep Research) 자율 오케스트레이터 시뮬레이터 스크립트
다음 소스코드는 OpenAI o3 및 Gemini Deep Research API 설계 철학을 반영하여, **하위 질의 동적 분해, 병렬 웹 검색, 획득 지식 조각에 대한 정합성 평가, 최종 종합 보고서 합성** 파이프라인 전체를 프로덕션 레벨에서 견고하게 작동하도록 설계한 파이썬 스크립트입니다.

```python
import os
import json
import asyncio
from typing import Dict, Any, List, Literal
from typing_extensions import TypedDict
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END

# 1. 딥리서치 상태 스키마 정의 (관심사 완벽 격리 구조)
class DeepResearchState(TypedDict):
    task: str                         # 사용자 거시 과업 (예: "2026 AI 에이전트 메모리 아키텍처 동향")
    sub_queries: List[str]            # 분해된 하위 질의 목록
    collected_knowledges: List[str]   # 수집된 중간 지식 조각들
    final_report: str                 # 최종 요약 보고서
    current_depth: int                # 재귀 조사 현재 깊이
    max_depth: int                    # 조사 최대 수용 깊이 (무한 루프 방지용 컷오프)

# 2. 기저 추론 모델 및 API 인스턴스 초기화
# 온도를 0으로 완전히 고정하여 결정론적 의사결정 경로 보장
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

def decompose_task(state: DeepResearchState) -> Dict[str, Any]:
    """1단계: 거시 과업을 3개의 직교하는 하위 질의로 세분 분해"""
    print("\n[SYSTEM::INFO] 1단계: 거시 과업 분할 및 계획 수립 개시")
    task = state["task"]
    
    prompt = f"""당신은 심층 리서치 에이전트의 기획 총괄 레이어입니다.
주어진 대주제에 대해 정보 누락과 의미론적 중복 없이 심층 탐색을 완수할 수 있도록,
서로 다른 관점을 가진 구체적이고 세분화된 하위 검색 쿼리 3개를 작성하여 JSON 리스트 형태로 반환하세요.

대주제: {task}
형식 예시: ["하위주제1", "하위주제2", "하위주제3"]"""

    response = llm.invoke([HumanMessage(content=prompt)])
    try:
        # 안전한 JSON 파싱 가드가 작동하며 문자열을 파이썬 리스트로 전환
        queries = json.loads(response.content)
    except Exception:
        # 파싱 오류 발생 시 휴리스틱 폴백 가이드라인 가동
        queries = [f"{task} 기술 동향", f"{task} 리스크 분석", f"{task} 실제 산업 적용 사례"]
        
    return {"sub_queries": queries, "collected_knowledges": [], "current_depth": 1}

def execute_recursive_search(state: DeepResearchState) -> Dict[str, Any]:
    """2단계: 분해된 하위 질의별로 개별적인 리서치를 모사 전개하여 데이터 축적"""
    depth = state["current_depth"]
    queries = state["sub_queries"]
    print(f"\n[SYSTEM::INFO] 2단계: 재귀 웹 검색 가동 (현재 조사 깊이: {depth} / {state['max_depth']})")
    
    new_knowledges = []
    for query in queries:
        # 실제 EXA 또는 Google 검색 API가 탑재되는 물리적 통합 영역
        # 여기서는 정확한 모사를 위해 고밀도 팩트 지식을 가상으로 소환하여 인입
        print(f"  - 검색 쿼리 송출 중: '{query}'")
        if "동향" in query or "아키텍처" in query:
            knowledge = f"[깊이 {depth} - 동향] Titans LMM(Neural Long-term Memory) 아키텍처는 컨텍스트 윈도우 한계를 2M 토큰 이상으로 크게 갱신하여 망각 없는 장기 기억의 지평을 열었다."
        elif "리스크" in query or "한계" in query:
            knowledge = f"[깊이 {depth} - 리스크] 무제한적인 툴 덤프 데이터의 직접 연접은 어텐션 소프트맥스 분모를 팽창시켜 툴 매개변수 바인딩 환각을 수반하는 Context Rot을 발생시킨다."
        else:
            knowledge = f"[깊이 {depth} - 적용] OpenAI o3 deep-research 및 Claude MARS 협동 모델은 사내 R&D Reranking 자동화와 분산 연산 오프로딩 가동 인프라로 전격 도입 완료되었다."
        new_knowledges.append(knowledge)
        
    # 기존 수집된 자료들과 현재 깊이에서 수확한 정보 조각들을 병합
    accumulated = state["collected_knowledges"] + new_knowledges
    return {"collected_knowledges": accumulated, "current_depth": depth + 1}

def evaluate_reflection(state: DeepResearchState) -> Literal["search_again", "synthesize"]:
    """3단계: 조건부 라우팅 검증선. 정보의 해상도가 성찰 임계치를 통과했는지 혹은 한계 깊이에 봉착했는지 판단"""
    current_depth = state["current_depth"]
    max_depth = state["max_depth"]
    
    if current_depth > max_depth:
        print("\n[SYSTEM::INFO] 조사 한계 깊이(Max Depth) 도달로 인한 검색 오프셋 종료 판단")
        return "synthesize"
        
    print("\n[SYSTEM::INFO] 수집 지식에 대한 자가 성찰(Self-Reflection) 전개")
    # 수집 자료가 충분히 신뢰할 만한지 LLM을 Judge로 세워 이진 판별 수행 가능
    # 여기서는 정형 조건 통제를 위해 깊이가 max_depth에 도달할 때까지 재귀 회귀를 유도
    return "search_again"

def synthesize_report(state: DeepResearchState) -> Dict[str, Any]:
    """4단계: 수집 완료된 장기 기억 지식 조각들을 최종 가공 및 일관성 있게 병합 요약"""
    print("\n[SYSTEM::INFO] 4단계: 출처 인덱싱 및 고해상도 최종 종합 보고서 합성 개시")
    task = state["task"]
    knowledges = "\n".join(state["collected_knowledges"])
    
    prompt = f"""당신은 기업 리서치 총괄 편집장입니다.
아래 재귀적 탐색을 통해 획득한 원시 지식 조각 전체를 분석하여,
중복을 제거하고 명확한 논리 구조를 지닌 최종 금융/기술 보고서를 한국어로 완성하세요.

주제: {task}

=== 수집된 지식 조각들 ===
{knowledges}
==========================

최종 보고서 (#개요 / #핵심 아키텍처 분석 / #시스템적 기여도 / #향후 Outlook):"""

    response = llm.invoke([HumanMessage(content=prompt)])
    return {"final_report": response.content}

# 3.2 상태 그래프(StateGraph) 조립 및 최적의 컴파일 가동
workflow = StateGraph(DeepResearchState)

workflow.add_node("decompose_task", decompose_task)
workflow.add_node("execute_search", execute_recursive_search)
workflow.add_node("synthesize_report", synthesize_report)

workflow.add_edge(START, "decompose_task")
workflow.add_edge("decompose_task", "execute_search")

workflow.add_conditional_edges(
    "execute_search",
    evaluate_reflection,
    {
        "search_again": "execute_search", # 자가 성찰 필터 실패 시 웹 검색 재귀 루프로 회귀
        "synthesize": "synthesize_report"  # 신뢰성 임계치 무결 도달 시 최종 종합으로 분기 전치
    }
)
```

<p>
재귀적 웹 검색 및 딥리서치 가동 환경은 네트워크 레이턴시와 비결정론적 외부 대상 서버의 상태 변이로 인해 상시 붕괴 위협에 노출되어 있습니다. 이를 완벽하게 극복하기 위한 영속 견고성(Durable Execution) 수호 아키텍처는 다음과 같습니다:
<br><br>
1. <b>상태 영속화 및 WAL (Write-Ahead Logging) 아키텍처</b>:<
에이전트가 매 루프 단계(Task Decomposition -> Search Action -> Observation)로 진입하여 메모리 변이(State Mutation)를 일으키기 직전, 현재까지 누적된 대화 상태 데이터셋(GraphState)을 직렬화(Serialization)하여 디바이스 디스크 장치의 WAL 로그에 동기식 쓰기(Synchronous Write)를 물리 강제합니다. 만약 네트워크 통신 단절이나 외부 도구 실행 중 발생한 언핸들드 익셉션(Unhandled Exception), 혹은 호스트 컨테이너의 갑작스러운 셧다운(Crash)으로 세션이 파괴되더라도, 시스템 복원 엔진은 메모리 재할당 이전에 WAL의 최종 커밋 로그를 판독하여 장애 발생 전 마지막 정상 분기 오프셋 지점부터 파이프라인 전체를 지연 없이 안정적으로 인양 복구해 냅니다.
<br><br>
2. <b>429 Rate Limit 방어 및 데드락 해소 가드레일</b>:<
- <b>지수 백오프 및 지터(Jitter)가 수반된 재시도 미들웨어</b>: 외부 API 타격 시 429 에러가 반환되면 즉시 스레드를 대기시키고, $t = \text{base\_delay} \times 2^{\text{retry}} + \text{random\_jitter}$ 공식에 기반한 점진적 지연 재시도를 실행하여 병목 트래픽을 분산시킵니다.
- <b>수명 제어 루프 상한 (Loop Cut-off Guardrail)</b>: 무한 루프 데드락으로 인한 금전적 폭사를 방지하기 위해 State 스키마 내에 `iteration_count`를 강제 마운트하고, 조건부 라우터 초입에서 이 카운터가 임계 상한선(예: 5회)을 초과하는 즉시 현재까지의 수집 정보만을 취합하여 즉각 강제 종결(Force-Accept) 노드로 라우팅 전치하도록 설계 구조를 구속 수호합니다.
