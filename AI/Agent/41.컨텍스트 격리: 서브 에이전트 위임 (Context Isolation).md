# [컨텍스트 격리: 서브 에이전트 위임 (Context Isolation)]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 에이전트 컨텍스트의 성장 한계와 3대 병목 현상
AI 에이전트가 복잡하거나 장기적으로 실행되는 과업을 수행할 때, 모든 생각 과정과 도구 실행 결과(Observation)를 단일 전역 컨텍스트 버퍼(VRAM)에 계속 누적 적재하는 방식은 세션 후반부로 갈수록 심각한 인프라 및 추론 결함을 야기합니다.
*   **컨텍스트 충돌 (Context Clash)**: 서로 다른 성격의 다단계 하위 목표(예: 자료 조사와 포맷 유효성 검증)가 동일한 컨텍스트 버퍼 내에 어지럽게 뒤섞여 상호 간의 지시 사항이 충돌하고 모델의 정렬(Alignment) 성능이 붕괴되는 현상입니다.
*   **컨텍스트 오염 (Context Poisoning)**: 이전 턴에서 도구를 가동하다가 발생한 상세 스택 트레이스 오류나 쓸모없는 원시 HTML 코드 블록 등이 메모리에 잔존하여, 현재 실행하려는 특정 논리 흐름 및 도구 호출 인자 할당에 심각한 환각(Hallucination) 오염을 전파하는 문제입니다.
*   **컨텍스트 희석 (Context Dilution)**: 중요 규칙 토큰과 필수 가이드라인이 비대해진 데이터 홍수 속에서 소프트맥스 가중치를 잃고 정량적으로 희석되는 현상입니다. 기저 LLM의 'Lost in the Middle' 현상과 맞물려, 시스템 제어권 상실 및 툴 오적용 장애를 직결합니다.

### 1.2 컨텍스트 격리 (Context Isolation) 패러다임과 서브 에이전트 위임
이러한 단일 버퍼의 과부하 한계를 극복하기 위해, 전체 시스템의 관심사를 완벽히 수직 분할하는 **컨텍스트 격리(Context Isolation)** 기법이 부상하였습니다.
*   **작무 영역별 캡슐화**: 전체 프로젝트를 하나의 모델이 홀로 감당하는 대신, 고도로 전문화된 시스템 프롬프트와 극도로 제한된 원자적 도구 세트만을 지닌 독립된 **하위 에이전트(Sub-Agent)**를 동적으로 생성하여 특정 임무를 위임합니다.
*   **메모리 영역의 차단**: 하위 에이전트는 기동되는 순간 부모 에이전트의 구구절절한 누적 대화 기록(히스토리에 따른 컨텍스트 부패 요인)을 일체 인계받지 않고, 오직 자신에게 할당된 작업 지시문(Task Description) 단 한 줄만을 최초 입력(`messages`)으로 삼아 격격히 차단된 독자적 샌드박스 추론 버퍼 내에서만 구동됩니다.
*   **고밀도 메타 데이터 회수**: 수만 토큰에 육박하는 하부 조사 원시 결과는 서브 에이전트 레벨에서 완전히 캡슐화 처리(및 로컬 파일 시스템 오프로딩)하고, 오직 최종 요약 정제된 1,000~2,000 토큰 미만의 정량 핵심 응답 텐서(Result Content)만을 부모(Supervisor)에게 반환하여 메인 콘텍스트를 상시 청정 상태로 보존합니다.

### 1.3 하위 에이전트의 이중 추상화 모델링 (Sub-Agent Schema)
서브 에이전트는 오케스트레이션 네트워크 내에서 두 가지 물리적 역할을 동시에 수용하도록 정밀 구조화되어 설계됩니다.
1.  **도구(Tool)로서의 역할**: 메인 감독자(Supervisor) 에이전트에게 자신의 정체성과 전문 영역 및 동적 바인딩 방법을 설명하는 메타 데이터 명세 역할을 수행합니다. (`name`, `description`)
2.  **에이전트(Agent)로서의 역할**: 작업을 넘겨받은 즉시 독립된 그래프 세션을 실행하고 하부 도구를 조작해 가며 주어진 목표를 끝까지 완수하는 자율 실행기 역할을 영위합니다. (`prompt`, `tools`)

### 2.2 컨텍스트 고립 및 병렬 수집의 계산 최적화 이점
*   **병렬 탐색 (Parallel Swarm Execution)**: 단일 스레드로 동작하는 에이전트는 비교 조사를 수행하기 위해 동기식 순차 루프를 돌며 극심한 시간 지연을 초래합니다. 컨텍스트 격리 하부 위임 방식을 적용하면 `asyncio.gather`를 통해 다수의 독립 연구원을 동시 물리 가동하므로 지연 시간(Latency)을 거의 상수의 영역($O(1)$)으로 압축할 수 있습니다.
*   **VRAM 연산량의 하향 제어**: 에이전트의 디코딩 계산 복잡도는 시퀀스 길이의 제곱($O(T^2)$)에 수렴하므로, 50번의 도구 조작 결과를 단일 전역 상태에 우겨넣으면 VRAM 자원이 포화되어 시스템 장애가 확정적으로 발생합니다. 컨텍스트 격리 모델은 하부 노드에서 VRAM 제곱 연산 버하를 분산 소비시키고 메인 버퍼에는 메타 결과만 가볍게 합류시키므로 고가의 GPU 인프라 부하를 물리적으로 영구 경감시킵니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반의 컨텍스트 격리 서브 에이전트 구현 마스터 스크립트
다음 소스코드는 부모 에이전트와 자식 에이전트 간의 컨텍스트 격리를 완벽하게 실현하고, `Command(update=...)` 기제를 결합하여 가상 가동되는 파이썬 실전 아키텍처 스키마입니다.

```python
import os
import operator
from typing import Annotated, Literal, TypedDict
from typing_extensions import NotRequired
from langchain_core.messages import ToolMessage, HumanMessage
from langchain_core.tools import tool, InjectedToolCallId
from langgraph.prebuilt import InjectedState
from langgraph.types import Command
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, START, END

# 1. 파일 상태 관리를 위한 리듀서(Reducer) 정의
def file_reducer(left, right):
    if left is None:
        return right or {}
    if right is None:
        return left
    return {**left, **right}

class Todo(TypedDict):
    content: str
    status: Literal["pending", "in_progress", "completed"]

# 2. 전역 메모리 정합 스키마 선언
class DeepAgentState(TypedDict):
    messages: Annotated[list, operator.add]
    todos: NotRequired[list[Todo]]
    files: Annotated[NotRequired[dict[str, str]], file_reducer]

# 3. 로컬 파일 조작 도구 세트 설계 (가상 파일 시스템 마운트)
@tool
def ls(state: Annotated[DeepAgentState, InjectedState]) -> list[str]:
    """가상 파일 시스템의 모든 파일 리스트를 배열로 나열합니다."""
    files = state.get("files", {})
    return list(files.keys()) if files else ["(물리 디렉토리가 비어 있습니다)"]

@tool
def read_file(file_path: str, state: Annotated[DeepAgentState, InjectedState]) -> str:
    """파일 경로를 전달받아 파일의 상세 텍스트 전체 내용을 완벽히 읽어옵니다."""
    files = state.get("files", {})
    if file_path not in files:
        return f"오류: 대상 파일 '{file_path}'이 존재하지 않습니다."
    return files[file_path]

@tool
def write_file(
    file_path: str,
    content: str,
    tool_call_id: Annotated[str, InjectedToolCallId]
) -> Command:
    """지정된 가상 파일 경로에 텍스트 데이터를 무결 기재하여 영속화합니다."""
    return Command(
        update={
            "files": {file_path: content},
            "messages": [
                ToolMessage(content=f"성공: 가상 디스크 내 '{file_path}' 쓰기 완료.", tool_call_id=tool_call_id)
            ]
        }
    )

# 4. 서브 에이전트용 특화 EXA 모사 검색 도구 설계 (컨텍스트 오프로딩 기조 탑재)
@tool
def web_search(query: str, tool_call_id: Annotated[str, InjectedToolCallId]) -> Command:
    """의미 기반 신경망 웹 검색을 가동하고, 상세 결과는 파일로 이관 격리한 뒤 요약만 콘텍스트로 회수합니다."""
    # 모사 검색 데이터 풀링
    search_database = {
        "langchain": "LangChain은 LLM 통합 파이프라인 프레임워크로, 프롬프트 템플릿, 메모리, 체인 및 다양한 타사 인터페이스 결합을 규격화합니다.",
        "agno sdk": "Agno SDK는 구 Phidata의 신형 프레임워크로, 완전 비동기 구조 및 경량성, 도구 중심의 직관적 에이전트 설계를 지향합니다."
    }
    
    matched_data = "상세 지식 탐색 실패: 최신 인덱스에서 관련 파편을 획득하지 못했습니다."
    for key, val in search_database.items():
        if key in query.lower():
            matched_data = val
            break
            
    filename = f"search_results_{query.lower().replace(' ', '_')}.md"
    
    # 상세 데이터는 파일 시스템으로 오프로딩 처리하고, 모델 컨텍스트 버퍼에는 힌트 요약 정보만 복구 송출
    file_content = f"# {query} 리서치 원시 로그\n{matched_data}"
    summary = f"🔍 [검색 완료]: \"{query}\" 결과를 '{filename}' 디스크 파일로 오프로딩 저장함. 필요 시 read_file 도구를 기동하세요."
    
    return Command(
        update={
            "files": {filename: file_content},
            "messages": [
                ToolMessage(content=summary, tool_call_id=tool_call_id)
            ]
        }
    )

# 5. 격리형 서브 에이전트 정의 및 동적 task 바인딩 팩토리 구현
class SubAgentConfig(TypedDict):
    name: str
    description: str
    prompt: str
    tools: list[str]

# 리서치 서브 에이전트 행동 지침 가이드라인 선언
RESEARCHER_PROMPT = """당신은 고도로 격리된 연구원 에이전트입니다.
반드시 web_search 도구를 단 1회만 정확히 호출하고 그 실행 결과에 근거하여 핵심 지식을 완전 축약 요약 보고하세요.
컨텍스트가 길어지는 것을 극도로 기피하므로 불필요한 부가 미사여구를 완벽히 삭제하십시오."""

def create_task_tool(all_tools: list, subagents: list[SubAgentConfig], model) -> tool:
    """부모의 전체 누적 대화 기록을 완벽 격리 수렴 전치하는 task 위임 도구를 빌드합니다."""
    agents = {}
    tools_by_name = {t.name: t for t in all_tools}
    
    # 레지스트리 기반 하위 에이전트 그래프 자율 조립 및 메모리 격리 수립
    for sa in subagents:
        _tools = [tools_by_name[tname] for t in sa["tools"] if (tname := t) in tools_by_name]
        agents[sa["name"]] = create_agent(
            model=model,
            tools=_tools,
            system_prompt=sa["prompt"],
            state_schema=DeepAgentState
        )
        
    other_agents_desc = "\n".join([f"- **{sa['name']}**: {sa['description']}" for sa in subagents])
    task_desc = f"""특화된 하위 서브 에이전트에게 고난도 개별 연구 과업을 완전히 위임 전치합니다.
    하위 에이전트는 부모의 대화 기록을 일체 상속받지 않는 극도의 격리 세션에서 동작하므로 지시문(description)은 모호하지 않고 자립적으로 충족되어야 합니다.
    
    ## 가용 연구원 목록:
    {other_agents_desc}
    """
    
    @tool(description=task_desc)
    def task(
        description: str,
        subagent_type: str,
        state: Annotated[DeepAgentState, InjectedState],
        tool_call_id: Annotated[str, InjectedToolCallId]
    ) -> Command:
        if subagent_type not in agents:
            return f"에러: 대상 에이전트 '{subagent_type}'가 가용 목록에 존재하지 않습니다."
            
        target_agent = agents[subagent_type]
        
        # 🔑 [컨텍스트 격리의 핵심 오프셋]: 부모의 messages 히스토리 전체를 절단하고, 오직 task description만 병입
        isolated_state = dict(state)
        isolated_state["messages"] = [HumanMessage(content=description)]
        
        # 격리 런타임 가동 및 지식 수확
        result = target_agent.invoke(isolated_state)
        sub_response = result["messages"][-1].content
        
        # 수확된 가상 파일 상태 변이 데이터와 축약 요약문만 부모의 MessagesState 채널로 전송 머징
        return Command(
            update={
                "files": result.get("files", {}),
                "messages": [
                    ToolMessage(content=sub_response, tool_call_id=tool_call_id)
                ]
            }
        )
        
    return task

# 6. 시스템 오케스트레이터 및 메인 그래프 결합 컴파일
```

<p>
