# [컨텍스트 오프로딩: 로컬 파일 시스템]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 에이전트 장기 실행의 치명적 장벽: 컨텍스트 부패(Context Rot)와 비용 폭증
대규모 언어 모델(LLM) 기반의 완전 자율형 에이전트가 복잡한 다단계 의사결정을 수십 턴 이상 수행할 때, 시스템이 직면하는 가장 치명적인 인프라적 병목은 **컨텍스트 부패(Context Rot)**와 **VRAM 계산량 및 API 호출 비용의 기하급수적 폭증**입니다.
*   **어텐션 맵의 정량적 희석**: 웹 페이지 전체 크롤링 결과, 데이터베이스 테이블 전체 덤프, 길고 정형화되지 않은 외부 API 원시 로그(Raw JSON 등)를 에이전트의 단기 기억 컨텍스트에 그대로 누적하여 연쇄 적재하면, 유효 컨텍스트가 임계점 이상으로 팽창합니다. 이로 인해 트랜스포머 레이어 내부의 어텐션 스코어 분모가 무한히 커져 정작 에이전트의 원천 수명 주기 규칙, 최종 목표 상태, 도구 입출력 정합성 제어 토큰들의 어텐션 할당 밀도가 $0$에 수렴하게 됩니다.
*   **비용의 비선형적 폭발**: 트랜스포머 모델의 셀프 어텐션 연산 강도는 입력 시퀀스 길이 $T$에 대해 제곱 비례($O(T^2)$)의 시간 및 메모리 복잡도를 지닙니다. 매 턴마다 수만 토큰에 이르는 이전 실행 이력과 원시 관찰 데이터를 컨텍스트 윈도우에 그대로 포함하여 LLM을 호출하는 것은 심각한 가동 지연(Latency)과 감당하기 힘든 토큰 비용을 청구합니다.
*   **솔루션으로서의 컨텍스트 오프로딩(Context Offloading)**: 이 한계를 타개하기 위해, 에이전트가 수집한 방대한 원시 지식과 중간 가공 데이터 전체를 프롬프트 버퍼에 직접 바인딩하지 않고, **외부의 격리된 로컬 파일 시스템이나 보조 저장소로 물리적으로 이탈(Offloading)**시키는 메커니즘이 고안되었습니다. 에이전트는 단기 컨텍스트 상에는 지식이 저장된 파일 경로와 극도로 압축된 메타데이터 힌트만을 상주시키며, 상세 분석이나 편집이 필요한 시점에만 파일의 특정 오프셋 영역을 정밀 가독(Page-by-Page Read)하여 추론 자원을 최적화합니다.

### 1.2 저장 백엔드(Storage Backend) 유형별 비교 분석
에이전트 아키텍처를 설계할 때, 중간 상태와 오프로딩된 파일 맥락을 저장하기 위해 선택할 수 있는 영속성 백엔드는 크게 4가지 레이어로 나뉩니다.

| 백엔드 유형 | 데이터 저장 위치 | 특징 및 영속성 수준 | 최적의 사용 사례 (Use Cases) |
| :--- | :--- | :--- | :--- |
| **StateBackend** | LangGraph 인메모리 `state` 채널 | - 단일 대화 스레드 내부에서만 유효한 휘발성 격리 구조<br>- 메모리 세션 종료 시 전량 사멸 | - 가벼운 스크래치패드<br>- 임시 가상 계산 상태 기록 |
| **FilesystemBackend** | 호스트의 실제 물리 디스크 영역 | - 실제 로컬 파일 시스템 상에 파일 객체로 영구 저장<br>- 디버깅 가시성 극대화 및 파일 편집기 즉시 연동 | - 개발자 CLI 환경 구축<br>- CI/CD 자동화 파이프라인 연계 |
| **StoreBackend** | LangGraph Store 데이터베이스 | - 크로스 스레드(Cross-thread) 영구 저장 지원<br>- 다른 대화 세션 간에도 상태 영속 공유 가능 | - 에이전트의 장기 사용자 선호도(Memory)<br>- 프로젝트 글로벌 가이드라인 관리 |
| **CompositeBackend** | 경로 프리픽스별 동적 라우터 | - 파일 경로 접두사별로 위 3가지 백엔드를 동적으로 분기 라우팅 | - 로컬 소스코드 조작과 글로벌 장기 기억을 동시 조율하는 복합 시스템 |

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 로컬 파일 시스템 기반 컨텍스트 오프로딩의 종단간 데이터 흐름도
아래 아키텍처 흐름도는 사용자가 광범위한 리서치 대과업을 입력했을 때, 에이전트가 `ls` 도구로 로컬 디렉토리 트리 구조를 오리엔테이션하고, Exa Search 실행 원시 결과 전체를 파일에 은닉 격리시킨 뒤, 초경량 메타데이터 링크와 핵심 Highlights만을 프롬프트 버퍼에 회수하여 최종 보고서를 작성하기까지의 데이터 제어선과 물리 연산 이관 흐름을 명시합니다.

```
[사용자 거시적 분석 및 보고서 작성 지시 인입]
  - "LangGraph 프레임워크를 검색하고 요약 보고서를 md 파일로 저장해 줘."
       │
       ▼ [1단계: 동적 오리엔테이션 (Orient)]
[ls 도구 기동] ──► WORKSPACE_DIR 디렉토리 트리 스캔
  - 물리 디스크 파일 및 디렉토리 구조 캡처 후 가벼운 경로 리스트만 LLM에 반환
       │
       ▼ [2단계: 지식 수확 및 강제 격리 (Research & Offloading)]
[web_search 도구 호출] ──► EXA Search API 타격
  - 신경망 기반 실시간 고해상도 웹 문서 본문 및 Highlights 획득 (수만 자 크기)
  - 원시 텍스트 스트림 전체를 프롬프트 버퍼에 밀어 넣지 않고 즉시 차단
  - WORKSPACE_DIR 내에 유일 무이한 파일(`search_langgraph_2026-08-22.md`)로 기재
  - 오프라인 물리 저장소로 VRAM 부담 완벽 전치
       │
       ▼ [3단계: 인-컨텍스트 프롬프트 최소화 (Summarize & Refer)]
[경량 메타데이터 응답 반환]
  - LLM 컨텍스트 버퍼에는 오직 다음 메타 텐서만 바인딩:
    * "검색 완료 및 파일 저장됨: search_langgraph_2026-08-22.md"
    * "상위 3개 검색 결과의 초경량 핵심 제목 및 Highlights"
    * "상세 정보가 필요하다면 read_file('파일명') 도구를 호출하세요."
       │
       ▼ [4단계: 정밀 부분 가독 (Read Line-by-Line)]
[LLM 의사결정: 추가 세부 정보 필요 여부 성찰]
  - 필요한 파일 경로만 핀포인트 지정하여 read_file(file_path, offset, limit) 기동
  - 줄 번호 인덱스 매핑과 페이지네이션 필터를 통해 필요한 맥락만 프롬프트에 마운트
       │
       ▼ [5단계: 최종 물리 결과 합성 (Synthesize)]
[write_file 도구 호출]
  - 종합 가공된 완성형 마크다운 보고서를 `langgraph_summary.md` 파일로 디스크에 직접 쓰기
  - VRAM 어텐션 포화 차단 및 완벽한 사실 근거 일치율 확보
```

### 2.2 XML 태그 기반 구조화 프롬프트 제어 전략
컨텍스트 오프로딩 아키텍처가 에이전트 런타임에서 탈조 현상 없이 매끄럽게 흐르기 위해서는 모델에게 자율적 컨텍스트 조율의 당위성을 인지시키는 구조화된 프롬프트 제어가 필수적입니다.
*   **`<Workflow Process>` 태그**: 오리엔트(ls) -> 탐색(web_search) -> 정밀 가독(read_file) -> 합성(write_file)으로 이어지는 에이전트 내부 연산 세션을 기계적으로 제약하여 비결정론적 이탈을 통제합니다.
*   **`<Context Offloading Strategy>` 태그**: 수만 줄의 날것 데이터는 인프라 보호를 위해 오직 디스크 파일에만 기재하고, 추론을 이어가는 프롬프트 버퍼에는 초경량 하이라이트 요약만 상주하도록 하는 자율 메모리 이탈(Eviction) 및 슬라이딩 윈도우 규칙을 학습시킵니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반의 컨텍스트 오프로딩 에이전트 전체 파이썬 소스코드
다음은 실제 디스크 디렉토리(`WORKSPACE_DIR`)와 Exa 시맨틱 검색 기능을 완벽하게 바인딩하여 가비지 정보 누적 없이 구동되는 고성능 컨텍스트 오프로딩 단일 에이전트의 완성형 파이썬 구현체입니다.

```python
import os
import sys
import operator
from pathlib import Path
from datetime import datetime
from typing import Annotated, Literal
from typing_extensions import TypedDict
from dotenv import load_dotenv

# LangChain & LangGraph 코어 API 로드
from langchain_core.tools import tool, InjectedToolCallId
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage, ToolMessage
from langgraph.graph import StateGraph, START, END
from langgraph.prebuilt import ToolNode
from langgraph.prebuilt import InjectedState
from exa_py import Exa

# 1. 환경 설정 및 물리 격리 워크스페이스 구축
load_dotenv()
if not os.getenv("OPENAI_API_KEY"):
    os.environ["OPENAI_API_KEY"] = "your-openai-api-key"
if not os.getenv("EXA_API_KEY"):
    os.environ["EXA_API_KEY"] = "your-exa-api-key"

# 에이전트 전용 격리형 디스크 저장소 정의
WORKSPACE_DIR = Path("./agent_workspace")
WORKSPACE_DIR.mkdir(exist_ok=True)

def get_today_str() -> str:
    return datetime.now().strftime("%Y-%m-%d")

# EXA API 시맨틱 신경망 검색 클라이언트 초기화
exa_client = Exa(api_key=os.environ["EXA_API_KEY"])

# 2. 에이전트 무결 단기 상태 스키마 정의 (파일 데이터는 디스크로 이탈하므로 상태에서 배제)
class Todo(TypedDict):
    content: str
    status: Literal["pending", "in_progress", "completed"]

class AgentState(TypedDict):
    messages: Annotated[list, operator.add]
    todos: list[Todo]

# 3. 로컬 파일 시스템 조작 도구셋 (Filesystem Utilities) 구현

@tool
def ls(path: str = ".") -> str:
    """
    워크스페이스 디렉토리의 모든 파일과 폴더의 목록 및 물리 크기를 나열합니다.
    작업을 시작하기 전, 디렉토리 트리 구조를 파악하고 가용 파일을 스캔할 때 필수적으로 기동하세요.
    """
    target_dir = WORKSPACE_DIR / path
    
    # 디렉토리 트리 파싱 및 보안 검증
    if not target_dir.exists():
        return f"오류: 지정된 디렉토리 경로 '{path}'가 존재하지 않습니다."
    
    if not target_dir.is_dir():
        return f"오류: 지정된 경로 '{path}'는 디렉토리가 아닙니다."
    
    items = []
    for item in sorted(target_dir.iterdir()):
        if item.is_dir():
            items.append(f"📁 {item.name}/")
        else:
            size = item.stat().st_size
            items.append(f"📄 {item.name} ({size} bytes)")
            
    return "\n".join(items) if items else "(디렉토리가 비어 있습니다)"

@tool
def read_file(file_path: str, offset: int = 0, limit: int = 100) -> str:
    """
    워크스페이스 내부의 특정 텍스트 파일 내용을 정밀 가독합니다.
    컨텍스트 오버플로우와 VRAM 포화를 방지하기 위해, 파일 내용을 줄 번호(cat -n)와 함께 페이지네이션으로 잘라서 반환합니다.
    편집 작업을 실행하기 전 기존 파일 내용 전체를 면밀히 인지할 때 반드시 호출하십시오.
    """
    target_file = WORKSPACE_DIR / file_path
    
    # Directory Traversal 취약점 원천 예방 필터
    try:
        target_file = target_file.resolve()
        workspace_resolved = WORKSPACE_DIR.resolve()
        if not str(target_file).startswith(str(workspace_resolved)):
            return "오류 보안 위반: 지정된 경로는 보안 영역인 워크스페이스 디렉토리를 벗어날 수 없습니다."
    except Exception:
        return f"오류: 유효하지 않은 파일 경로 포맷입니다. ({file_path})"
        
    if not target_file.exists():
        return f"오류: 대상 파일 '{file_path}'을 물리적으로 찾을 수 없습니다."
        
    if not target_file.is_file():
        return f"오류: 대상 경로 '{file_path}'는 파일이 아닙니다."
        
    try:
        content = target_file.read_text(encoding="utf-8")
    except Exception as e:
        return f"오류: 인코딩 포맷 불일치로 인한 파일 읽기 실패 - {str(e)}"
        
    if not content:
        return "참고: 대상 파일이 존재하나 내부 텍스트 콘텐츠가 비어 있습니다."
        
    lines = content.splitlines()
    start_idx = max(0, offset)
    end_idx = min(start_idx + limit, len(lines))
    
    if start_idx >= len(lines):
        return f"오류: 요청한 offset 줄 번호 {offset}이 파일의 총 라인 수({len(lines)}줄)를 초과했습니다."
        
    formatted_lines = []
    for i in range(start_idx, end_idx):
        formatted_lines.append(f"{i + 1:6d}\t{lines[i]}")
        
    return "\n".join(formatted_lines)

@tool
def write_file(file_path: str, content: str) -> str:
    """
    워크스페이스 내에 지정된 경로로 파일을 영구 생성하거나 덮어씁니다.
    최종 요약 보고서 합성, 대규모 데이터 가공 산출물 작성 시 디스크에 실제 기재하기 위해 사용하세요.
    주의: 이 도구는 파일 전체 내용을 완전히 새것으로 교체(Overwrite)합니다.
    """
    target_file = WORKSPACE_DIR / file_path
    
    try:
        target_file.parent.mkdir(parents=True, exist_ok=True)
        target_file = target_file.resolve()
        workspace_resolved = WORKSPACE_DIR.resolve()
        if not str(target_file).startswith(str(workspace_resolved)):
            return "오류 보안 위반: 지정된 경로는 보안 영역인 워크스페이스 디렉토리를 벗어날 수 없습니다."
    except Exception as e:
        return f"오류: 경로 분석 실패 - {str(e)}"
        
    try:
        target_file.write_text(content, encoding="utf-8")
        file_size = target_file.stat().st_size
        return f"✅ 파일 '{file_path}'이(가) 디스크에 무결 저장되었습니다. 물리 크기: {file_size} bytes"
    except Exception as e:
        return f"오류: 파일 물리 쓰기 처리 중 장애 발생 - {str(e)}"

# 4. 웹 검색 도구의 컨텍스트 오프로딩 이식 구현

@tool
def web_search_offloaded(query: str) -> str:
    """
    EXA 시맨틱 검색 엔진을 통해 웹에서 최신 기술 동향, 뉴스, 연구 문서를 수확합니다.
    본 도구는 검색된 원시 대규모 텍스트 전체를 디스크 파일로 즉시 격리 이탈(Offloading)시키고,

tools = [ls, read_file, write_file, web_search_offloaded]

FILE_USAGE_INSTRUCTIONS = """You are a highly efficient autonomous agent with a local filesystem workspace.
Your primary engineering constraint is keeping the context window clean to avoid Context Rot and OOM errors.
To achieve this, you must offload large texts into files and read them back selectively.

<Workflow Process>
1.  **Orient**: Start with ls() to understand the filesystem structure and see what files are already available.
2.  **Research**: Use web_search_offloaded() for query execution. It will save heavy content to disk and return a summary.
3.  **Read**: If and only if you need deeper details from a log file, call read_file() with appropriate limits/offsets.
4.  **Synthesize**: Always compile and write your final reports, lists, and analyses to files using write_file().
</Workflow Process>

<Context Offloading Strategy>
- Do not keep raw search outputs or long tables in your short-term message buffer.
- Immediately write them to descriptive markdown files inside the workspace.
- Provide a summary and the exact filename for the user in your final answer.
- Always use the local path: ./agent_workspace/
</Context Offloading Strategy>

Always speak and write in Korean. Deterministic paths ONLY (temperature=0.0)."""

# 6. LangGraph 상태 머신 빌드
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
llm_with_tools = llm.bind_tools(tools)

def call_model(state: AgentState):
    print("---🧠 CALL MODEL (컨텍스트 오프로딩 성찰)---")
    messages = [SystemMessage(content=FILE_USAGE_INSTRUCTIONS)] + state["messages"]
    response = llm_with_tools.invoke(messages)
    return {"messages": [response]}

def should_continue(state: AgentState) -> Literal["tools", "end"]:
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        print("---🔧 GOTO TOOLS (격리 제어선 가동)---")
        return "tools"
    print("---✅ COMPLETED (과업 종결)---")
    return "end"

# 그래프 위상 정의
workflow = StateGraph(AgentState)
workflow.add_node("call_model", call_model)
workflow.add_node("tools", tool_node)

workflow.add_edge(START, "call_model")
workflow.add_conditional_edges(
    "call_model",
    should_continue,
    {
        "tools": "tools",
        "end": END
    }
)
workflow.add_edge("tools", "call_model")

# 가동기 컴파일 완성
compiled_agent = workflow.compile()
print("✅ 컨텍스트 오프로딩 가동 에이전트 엔진 빌드 무결성 확보 완료!")
```

<summary>상세 해설 확인하기</summary>
<p>
Directory Traversal 공격은 공격자가 입력한 상대 경로 기호인 상위 디렉토리 이동 식별자(`..`)가 운영체제의 경로 확인 런타임에서 연쇄 연산되면서, 허용되지 않은 상위 기밀 영역으로 포인터를 리다이렉트시키는 인프라 붕괴 수단입니다.
<br><br>
이를 원천 봉쇄하는 아키텍처 가드레일은 다음과 같이 동작합니다:
1. **물리 캐노니컬 정형화 연산 (Canonicalization)**: `target_file.resolve()`를 호출하여 입력 경로 문자열에 숨겨진 `..`이나 심볼릭 링크(Symbolic Link)를 OS 수준에서 완전히 전개하여 최종 목적지의 정형화된 절대 경로(Canonical Absolute Path)를 도출합니다.
2. **논리적 포함 관계 집합 검증**: 격리 보안 영역으로 선언된 최상위 디렉토리 집합 $WORKSPACE\_DIR$의 절대 경로 문자열을 $S_{base}$라 하고, 정형화된 최종 목적 파일 경로 문자열을 $S_{target}$이라 할 때, 조건식 $S_{target}.startswith(S_{base}) == True$가 성립하는지 이진 집합 필터링을 실행합니다. 이 교집합 구속 조건이 충족되지 않는(False) 파일 쓰기 및 읽기 요청은 커널 수준으로 연산이 송출되기 전에 런타임 에러(`보안 예외 기각`)로 프로세스를 즉각 폭사시켜 호스트 시스템을 상시 구호 수호합니다.
