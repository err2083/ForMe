# [Short term memory와 Long term memory]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 에이전트 메모리 아키텍처의 이중 구조: 단기 기억(Short-term Memory)과 장기 기억(Long-term Memory)
* **단기 기억 (Short-term Memory/Working Memory)**: 
  단기 기억은 에이전트가 단일 세션(대화창) 내부에서 유지하는 컨텍스트 버퍼이자 대화 이력(Chat History)의 집합입니다. 챗봇이나 ReAct 에이전트의 기본적인 질의응답을 구현하기 위해 필수적인 구성 요소로, 체크포인터(Checkpointer) 장치 등을 활용해 대화 흐름의 위상을 동기화하고 상태를 임시 축적합니다.
* **장기 기억 (Long-term Memory/LTM)**: 
  장기 기억은 단일 대화창의 한계를 넘어서 전체 세션과 세션 사이를 유기적으로 연결하는 영속적 지식 저장소 개념입니다. 사람이 이전 작업에서 배운 업무 경험이나 특정 개념을 다른 작업에 활용하듯이, 에이전트가 장기 과업을 수행하거나 사용자의 개인화 선호도(User Preference), 고유한 작업 방식, 과거 마일스톤의 미시적 진척 상황을 영구 보존하기 위해 필수적으로 도입되어야 하는 기술적 근간입니다.

### 1.2 도구 바인딩(Tool Binding) 기반의 자율 장기 기억 축적 및 인덱싱 원리
* **인-컨텍스트 메모리 스토어 제어 루프**: 
  에이전트가 단기 기억 세션 내에서 획득한 고순도 정보나 사용자의 특화 선호도를 장기 기억으로 인코딩하는 과정은 비교적 간단하면서도 세련된 도구 결합 구조를 취합니다. 에이전트 본체 모델에 메모리를 영속 적재하는 쓰기 도구(예: `upsert_memory` 또는 `store_memory`)를 명시적으로 바인딩(Tool Binding)하여 제공합니다.
* **메모리 저장 의사결정의 자율화**: 
  에이전트는 대화 흐름을 실시간 감시하다가 현재 컨텍스트 내에서 추후 다른 세션에 재활용할 만한 가치 있는 정보가 감지되면, 스스로 판단하여 `upsert_memory` 함수를 도구 호출(Tool Call)하여 장기 기억 영역에 데이터를 이식합니다. 또한, 필요에 따라 저장된 과거 정보를 검색할 수 있는 읽기/조회 도구(Retrieve Memory Tool)를 동시에 주입하여 장기 기억의 자율 탐색 및 호출 사이클을 전개합니다.

### 1.3 장기 기억 데이터베이스의 두 패러다임: 벡터 유사도 기반 VS 그래프(Graph) 기반 CRUD
* **전통적인 벡터 DB 유사도 검색의 한계**: 
  단순히 텍스트를 고정 차원 벡터 공간 상에 사영하고 유사도 거리 검색(Cosine Similarity)에 의존하는 방식은 장기 기억 관리에서 치명적인 데이터 정합성 결함을 초래합니다. 장기 기억은 고정된 지식 블록이 아니라 시간의 흐름에 따라 계속 수정(Update), 삭제(Delete), 병합(Upsert)되는 동적 상태(Dynamic CRUD)를 유지해야 합니다. 벡터 DB는 특정 사실이 바뀔 때 기존 벡터 데이터를 정교하게 갱신하거나 충돌되는 모순 관계를 인지하고 무력화하는 논리적 엄밀성이 원천적으로 결여되어 있습니다.
* **관계 정의 및 무결성을 수호하는 지식 그래프(Knowledge Graph)의 이점**: 
  이러한 한계를 도파하기 위해 최근 현대 고성능 에이전트 아키텍처는 벡터를 넘어 **지식 그래프(Knowledge Graph)** 형태로 장기 기억을 인덱싱하고 설계합니다. 대화와 문서 속에서 실시간으로 개체(Entity)를 탐지하고 이들 간의 의미적·논리적 관계(Relation)를 방향성 엣지로 연결하여 저장합니다. 이를 통해 신규 기억 유입 시 기존 노드 및 엣지의 상태를 동적으로 재정의함으로써, 기억의 중복 저장과 왜곡을 방지하고 기억의 삭제/수정 작업 시 모순 없이 완벽한 상태 무결성과 고신뢰성 CRUD 제어력을 영위할 수 있게 됩니다.

### 1.4 현대 장기 기억 관리의 최신 엔지니어링 트렌드: File System 오프로딩과 경량화
* **벡터/그래프 인덱싱 오버헤드와 비용 병목**: 
  지식 그래프나 상용 분산 벡터 스토어를 가동하여 실시간 장기 기억을 빌드하는 패러다임은 고가의 인프라 설치 및 유지보수 비용을 요구하며, 검색 왕복 지연시간(Network Latency)과 매 턴마다 발생하는 인덱싱 연산 오버헤드로 인해 실시간 프로덕션 배포 시 치명적인 지연을 초래합니다.
* **File System 기반 단순 영속화의 급부상**: 
  최근 앤트로픽의 Claude Code 등이 채택하고 있는 가장 성공적인 LTM 트렌드는 **파일 시스템(File System)을 기반으로 한 극도로 단순하고 강력한 파일 제어 로직**입니다. 에이전트에게 파일 시스템 상에서의 읽기, 쓰기, 수정, 편집 툴을 쥐어주고, 에이전트가 일하고 탐색하는 고유의 표준 행동 방식이나 상태 스키마를 `Claude.md` 또는 `todo.md` 같은 구체적인 물리 마크다운 파일로 가상 디렉토리 내에 직접 기록 및 관리하게 만듭니다. 이로써 외부 DB 세션 구축에 따르는 불필요한 레이턴시와 과금 요소를 완벽히 패스하고, 토큰 창의 사용량을 선형적으로 보존 관리하는 동시에 로컬 협업 정합성까지 지키는 기막힌 하드웨어적 최적화를 확보합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 단기 기억(Short-term)과 장기 기억(Long-term) 통합 탑재 에이전트의 데이터 흐름도

```
[사용자 입력 (User Message)]
       │
       ▼ [세션 런타임 제어판 진입]
[단기 기억 콘텍스트 조립 (Short-term Context)] ◄─── [Checkpointer]
  - 대화 히스토리 및 당면 Thought 상태 유지            - 로컬 상태 메시지 실시간 복원
       │
       ├─────────────────────────────────────────┐
       ▼ [의사결정 및 추론 실행]                ▼ [장기 기억 자율 인출 (Retrieve)]
[기저 LLM 디코더 연산 가동]                       [장기 기억 저장소 (LTM)]
       │                                           ├─► File System / Claude.md
       │                                           └─► Zep Dynamic KG / Graph DB
       ▼                                                 │
[도구 호출 판단 (Tool Call Decision)]                    ▼ (중요 사실 호출)
  - 이 맥락에 사용자의 영구적인 선호도나             [과거 세션 핵심 지식 프롬프트 증강]
    장기 보존 가치 지식이 존재하는가?
       │
       ├─────────────────────────────────────────┐
       ▼ [YES: store_memory 툴 노드 기동]       ▼ [NO: 직접 최종 응답 생성]
[upsert_memory(topic_key, memory_fact) 호출] [사용자 맞춤형 최종 답변 출력]
       │                                                 │
       ▼                                                 ▼
[장기 기억 상태 영구 업데이트]                                 [END]
  - 그래프 관계 재구성 및 파일 디스크 쓰기
```

### 2.2 Zep Dynamic KG vs Traditional RAG의 토큰 효율 및 지연 시간 분석
* **전통적인 Vector RAG의 토큰 오버헤드**: 
  Vector RAG는 쿼리 시점에 질문과 유사도가 높은 다량의 청크(chunk)들을 중복에 상관없이 단순 연접(Append) 인출하여 단기 컨텍스트 창에 주입하므로, 토큰 크기를 비대화시켜 VRAM 제곱 복잡도 병목을 자극하고 비용을 폭증시킵니다.
* **동적 지식 그래프(Dynamic KG)의 의미적 압축 기여**: 
  Zep Dynamic KG 등 최신 지식 그래프 기반의 장기 기억 장치는 유입되는 텍스트를 실시간으로 분석하여 고순도의 'Entity-Relation' 튜플 구조로 상호 요약 및 관계화합니다. 탐색 시점에 불필요한 텍스트 찌꺼기와 부연 설명을 완전히 배제하고 오직 "A는 B와 관계가 있다"는 극도로 고압축된 구조화 정보(Entity와 Summary)만을 선별하여 프롬프트로 전이시킵니다. 이로 인해 단기 어텐션 창 내부의 불필요한 토큰 폭주를 원천 봉쇄하여 하드웨어 가용율을 극대화하고, 의미적 오염(Lost in the Middle) 현상을 원천 방지하여 결과 품질을 극한으로 끌어올립니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반의 Long-term Memory 자율 저장 에뮬레이터 스크립트
다음 소스코드는 사용자와의 대화를 실시간 모니터링하여, 추후 재활용할 만한 선호도나 작업 방식이 검출될 경우 `@tool`로 정의된 `upsert_memory`를 자율 가동하고 이를 그래프 노드 전이 파이프라인 내에서 상태 보존하도록 구축한 파이썬 마스터 코드입니다.

```python
import os
import json
import requests
from typing import Dict, Any, List, Literal
from pydantic import BaseModel, Field

# LangChain 및 LangGraph 코어 인터페이스 인입
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, BaseMessage
from langchain.tools import tool
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode

# 1. 장기 기억(LTM) 영속성 유지를 위한 로컬 파일 시스템 저장소 모사
class LocalFileLTMStore:
    def __init__(self, storage_path: str = "/workspace/scratch/ltm_store.json"):
        self.path = storage_path
        self.memory_db = {}
        self._load_db()

    def _load_db(self):
        if os.path.exists(self.path):
            try:
                with open(self.path, "r", encoding="utf-8") as f:
                    self.memory_db = json.load(f)
            except Exception:
                self.memory_db = {}
        else:
            self.memory_db = {}

    def upsert(self, key: str, value: str):
        self.memory_db[key] = value
        with open(self.path, "w", encoding="utf-8") as f:
            json.dump(self.memory_db, f, ensure_ascii=False, indent=2)
        print(f"[LTM_DISK::WRITE] 장기 기억 적재 완료: {key} -> {value}")

    def query_all(self) -> str:
        if not self.memory_db:
            return "현재 누적된 장기 기억이 존재하지 않습니다."
        return "\n".join([f"- {k}: {v}" for k, val in self.memory_db.items()])

# LTM 물리 인스턴스 전역 세팅
ltm_storage = LocalFileLTMStore()

# 2. 에이전트 장기 메모리 입력을 위해 바인딩할 자율 LTM 도구 명세 설계
@tool
def upsert_memory(topic_key: str, memory_fact: str) -> str:
    """
    사용자의 중요한 개인화 정보, 업무 선호도, 고유한 작업 방식 및 
    다음 세션에서도 영속 기억해야 할 주요 팩트를 로컬 장기 기억(LTM) 디스크에 저장합니다.
    """
    ltm_storage.upsert(topic_key, memory_fact)
    return f"성공적으로 장기 기억 저장소에 '{topic_key}' 항목을 영구 업데이트하였습니다."

class LTMWorkflowOrchestrator:
    def __init__(self, api_key: str):
        # 결정론적 판단을 장착하기 위해 탐색 온도 수축 제어
        self.llm = ChatOpenAI(
            model="gpt-4-turbo",
            temperature=0.0,
            openai_api_key=api_key
        )
        self._assemble_ltm_graph()

    def call_model_node(self, state: MessagesState) -> Dict[str, Any]:
        """
        [Node] 메시지 히스토리에 디스크 상의 영속 장기지식을 주입하고 추론을 전개하여 도구 호출 여부 감지
        """
        print("\n--- [NODE] CALL MODEL NODE ---")
        # 디스크에 저장되어 있던 누적 장기 기억 복원
        restored_ltm_block = ltm_storage.query_all()
        
        system_directive = (
            "당신은 강력한 장기기억 시스템(LTM)을 탑재한 영속 도우미 에이전트입니다.\n"
            "아래에 첨부된 장기기억 정보들을 바탕으로 사용자의 고유 취향과 작업 패턴에 최적 정렬되어 응답하세요.\n"
            "또한 사용자와 대화 중 추후 세션에서도 보존해야 할 새로운 선호도, 고유 팩트가 발견되면 "
            "반드시 'upsert_memory' 도구를 기동하여 장기 저장소에 저장해야 합니다.\n\n"
            f"--- [복원된 영속 장기기억 목록] ---\n{restored_ltm_block}"
        )
        
        # 모델에 메모리 장기 저장 도구 명세 바인딩
        model_with_ltm = self.llm.bind_tools([upsert_memory])
        
        # 상태에 적재된 단기 대화 메시지 흐름 끄집어내기
        messages_with_system = [{"role": "system", "content": system_directive}] + state["messages"]
        response = model_with_ltm.invoke(messages_with_system)
        
        return {"messages": [response]}

    def _should_continue_edge(self, state: MessagesState) -> Literal["tools", "__end__"]:
        """
        [Conditional Edge] 모델이 장기 메모리 저장 도구(upsert_memory) 호출을 결정했는지 판정
        """
        print("\n--- [EDGE] DETERMINE ROUTE ---")
        last_message = state["messages"][-1]
        
        if getattr(last_message, "tool_calls", None):
            print("[EDGE::LTM] 자율 장기 기억 저장 도구(upsert_memory) 호출 감지 -> ToolNode 분기 처리.")
            return "tools"
        print("[EDGE::LTM] 특이 지식 저장 사항 없음 -> 최종 응답 및 상태 기각 종료.")
        return "__end__"

    def _assemble_ltm_graph(self):
        # 1. 메시지 채널 기반 상태 그래프 시동
        self.workflow = StateGraph(MessagesState)
        
        # 2. 노드 배치 및 도구 노드 결합
        self.workflow.add_node("call_model", self.call_model_node)
        self.workflow.add_node("tools", ToolNode([upsert_memory]))
        
        # 3. 엣지 가이드 매핑
        self.workflow.add_edge(START, "call_model")
        
        # 도구 판단에 대한 조건부 분기 엣지 마운트
        self.workflow.add_conditional_edges(
            "call_model",
            self._should_continue_edge,
            {
                "tools": "tools",
                "__end__": END
            }
        )
        
        # 도구 실행 후 다시 모델로 회귀하여 저장 확인 피드백 및 다음 대화 진행 처리 (순환 루프 완성)
        self.workflow.add_edge("tools", "call_model")
        
        # 그래프 물리 컴파일
        self.app = self.workflow.compile()
        print("[LTM::COMPILE] Stateful 장기 기억 에이전트 그래프가 컴파일 성공하였습니다.")

    def execute_ltm_agent(self, user_message: str):
        """
        상태 전이 변화를 모니터링하는 시뮬레이터 실행기
        """
        print(f"\n[LTM::START] 사용자 입력 접수: '{user_message}'")
        inputs = {"messages": [HumanMessage(content=user_message)]}
        
        for event in self.app.stream(inputs, stream_mode="values"):
            event["messages"][-1].pretty_print()
```

### 3.2 핵심 시스템 설계 규격과 LTM 파라미터 간의 인과적 매핑 분석
* **`upsert_memory` 도구 설명(Docstring) 최적화의 인프라적 가치**: 
  에이전트가 어떤 상황에서 디스크 저장을 실행해야 할지에 대한 조건 분기선은 프롬프트뿐 아니라 도구 설명 구문에 정밀히 바인딩되어 동작합니다. "사용자의 중요한 개인화 정보, 업무 선호도, 고유한 작업 방식 및 다음 세션에서도 영속 기억해야 할 주요 팩트"라는 물리적 세부 기준을 명시해 둠으로써, 일반적인 로컬 수치나 단순 인사말을 쓸데없이 장기 저장소에 적재하여 디스크 VRAM 노이즈를 팽창시키는 오작동을 미연에 획기적으로 차단해 냅니다.
* **순환 엣지(`tools` ──► `call_model`)의 실시간 피드백 정합성**: 
  도구 실행 노드(`tools`) 완료 직후 `END`로 빠지지 않고 다시 자율 판단 모델 노드로 흐름을 즉시 피딩 백트래킹함으로써, 에이전트가 "내가 지시 사항을 성공적으로 메모리 디스크 상에 잘 저장했음"을 실시간 `ToolMessage` 관찰 결과를 통해 스스로 인지하고, 안심하고 대화 제어권을 마스터 루프에 복귀시켜 사용자에게 안정적인 최종 완료 답변을 전달하도록 수렴시킵니다.
