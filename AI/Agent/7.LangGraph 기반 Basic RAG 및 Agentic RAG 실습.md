# [LangGraph 기반 Basic RAG 및 Agentic RAG 실습]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 LangChain RAG와 LangGraph RAG의 아키텍처적 패러다임 전환과 상태(State) 주권
기존 RAG 시스템을 구축할 때 널리 활용되던 LangChain은 단방향적인 체인(Chain) 아키텍처에 기반하여 정적이고 순차적인 파이프라인을 형성하는 데 특화되어 있었습니다. 그러나 이러한 정적인 설계는 복잡하고 자율적인 의사결정이 요구되는 현대의 최상위 AI 에이전트 시스템에서 심각한 아키텍처적 한계를 노출합니다.
- **LangChain RAG의 선형적 제약과 한계**: LangChain RAG는 사용자 질문이 유입되면 관련 문서를 검색(Retrieval)하고, 이를 프롬프트에 결합하여 답변을 생성(Generation)하는 단방향 선형 파이프라인(Directed Acyclic Graph)을 고수합니다. 이 정적 구조 하에서는 도중 검색된 문서가 실제 질문과 전혀 어긋나는 무익한 정보이거나 에러 메시지 찌꺼기인 경우에도 이를 감지하여 뒤로 되돌아가 검색 쿼리를 수정하거나 다른 외부 데이터베이스를 재탐색하는 등의 유연한 **순환 루프(Cycle)와 조건부 분기(Conditional Branching)**를 제어하기가 극도로 난해합니다.
- **LangGraph RAG의 상태(State) 중심 패러다임 혁신**: LangGraph는 정적 체인 구조를 완전히 탈피하고, 전체 시스템 워크플로우를 노드(Nodes)와 엣지(Edges)로 구성된 **'상태 기반 그래프(State Graph)'** 구조로 재정립합니다. 이 아키텍처의 핵심 정수는 그래프를 통과하는 모든 연산 컴포넌트가 공유하는 **'전역 상태(State)'**를 선언하고 이를 명확하게 추적 관리(State Management)하는 메커니즘에 있습니다.
- **상태 제어력을 통한 시스템 복원력 확보**: 에이전트 개발자는 이제 단순히 LLM의 생성에 실행 흐름을 방임하지 않고, 그래프 상태에 저장된 사용자 질문, 검색된 문서 세트, 이전의 실행 이력 메시지 텐서들을 실시간으로 모니터링하고 수정할 수 있는 완전한 상태 주권을 영위합니다. 검색 결과가 질문과 무관하다고 판단되면 즉시 질문 재작성(rewrite_question) 노드로 제어 흐름을 분기 회귀시키고, 이 과정에서 발생한 상태 변화를 지속적으로 누적 업데이트함으로써, 비결정론적으로 동작하는 자율 에이전트의 예외 복구 성능을 결정론적 시스템 제어 하에 둘 수 있게 됩니다.

### 1.2 상태 전이 기반 에이전틱 제어(Stateful Agentic Control)와 멀티 세션 아키텍처
LangGraph 아키텍처의 중심 기저는 모든 노드 간의 데이터 전이를 명확한 스키마 구조의 `TypedDict` 상태(State) 객체인 `GraphState` 또는 `MessagesState`로 통제한다는 점입니다. 이는 단순한 프로토타입 챗봇을 넘어, 엔터프라이즈 환경에서 무수히 많은 다중 사용자 세션을 안전하게 영속 보존해야 하는 백엔드 시스템 엔지니어링 관점에서 지대한 구조적 가치를 제공합니다.
- **이벤트 기반 분산 세션 관리**: LangGraph RAG 시스템에서 각 추론 단계(Retrieve, Grade, Rewrite, Generate)는 독립된 노드 함수들로 정교하게 쪼개어져 정의됩니다. 각 노드는 이전 노드의 내부 변수들에 직접 관여하지 않고, 오직 인자로 주입되는 상태 객체를 판독하여 연산을 처리한 뒤 신규 상태 사본만을 리턴하여 전이시킵니다.
- **체크포인팅(Checkpointing)을 통한 런타임 디버깅 무결성**: 이러한 상태 전이의 엄밀성 덕분에, 에이전트가 다단계 자율 루프 도중 네트워크 장애나 API 타임아웃 등으로 불시에 중단되더라도 시스템은 전역 체크포인터 메모리에 박제되어 있던 이전 상태 세션을 즉각 역직렬화하여 복원할 수 있습니다. 즉, 처음부터 전체 추론을 재실행하며 가혹한 토큰 비용과 대기 시간을 중복 지불할 필요 없이, 실패한 노드 시점부터 추론 체인을 영리하게 재가동하는 실전적인 엔지니어링 안정성을 달성하게 됩니다.

### 1.3 문서 관련성 평가(Document Grading)를 통한 노이즈 차단 및 어텐션 보호
RAG 파이프라인에서 벡터 유사도 점수만을 맹신하여 인출(Retrieve)된 문서들을 그대로 LLM 프롬프트에 주입(Augment)하면, 문맥과 어긋난 파편적이고 무익한 텍스트 찌꺼기들이 프롬프트를 물들이는 심각한 노이즈 포화 장애를 유발합니다. 이는 기저 트랜스포머 디코더 모델의 어텐션 분배 가중치를 분산시켜 도구 인자 파싱 정확도를 훼손하는 원인이 됩니다.
- **이진 채점 문서 평가기(Document Grader)의 개입**: LangGraph 기반 Agentic RAG는 검색 노출 직후 최종 답변 생성 노드로 가기 전, 검색된 지식 청크의 실제적 질문 관련성을 판독하는 `grade_documents` 조건부 분기 레이어를 강제 마운트합니다. 이 평가기는 Pydantic의 이진 점수(`yes` or `no`) 정형 구조를 기저 LLM의 structured_output 장치와 융합하여 기하학적 유사도에 숨어 있던 무관한 노이즈 청크들을 정밀하게 발라냅니다.
- **어텐션 보호 및 컨텍스트 무결성 수호**: 채점 점수가 `no`에 도달하면 그래프 엔진은 불량 문서를 답변 생성기에 인입시키지 않고 격리 폐기 처리한 뒤, 질문 재작성 노드로 흐름을 리라우팅(Rerouting)시킵니다. 이로써 최종 답변 생성기 레이어가 처리해야 하는 입력 컨텍스트 버퍼 내부를 100% 무결한 고순도 지식 성분으로만 정화 조립하여, 환각 발생율을 물리적 연산 단계에서 영(0)으로 수렴하도록 이끌어 줍니다.

### 1.4 질문 재작성(Query Rewriting)과 동적 재검색 루프의 자가 개선(Self-Correction) 시너지
Advanced RAG 영역에서 단발성 질문 변환(Query Rewrite)이 RAG 성능을 개선했으나, LangGraph의 상태 그래프 순환(Cycle) 구조와 결합한 질문 재작성(`rewrite_question`) 노드는 차원이 다른 강력한 자가 개선(Self-Correction) 시너지를 발생시킵니다.
- **반복적 자율 정화 루프의 구동**: 사용자가 "DeepSeek-OCR 모델의 압축률과 OmniDocBench 성능 수치를 함께 말해줘"와 같은 다중 분석 복합 질문을 입수시켰을 때, 에이전트의 1차 단순 검색 쿼리("DeepSeek-OCR 성능")는 두 정보 중 하나의 청크만 소환하거나 둘 다 놓치는 불완전 검색에 봉착할 가능성이 높습니다.
- **의미론적 의도 역추적 및 변형 검색**: LangGraph RAG 하에서, 1차 검색 문서가 Grader에 의해 부적합 판정을 받으면 `rewrite_question` 노드가 깨어나 이전 질문의 의미론적 의도를 문맥 분석하여 보다 구체적이고 정제된 확장 키워드 조합(예: "contexts optical compression ratio of DeepSeek-OCR")으로 쿼리 텐서를 재생성해 상태에 업데이트합니다. 이어서 엣지는 제어권을 다시 검색 및 툴 호출 노드로 피딩 회귀(Feedback Cycle)시킴으로써, 에이전트가 "원하는 답을 얻을 때까지 스스로 질문 검색식을 혁신하며 재시도하는" 고도의 동적 행동 지능을 발휘하게 유도합니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 LangGraph 기반 Stateful RAG 에이전트의 종단간 데이터 흐름도
아래 아키텍처 흐름도는 사용자 질문의 최초 유입 단계부터 에이전트가 검색 유무를 판별하고, 인출된 문서들의 가치를 정밀 채점하여, 조건부 분기를 타고 질문 재작성과 재검색 루프를 경유한 뒤 무결 답변에 수렴 도달하기까지의 전 과정 데이터 전이와 상태 변화를 텐서 정사 관점에서 도량합니다.

```
[사용자 복합 질문 인입 (User Question)]
       │
       ▼ [State: GraphState / MessagesState 생성 초기화]
[generate_query_or_respond 노드 작동] ◄──────────────────────────────────────────┐
  - LLM bind_tools([retriever_tool]) 호출                                 │
       │                                                                       │
       ├─────────────────────────────────────────┐                             │
       ▼ [Yes: Tool Call 발생]                   ▼ [No: 직접 즉각 응답]         │
[retrieve_context 툴 노드 기동]            [기저 parametric 지식 답변 생성]       │
       │                                         │                             │
       ├──► 1. text-embedding-3-small 벡터 사영   │                             │
       ├──► 2. InMemoryVectorStore ANNs 검색│                             │
       └──► 3. Top-K 문서 청크 원문 확보         │                             │
       │                                         │                             │
       ▼                                         ▼                             │
[grade_documents 조건부 엣지 채점]             [END]                           │
  - with_structured_output(GradeDocuments)                                │
       │                                                                       │
       ├─────────────────────────────────────────┐                             │
       ▼ [yes: 관련성 충분 검증 완료]           ▼ [no: 관련성 미흡 탈락]        │
[generate_answer 노드 가동]                [rewrite_question 노드 가동] ────────┘
  - RAG 힌트 기반 최종 언어 디코딩     - 쿼리 의미론적 의도 확장 재작성
       │
       ▼
     [END]
```

### 2.2 MessagesState 기반 메시지 이력 축적 시의 토큰 폭주(Token Exploding) 관리 구조
LangGraph의 빌트인 상태 채널인 `MessagesState`는 시스템 가동 중 발생하는 모든 AI 메시지, 휴먼 메시지, 그리고 툴 실행 결과 메시지들을 하나의 순차적인 메시지 어레이 리스트(`List[BaseMessage]`)로 관리 및 보존합니다. 에이전트가 질문 재작성과 재검색 조건부 루프를 3회 이상 전개하게 되면 다음과 같은 심각한 토큰 팽창 병목이 유발됩니다.
- **메시지 어레이 축적에 따른 연산 비대화**: 루프를 돌 때마다 이전 회차에서 생성된 불량 질문 텍스트, 쓸모없는 이전 RAG 관찰 결과(Observation)의 원시 텍스트 블록 전체가 이력 데이터 어레이 상에 삭제되지 않고 고스란히 남아 다음 LLM API 프리필(Prefill) 입력으로 누적 연접됩니다. 이는 트랜스포머의 제곱 연산 복잡도 \\(O(T^2)\\)를 극도로 자극하여, TTFT 지연 시간을 지연시키고 서빙 트랙잭션 비용을 기하급수적으로 폭증시킵니다.
- **동적 상태 정제(State Filtering / Pruning)의 구현 가이드라인**:
  - **오래된 툴 결과 메시지 휘발화**: 재작성 및 재검색이 진행되어 신규 RAG 결과가 주입되는 즉시, 이전 루프 단계에서 주입되었던 무익한 과거 툴 메시지(`ToolMessage`)와 질문 메시지를 상태 메모리에서 자동으로 솎아내어 축출(Eviction)시키는 커스텀 리듀서(Reducer) 또는 상태 필터 노드를 파이프라인 전단에 배치해야 합니다.
  - **메시지 윈도우 슬라이싱**: LangGraph 어플리케이션 컴파일 시 최신 N개의 대화 및 행동 텐서만 유지되도록 상태 메시지 어레이를 선입선출(FIFO) 슬라이딩 윈도우 방식으로 강제 제약하여 토큰 사용량을 상수로 통제 조율해야 비용 안정성을 확보할 수 있습니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 LangGraph 기반 Stateful Basic RAG & Agentic RAG 마스터 소스코드
다음 소스코드는 Chroma 로컬 인메모리 벡터 DB 생성 및 `StateGraph(GraphState)` 기반의 결정론적 Basic RAG 아키텍처와, `@tool` 장치, `grade_documents` 조건부 분기 채점기, `rewrite_question` 자가 개선 노드가 완전히 결합된 비결정론적 **Agentic RAG** 워크플로우의 완벽한 종단간 프로독션 구현 파이썬 스크립트입니다.

```python
import os
import json
from typing import Dict, Any, List, Literal, Tuple
from pydantic import BaseModel, Field
from dotenv import load_dotenv

# LangChain 및 LangGraph 핵심 인터페이스 모듈 임포트
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import PyPDFLoader
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.documents import Document
from langchain_core.messages import HumanMessage, BaseMessage
from langchain.tools import tool
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition

# .env 환경 변수 로딩 및 키 체크
load_dotenv()
api_key = os.getenv("OPENAI_API_KEY", "MOCK_KEY_SAFE")

# =====================================================================
# 1. 인프라 레이어 구축: 문서 로딩, 청킹, 고성능 로컬 벡터 DB 인덱싱
# =====================================================================
class DocumentIndexInfrastructure:
    def __init__(self, api_key: str):
        self.embeddings = OpenAIEmbeddings(openai_api_key=api_key)
        self.vectorstore = None
        self.retriever = None

    def build_index(self, pdf_file_path: str):
        # PDF 문서 파싱 및 tiktoken 인코더 기반 계층적 쪼개기 수행
        loader = PyPDFLoader(pdf_file_path)
        docs = loader.load()
        
        # 가독성과 검색 해상도 최적화를 위해 청킹 규격 영점 조절
        text_splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(
            chunk_size=500,     # 각 분할 청크당 최대 토큰 수
            chunk_overlap=50    # 문맥 경계 유실 복원을 위한 중첩 크기
        )
        doc_splits = text_splitter.split_documents(docs)
        print(f"[INFRA::INDEX] 원본 {len(docs)}페이지가 {len(doc_splits)}개의 청크로 분할 완료되었습니다.")
        
        # ChromaDB 로컬 인메모리 스토어 생성 및 문서 적재
        self.vectorstore = Chroma.from_documents(
            documents=doc_splits,
            collection_name="agent-rag-chroma",
            embedding=self.embeddings
        )
        # 상위 3개의 고유 연관 지식 문맥을 인출하는 검색기(Retriever) 장착
        self.retriever = self.vectorstore.as_retriever(search_kwargs={"k": 3})
        print("[INFRA::INDEX] 로컬 ChromaDB 벡터 공간 생성이 최종 완료되었습니다.")

# =====================================================================
# 2. Agentic RAG 컴포넌트 설계: 도구, 채점기, 질문 재작성 정의
# =====================================================================

# 툴로 바인딩될 가용 검색기 전역 중재 인프라 포인터
_global_retriever_ref = None

@tool
def retrieve_context_tool(query: str) -> str:
    """
    사내 지식 베이스 또는 학술 보고서 데이터베이스에서 입력된 쿼리와 
    가장 의미적 연관성이 높은 핵심 문서 청크 텍스트를 인출해 옵니다.
    """
    global _global_retriever_ref
    if not _global_retriever_ref:
        return "검색 엔진이 시스템 오프라인 상태입니다."
    docs = _global_retriever_ref.invoke(query)
    return "\n\n".join([doc.page_content for doc in docs])


class GradeDocuments(BaseModel):
    """
    문서 관련성 정밀 이진 평가를 위한 구조화된 스키마 정의
    """
    binary_score: str = Field(
        description="검색된 문서가 질문에 답변하기에 유용하고 관련이 충분한가요? 'yes' 또는 'no'"
    )


class AgenticRAGOrchestrator:
    def __init__(self, index_infra: DocumentIndexInfrastructure, api_key: str):
        self.infra = index_infra
        global _global_retriever_ref
        _global_retriever_ref = self.infra.retriever
        
        # 결정론적 도구 인자 분석 및 채점을 위해 온도 완전 수축 제어
        self.llm = ChatOpenAI(model="gpt-4-turbo", temperature=0.0, openai_api_key=api_key)
        self.grader_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.0, openai_api_key=api_key)
        
        self._assemble_graph()

    # --- 노드 및 조건부 분기 메서드 정의 (State Machine Nodes) ---

    def generate_query_or_respond(self, state: MessagesState) -> Dict[str, Any]:
        """
        [Node] LLM이 현재 메시지 흐름을 보고, 검색 툴을 호출할지 최종 응답할지 자율 결정
        """
        print("\n--- [NODE] GENERATE QUERY OR RESPOND ---")
        # 검색 툴 retrieve_context_tool을 LLM 파라미터 영역에 선제 바인딩
        response_model = self.llm.bind_tools([retrieve_context_tool])
        response = response_model.invoke(state["messages"])
        return {"messages": [response]}

    def grade_documents_edge(self, state: MessagesState) -> Literal["generate_answer", "rewrite_question"]:
        """
        [Conditional Edge] 인출된 RAG 문서의 실제 관련성을 Pydantic 스키마 기반 채점
        """
        print("\n--- [EDGE] GRADE DOCUMENTS ---")
        user_raw_question = state["messages"].content
        retrieved_tool_content = state["messages"][-1].content
        
        grade_prompt = (
            "당신은 인출된 문서 조각이 사용자의 당면 질문에 답변하기에 문맥적으로 적합하고 "
            "관련된 핵심 정보를 내포하고 있는지 검증하는 전문 채점관입니다.\n"
            f"사용자 질문: {user_raw_question}\n"
            f"검색된 문서 내용:\n{retrieved_tool_content}\n\n"
            "의미나 키워드가 질문의 답을 도출하는 데 기여한다면 무조건 'yes', 그렇지 않다면 'no'로 단호히 판정하십시오."
        )
        
        # 구조적 출력 모듈을 통한 결정론적 이진 채점 수렴 보장
        graded_output = self.grader_llm.with_structured_output(GradeDocuments).invoke(
            [{"role": "user", "content": grade_prompt}]
        )
        
        score = graded_output.binary_score.strip().lower()
        if score == "yes":
            print("[EDGE::GRADE] 관련성 충분 검증 완료 -> generate_answer 단계 이양.")
            return "generate_answer"
        else:
            print("[EDGE::GRADE] 관련성 미흡 및 불량 판정 -> rewrite_question 질문 재작성 리라우팅.")
            return "rewrite_question"

    def rewrite_question(self, state: MessagesState) -> Dict[str, Any]:
        """
        [Node] 검색 문서 불량 시, 보다 높은 재소환을 보장하기 위해 사용자 질문을 확장 재작성
        """
        print("\n--- [NODE] REWRITE QUESTION ---")
        original_question = state["messages"].content
        
        rewrite_prompt = (
            "당신은 검색 정확도를 올리기 위해 쿼리를 상세화하고 확장하는 Query Transformation 엔진입니다.\n"
            "다음 최초 사용자 질문에 내포된 의미론적 의도(Semantic intent)를 추적하여, "
            "벡터 데이터베이스 검색 시 훨씬 높은 매칭 거리를 획득할 수 있는 구체적인 검색 쿼리 단락으로 재작성하십시오.\n"
            f"최초 질문: {original_question}\n"
            "설명 없이 오직 개선된 질문 텍스트만 출력하십시오."
        )
        
        improved_response = self.llm.invoke([{"role": "user", "content": rewrite_prompt}])
        print(f"[NODE::REWRITE] 개선된 신규 검색 쿼리: '{improved_response.content}'")
        return {"messages": [HumanMessage(content=improved_response.content)]}

    def generate_answer(self, state: MessagesState) -> Dict[str, Any]:
        """
        [Node] 엄격히 여과 정화된 RAG 문맥을 기반으로 사실 정합적 최종 답변 생성
        """
        print("\n--- [NODE] GENERATE ANSWER ---")
        original_question = state["messages"].content
        sanitized_context = state["messages"][-1].content
        
        answer_prompt = (
            "당신은 학술 문서 데이터를 무결 해석하는 지식 도우미입니다. "
            "철저히 아래에 첨부된 신뢰할 수 있는 참조 정보에만 기반하여 답변을 도출하십시오.\n"
            "질문에 답할 정보가 본문에 명시되지 않았다면 아는 체하지 말고 모른다고 정직하게 밝히십시오.\n"
            "한국어로 작성하고 세 문장 이내로 콤팩트하게 논증해 답변하십시오.\n\n"
            f"참조 정보:\n{sanitized_context}\n\n"
            f"사용자 질문: {original_question}"
        )
        
        final_answer = self.llm.invoke([{"role": "user", "content": answer_prompt}])
        return {"messages": [final_answer]}

    # --- 그래프 조립 및 컴파일 (Graph Assembly) ---

    def _assemble_graph(self):
        # 1. 메시지 누적 이력 기반 상태 그래프 시동
        self.workflow = StateGraph(MessagesState)
        
        # 2. 독립 노드 등록 배치
        self.workflow.add_node("generate_query_or_respond", self.generate_query_or_respond)
        self.workflow.add_node("retrieve", ToolNode([retrieve_context_tool]))
        self.workflow.add_node("rewrite_question", self.rewrite_question)
        self.workflow.add_node("generate_answer", self.generate_answer)
        
        # 3. 정적 엣지 연결
        self.workflow.add_edge(START, "generate_query_or_respond")
        
        # 4. 조건부 분기 엣지 1: 툴 호출이 필요한지 자율 판단 분기
        self.workflow.add_conditional_edges(
            "generate_query_or_respond",
            tools_condition,  # LangGraph 기본 장착 툴 감지 조건 함수
            {
                "tools": "retrieve",  # 툴 호출 지시 발생 시 retrieve 노드 전치
                END: END              # 직접 답변 결정 시 즉각 상태 기각 종료
            }
        )
        
        # 5. 조건부 분기 엣지 2: 검색된 결과의 고순도 가치를 grade하여 분기
        self.workflow.add_conditional_edges("retrieve", self.grade_documents_edge)
        
        # 6. 정적 역회귀 루프 및 출구 연결
        self.workflow.add_edge("generate_answer", END)
        self.workflow.add_edge("rewrite_question", "generate_query_or_respond")  # 순환 루프(Cycle) 완성
        
        # 7. 그래프 물리 컴파일 완료
        self.app = self.workflow.compile()
        print("[AGENT::COMPILE] Agentic RAG 워크플로우 그래프가 성공적으로 조립 및 컴파일되었습니다.")

    def run_agentic_rag(self, complex_goal: str):
        """
        에이전트 그래프를 스트리밍 값 상태 변화 모드로 시동하여 추론 전이 관측
        """
        print(f"\n[AGENT::START] 자율 업무 명령 시동: '{complex_goal}'")
        inputs = {"messages": [HumanMessage(content=complex_goal)]}
        
        for event in self.app.stream(inputs, stream_mode="values"):
            # 각 노드 실행 결과가 완료될 때마다 전이 완료된 최종 메시지를 감시 모니터링 출력
            event["messages"][-1].pretty_print()
```

### 3.2 핵심 시스템 설계 규격과 Titans/Confession 파라미터 맵 관계 분석
위 구현 코드 상에서 에이전트 시스템 가동 안정성과 비용 효율을 조율하는 핵심 변수들의 물리적 상관관계를 규정합니다.

- **`tools_condition`과 비결정적 자율 툴 바인딩 제어**:
  - **영향 및 원리**: `generate_query_or_respond` 노드에서 LLM에 툴 명세를 결합한 후, 생성 결과를 통과시켰을 때 반환된 객체의 `tool_calls` 필드 유무에 따라 흐름을 리액트(ReAct) 루틴이나 기각 단계로 분기시키는 장치입니다. 이때 `temperature=0.0`으로 완전히 결정화해 두지 않으면, 동일한 질문에서도 어느 세션에서는 툴을 가동하고 다른 세션에서는 무단 생략하는 동작 불일치가 일어납니다. 따라서 온도를 0으로 구속하여 툴 호출 여부에 대한 판단 통제권을 완벽하게 보장해야 합니다.
- **`with_structured_output(GradeDocuments)`를 통한 분기 안정성 수집**:
  - **영향 및 원리**: 관련성 채점기 노드는 분기 조건의 트리거를 결정짓는 핵심 중재판입니다. 채점 모델이 비정형 자연어(예: "관련성이 꽤 있어 보입니다")로 답변하면, 조건부 엣지 내부에서 `if score == "yes"` 분기를 태울 때 문자열 불정합 예외 런타임 크래시가 유발됩니다. Pydantic 스키마를 강제 주입하여 모델의 출력을 JSON `{ "binary_score": "yes" | "no" }`로 수학적 원-핫(One-Hot) 수축시킴으로써, 엣지 파이프라인의 분기 거동 신뢰도를 백퍼센트 보장합니다.

<br><br>
반면, LangGraph RAG의 Stateful StateGraph 구조는 모든 노드의 동작 전후 상태 전이 과정을 데이터베이스나 로컬 영속 디바이스 상에 스냅샷 형태로 실시간 직렬화하는 '체크포인터(Checkpointing) 인프라'를 코어 레벨에서 제공합니다.
<br><br>
에이전트가 다단계 자율 추론을 실행할 때마다, LangGraph 제어기는 각 스텝이 완료된 직후의 전역 `State` 사본을 고유 세션 ID(`thread_id`)와 매핑하여 상태 메모리에 즉각 박제 기록합니다. 3단계에서 심각한 하드웨어 크래시가 유발되어 세션 스레드가 사멸하더라도, 백엔드 복원 서버는 즉각 체크포인터 스토리지에 쿼리하여 해당 `thread_id`의 마지막 정상 저장 시점인 2단계 완료 스냅샷을 디바이스 가상 메모리에 완전 환원(Restore)시킵니다.

### 💡 2번 질문 해설 보기
<details>
<summary>상세 해설 확인하기</summary>
<p>
트랜스포머의 어텐션 메커니즘에서 소프트맥스 확률값 분배는 입력 토큰의 수 $T$가 증가할수록 소프트맥스의 분모가 지수적으로 팽창하여 전체 어텐션 값들이 사방으로 평평하게 뭉개지는 '어텐션 포화(Attention Saturation)' 문제를 유발합니다. 특히, 관련성 평가에서 `no`로 기각된 다량의 노이즈 텍스트 청크들이 `MessagesState`에 고스란히 적재된 채 질문 재작성 루프가 거듭 전개될 때, 입력 텐서 $T$는 선형을 초과해 축적 비대화됩니다.
<br><br>
이 시점에 트랜스포머 레이어 내부의 소프트맥스 정렬 수식의 거동은 다음과 같습니다:
$$\text{softmax}(\mathbf{scores})_i = \frac{e^{s_i}}{\sum_{j=1}^{T} e^{s_j}}$$
여기서 불필요한 노이즈 토큰 분모 합산항 $\sum e^{s_j}$가 비대해짐에 따라, 에이전트의 도구 선택 판단에 진짜 결정적인 단서를 제공하는 시스템 가이드라인 토큰 $i$의 실제 기여 확률인 $\text{softmax}(\mathbf{scores})_i$의 절댓값은 기하학적으로 희석되어 $0$에 수렴하게 됩니다. 이 상태가 곧 에이전트가 도구 스키마의 필수 인자를 엉뚱한 변수로 오지목하여 입력하는 '도구 바인딩 환각' 장애로 귀착되는 인과입니다.
<br><br>
이를 원천 차단하기 위해 런타임 제어기 레벨 상단에 다음과 같은 **'상태 솎아내기(State Pruning)'** 리듀서 수식을 장착해야 합니다:
$$\mathbf{S}_{t+1} = \mathbf{S}_t \setminus \{ \mathbf{M}_k \mid \mathbf{M}_k \in \mathbf{M}_{\text{tool}} \ \wedge \ \text{Is_Irrelevant}(\mathbf{M}_k) \}$$
즉, `grade_documents` 노드 평가 직후 점수가 하한 마진에 미달하는 모든 `ToolMessage` 성분들을 메시지 이력 배열 상에서 즉각 물리적으로 배제소거(Eviction) 처리한 뒤 오직 정화된 의도 쿼리 텐서만을 다음 루프로 전이시키는 필터링 규칙을 설계해야 어텐션 포화 자원을 백퍼센트 보존할 수 있게 됩니다.
</p>
</details>

<p>
무한 검색 루프 데드락(Infinite Retrieval Loop Deadlock)은 사용자의 복합 질문에 적합한 데이터가 RAG 문서 저장소 내에 아예 부재함에도 불구하고, 에이전트의 추론 모듈이 "완벽한 정보를 얻을 때까지 재질의하라"는 시스템 메시지에만 과적합 구속되어, 유사한 변형 질문만을 끊임없이 생산해 자기를 반복 호출하며 자원을 갉아먹는 치명적인 비결정적 순환 교란 상태입니다.
<br><br>
이를 시스템 엔지니어링 관점에서 원천 규제 방어하기 위한 두 가지 가드레일 설계 아키텍처는 다음과 같습니다:
1. **Max Retry Counter (상태 카운터 결합)**: 전역 `GraphState` 내부에 `retrieval_count: int` 필드를 필수 장착합니다. 에이전트가 `rewrite_question` 노드를 통과할 때마다 이 카운터 변수를 $1$씩 동적으로 가산 가중시키고, 조건부 분기 엣지 `grade_documents` 통과 시점에서 `if state['retrieval_count'] >= 3` 조건이 충족되면 더 이상의 재작성 분기를 영구 원천 폐쇄하고 "지식 부재로 답변 불가" 상태 노드인 `generate_fallback_answer`로 강제 전치 아웃(Eviction)시키는 물리적 차단선을 마운트합니다.
2. **동적 금지 목록(Dynamic Tabu Search) 상태 필터**: 에이전트가 루프 가동 중 생성했던 모든 이전 단계의 실패 쿼리 문자열들을 `GraphState['tabu_queries']: List[str]` 채널에 실시간 덧붙여 기록 보존합니다. `rewrite_question` 노드가 실행될 때, 시스템은 이 금지 목록과 LLM 엔진에 다음과 같은 강제 시스템 가이드를 동시에 바인딩하여 밀어 넣습니다:
   "경고: 이전 단계에서 시도했던 다음 쿼리들은 완전히 무의미한 검색 결과만 초래했습니다: [tabu_queries]. 절대 이와 동의어이거나 통사적으로 유사한 단어 조합을 생성하지 말고, 전혀 다른 새로운 각도의 어휘와 시각을 사용하여 질문을 재작성하시오."
<br><br>
이 두 중재 제어막을 LangGraph의 노드와 엣지 전이 파이프라인에 이식해야만, 비결정론적으로 진동하는 에이전틱 RAG의 흐름을 상시 안전하고 예측 가능한 물리 범위 내로 통제하는 비즈니스 무결성을 완성할 수 있습니다.
</p>
