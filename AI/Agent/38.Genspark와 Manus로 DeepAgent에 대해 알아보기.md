# [Genspark와 Manus로 DeepAgent에 대해 알아보기]

## 1. 에이전트 개발 관점의 핵심 아키텍처 분석

### 1.1 메타(Meta)가 주목한 에이전트 선구자, Manus AI의 기술적 위상
* **실질적 비즈니스 수행 능력으로의 패러다임 전환**: 거대언어모델(LLM) 모델 자체의 파라미터 확장과 인지력 경쟁이 치열하게 전개되던 시기, Manus AI는 텍스트 질의응답을 넘어선 실질적 실행(Action Execution)에 전력을 집중하여 에이전트 기술의 대도약을 이루어냈습니다. 최근 메타에 인수되며 그 가치를 세계적인 인프라 엔지니어링 수준에서 입증했습니다.
* **VM Sandbox 환경의 실시간 동적 할당**: Manus AI는 사용자의 작업 요청이 수입되면 개별 태스크에 완전히 정합된 가상 머신 샌드박스(VM Sandbox) 환경을 실시간 동적 부여합니다. 이 격리된 환경 내에서 브라우징, 터미널 조작, 코드 컴파일러 구동, 파일 입출력을 완벽하게 자율 가동하여 다른 AI 기업들 대비 압도적으로 복잡한 다단계 업무(Multi-step Tasks)를 해결합니다.
* **Context Engineering 노하우 기반의 신뢰성 극대화**: 에이전트가 복잡한 물리 행위를 이어갈 때 시스템 안정성을 결정짓는 요소는 모델의 파라미터 체급이 아닌 '컨텍스트를 정밀하게 설계하고 Curation하는 엔지니어링 노하우'에 있습니다. Manus는 파일 시스템을 활용해 인지적 한계를 원천적으로 극복하는 혁신적인 Context Engineering 구조를 선도적으로 입증해 냈습니다.

### 1.2 DeepAgent 아키텍처의 설계 사상과 지향점
* **DeepAgent 핵심 아키텍처**: Claude Code, Genspark, Manus AI 등 현존하는 최고 성능의 지능형 에이전트들은 모두 공통적으로 **"DeepAgent" 구조**로 수렴하고 있습니다. 
* **구조적 핵심 기둥 (Planning & Context Management)**: 단순한 ReAct 반복 오케스트레이션은 VRAM 한계에 쉽게 직면합니다. DeepAgent의 설계 사상은 **Planning(계획 수립)**과 **Context Management(컨텍스트 통제)**를 에이전트 본체의 추론 연산과 정밀 이격시키는 데 있습니다. 이를 실현하기 위해 디스크 또는 상태 레벨의 파일 시스템과 전문 서브 에이전트(Sub-agent) 위동 체계를 기하학적으로 연동시킵니다.

## 2. 데이터 흐름 및 컨텍스트/토큰 관리 구조

### 2.1 파일 시스템 기반 컨텍스트 오프로딩(Context Off-loading) 메커니즘
* **컨텍스트 부패(Context Rot) 예방**: 고도의 리서치나 복잡한 시스템 개발을 수행할 때, 에이전트는 단일 세션에서 평균 50회 이상의 도구 호출(Tool Calls)과 외부 세계 피드백 관찰을 겪습니다. 이 과정에서 쏟아지는 수만 단어의 웹 브라우징 텍스트, 코드 컴파일 로그, 데이터 덤프 데이터셋을 그대로 대화 히스토리 버퍼(Context Window)에 누적시키면, VRAM 계산 복잡도가 $O(T^2)$로 폭증하여 모델 성능이 기하급수적으로 저하되는 컨텍스트 부패가 발생합니다.
* **가상/로컬 파일 시스템으로의 임시 이관**: Manus는 대화 턴 중간의 상세 관찰 결과나 원시 로우 데이터를 세션 버퍼에 직접 바인딩하지 않고, VM Sandbox 디스크 내부에 파이썬 스크립트(.py), 데이터(.csv, .json), 문서(.txt, .md) 형태로 완전히 박제 오프로딩합니다.
* **초경량 메타 텐서(Metadata) 교환**: 추론 연산 창(VRAM 버퍼)에는 오직 결과의 파일 저장 경로 정보와 가볍게 정제된 한 줄 메타 정보(초경량 메타 텐서)만 회수 탑재합니다. 이를 통해 무의미한 토큰 낭비를 절감하고, VRAM 대역폭 부하를 상수의 대역폭 하한으로 영구 구속 통제할 수 있습니다.

### 2.2 todo.md 기반의 목표 추적 및 암송(Recitation) 패턴
* **미션 드리프트(Mission Drift)의 물리적 차단**: 턴의 흐름이 수십 차례 이상 초장기화(Long-running Tasks)되면, 수입된 노이즈 토큰의 어텐션 포화로 인해 에이전트가 최초의 비즈니스 목표를 망각하거나 엉뚱한 작업 루프에 수렴해 버리는 미션 드리프트 위협에 빠지기 쉽습니다.
* **todo.md 마일스톤 관리와 Recitation**: Manus는 태스크의 런타임 개시 시점에 디스크 공간 상에 `todo.md` 파일을 수립하여 세부적인 하위 마일스톤 일정표(content)와 상태(status: pending, in_progress, completed)를 동적으로 추적, 기록합니다.
* **컨텍스트 하단에서의 목표 암송**: 에이전트는 도구를 실행하고 매 턴 결과를 갱신할 때마다, 파일 시스템 내부의 `todo.md` 내용을 자율적으로 다시 읽고(Read) 진행 상황을 정밀 갱신(Update & Rewrite)합니다. 컨텍스트의 최말단에서 가용한 실행 계획을 끊임없이 소리 내어 복기(Recite)하게 만듦으로써, 대규모 노이즈 자극 하에서도 초기 거시 지시사항에 밀착 정렬되도록 의도 통제력을 유지합니다.

## 3. 에이전트 워크플로우 구현 및 API/설정 매핑 분석

### 3.1 VM Sandbox 격리 제어 및 수명 주기 관리
* **작업별 완전 격리형 VM Sandbox 아키텍처**: 각 작업 스레드는 독립적으로 가동되는 Docker 또는 MicroVM 기반의 샌드박스 내부에서 안전하게 실행됩니다.
* **디스크 기반 수명 주기 관리**: 호스트 컴퓨터는 에이전트의 불법 시스템 콜이나 파괴적인 디바이스 접근 명령을 인프라 레이어에서 완벽히 수용·격리하며, 작업 완수 즉시 ephemeral VM을 완전 소멸시켜 악성 코드 전파와 비정결 가중치 누적 위협을 완벽히 소멸시킵니다.

### 3.2 샌드박스 기반 DeepAgent 설계 표준 시뮬레이션 소스코드
다음 소스코드는 파일 시스템 오프로딩, `todo.md` 기반 상태 관리, 그리고 생각-행동-관찰 루프 속의 자가 암송(Recitation) 메커니즘을 완전 정합적으로 결합한 실전 파이썬 엔지니어링 마스터 스크립트 표준 규격입니다.

```python
import os
import sys
from pathlib import Path
from typing import TypedDict, List, Literal, Annotated
from datetime import datetime

# 1. 시뮬레이션용 파일 시스템 샌드박스 가상 경로 설정
SANDBOX_DIR = Path("./sandbox_workspace")
SANDBOX_DIR.mkdir(exist_ok=True)

# 2. 구조화된 할 일 정의
class TodoItem(TypedDict):
    content: str
    status: Literal["pending", "in_progress", "completed"]

class DeepAgentState(TypedDict):
    messages: List[dict]
    todos: List[TodoItem]
    current_focus: str

# 3. 샌드박스 파일 시스템 제어 API (Context Off-loading Tools)
def write_file_to_sandbox(filename: str, content: str) -> str:
    """상세 덤프 및 중간 맥락 데이터를 샌드박스 디스크로 오프로딩합니다."""
    filepath = SANDBOX_DIR / filename
    filepath.write_text(content, encoding="utf-8")
    return f"[Offloaded] {filename} 저장 완료 ({len(content)} characters)"

def read_file_from_sandbox(filename: str) -> str:
    """샌드박스 내부 디스크에서 정밀 데이터나 분석 스크립트를 가져옵니다."""
    filepath = SANDBOX_DIR / filename
    if not filepath.exists():
        return f"Error: '{filename}' 파일을 찾을 수 없습니다."
    return filepath.read_text(encoding="utf-8")

def update_todo_file_on_disk(todos: List[TodoItem]):
    """todo.md 마일스톤 상태를 물리 디스크 상에 박제 영속화합니다."""
    filepath = SANDBOX_DIR / "todo.md"
    lines = ["# TASK MILESTONES (todo.md)\n"]
    for i, item in enumerate(todos, 1):
        status_emoji = {"pending": "⏳", "in_progress": "🔄", "completed": "✅"}
        emoji = status_emoji.get(item["status"], "❓")
        lines.append(f"{i}. {emoji} {item['content']} ({item['status']})")
    
    filepath.write_text("\n".join(lines), encoding="utf-8")

# 4. 자가 계획 복기 및 암송 오프셋 구현 (Recitation Pattern)
def recite_todo_plan() -> str:
    """컨텍스트 말단에서 todo.md를 불러와 모델에 계획을 자율 리마인드 시킵니다."""
    todo_path = SANDBOX_DIR / "todo.md"
    if not todo_path.exists():
        return "[Recitation] 아직 수립된 계획 파일이 없습니다."
    
    plan_content = todo_path.read_text(encoding="utf-8")
    return f"""
=== [GOAL RECITATION] CURRENT TODO STATUS ===
{plan_content}
============================================
"""

# 5. 실전 실행 예뮬레이터 클래스
class ManusDeepAgent:
    def __init__(self, topic: str):
        self.state: DeepAgentState = {
            "messages": [{"role": "user", "content": topic}],
            "todos": [
                {"content": "관련 핵심 주제 웹 시맨틱 검색", "status": "pending"},
                {"content": "대용량 검색 결과 파일 시스템 오프로딩 저장", "status": "pending"},
                {"content": "최종 분석 보고서 구조화 생성 및 배포", "status": "pending"}
            ],
            "current_focus": ""
        }
        # 최초 계획을 디스크 상에 기록
        update_todo_file_on_disk(self.state["todos"])
        print("✅ 초기 계획 todo.md 생성 완료!")

    def step_execution(self, step_index: int):
        """수립된 계획 단계별로 액션을 처리하고 컨텍스트를 제어합니다."""
        print(f"\n--- ▶ STEP {step_index + 1} 실행 기동 ---")
        
        # 1. Recitation 패턴 가동: 계획 복기
        recitation_hint = recite_todo_plan()
        print(recitation_hint)
        
        # 2. 이전 단계 완료 처리 및 현재 단계 in_progress 전치
        for i, todo in enumerate(self.state["todos"]):
            if i < step_index:
                todo["status"] = "completed"
            elif i == step_index:
                todo["status"] = "in_progress"
                self.state["current_focus"] = todo["content"]
        
        update_todo_file_on_disk(self.state["todos"])
        
        # 3. 비즈니스 액션 분기 및 파일 시스템 오프로딩 결합
        if step_index == 0:
            # 시뮬레이션된 웹 검색 덤프 데이터 (수천 라인으로 간주)
            raw_search_dump = "TITLES: AI Agents Trends, MCP standard specs, Manus sandbox setups, Claude Code CLI..." * 100
            # 대용량 데이터를 컨텍스트 버퍼에 통짜로 연접하지 않고 오프로딩
            offload_log = write_file_to_sandbox("mcp_search_raw.txt", raw_search_dump)
            print(offload_log)
            # 메인 컨텍스트 버퍼에는 경로 텐서만 주입
            self.state["messages"].append({
                "role": "assistant",
                "content": f"검색 결과를 mcp_search_raw.txt 파일로 오프로딩했습니다. 핵심: MCP 표준화 및 샌드박싱 트렌드 파악."
            })
            
        elif step_index == 1:
            # 오프로딩된 파일을 디스크에서 직접 읽어 정밀 처리 수행
            search_raw = read_file_from_sandbox("mcp_search_raw.txt")
            summary_content = f"총 {len(search_raw)} 바이트의 원시 검색 지식을 디스크 상에서 가역 압축 분석 완료: MCP N+M 구조 검증."
            print(f"[Core Engine Process] {summary_content}")
            
            self.state["messages"].append({
                "role": "assistant",
                "content": summary_content
            })
            
        elif step_index == 2:
            # 최종 보고서 디스크 쓰기
            final_report = """# AI Agent Architecture Report
1. Architecture: DeepAgent (Manus & Claude Code)
2. Memory: File-system base offloaded context
3. Planning: todo.md recitation pattern enabled
"""
            write_file_to_sandbox("mcp_final_report.md", final_report)
            print("🎉 최종 마스터 보고서가 샌드박스 파일 mcp_final_report.md 로 안전하게 정사 기재되었습니다!")
            
            # 최종 단계 완료 처리
            for todo in self.state["todos"]:
                todo["status"] = "completed"
            update_todo_file_on_disk(self.state["todos"])
            
            # 최종 Recitation 확인
            print(recite_todo_plan())

# 6. 실행 가동 테스트
agent_sim = ManusDeepAgent("대규모 분산 파일시스템 기반 AI 에이전트 아키텍처 조사")
for i in range(3):
    agent_sim.step_execution(i)
```

## 4. 에이전트 구조적 메커니즘 자가 진단

### [질문 1]
에이전트가 수십 차례 이상 외부 브라우저 조작 및 코드 실행 도구를 번갈아 가동할 때 발생하는 '컨텍스트 부패(Context Rot)'의 구체적인 수학적·인프라적 원인을 어텐션 가중치 가속화 메커니즘의 관점에서 논하고, Manus가 취한 '가상 파일 시스템 오프로딩'과 'todo.md 암송(Recitation) 패턴'이 이 병목을 어떻게 극복하는지 그 기술적 실증 기제를 기술하시오.

### [해설]
* **원시 어텐션 맵의 수치적 희석**: 트랜스포머 아키텍처 상에서 턴이 지속 축적되면 입력 시퀀스의 길이 $T$가 점진적으로 팽창하게 되며, 이에 따라 소프트맥스 가중치 계산 분모가 점증하여 초기의 엄격한 지시조건(System Prompts) 및 도구의 JSON Schema 필드가 어텐션 맵 영역 내에서 가중치가 $0$에 수렴하도록 무력화(Attention Dilution)시킵니다. 특히 웹 브라우징 결과나 디버깅 덤프 에러 로그와 같이 의미론적 연관성이 낮은 저해해상도 '노이즈 토큰'들이 버퍼 아래쪽에 대량 연접(Concat) 기재되면, 에이전트가 이전 실행 단계의 잔여 텍스트 찌꺼기에 사로잡히는 컨텍스트 오염과 문맥 정합성 파괴가 초래됩니다.
* **파일 시스템 오프로딩을 통한 VRAM 연산의 수학적 동결**: 상세한 외부 피드백 데이터 덤프 전문을 대화 히스토리 메모리에 집어넣지 않고, 로컬 임시 영속 파일(`.txt`, `.json`)로 이탈 이송(Off-loading)시킴으로써 입력 토큰 크기를 물리적 상수로 영구 격리 통제합니다. 이는 어텐션 연산 복잡도 $O(T^2)$의 무한 팽창을 완벽히 정지시켜 VRAM 연산 제곱 오버헤드를 물리적으로 방어하는 역할을 합니다.
* **todo.md Recitation 패턴의 정합성 가속 메커니즘**: 파일 시스템에 계획 파일을 생성한 후 매 회차 마다 이 파일을 읽어 어텐션 버퍼 최하단에 정렬하여 로드(Recitation)시키면, 소프트맥스 확률 공간 상에서 현재 해야 할 당면 마일스톤 토큰들의 어텐션 기여 점수를 인위적으로 수직 인양(Recency Bias 및 Attention Boosting)하게 됩니다. 이 패턴 덕분에 모델은 이전 회차의 노이즈 정보 유무에 흔들리지 않고 가장 신선한 '현재 당면 과제'에만 어텐션 포커스를 수렴 고정할 수 있으며, 이로 인해 미션 드리프트를 완벽하게 극복하게 됩니다.

### [질문 2]
다중 VM Sandbox 세션을 분산하여 운용하는 프로덕션 레벨의 에이전트 아키텍처 구축 시, 도구 실패나 세션 레이턴시 폭증으로 인한 샌드박스 이탈 예방(Time-out 및 상태 유실 방지)을 달성해야 합니다. 각 에이전트 스레드의 런타임 수명 주기(Lifecycle)를 안전하게 격리하고, 비정상 중단 상태를 무결 복구(Checkpointing)하기 위해 시스템 인프라 수준에서 적용해야 할 고장 감내(Fault-Tolerance) 아키텍처 가이드라인을 작성하시오.

### [해설]
* **MicroVM 기반 커널 격리 및 리소스 상한 규제**: 에이전트가 수행하는 비결정론적 코드 실행이나 패키지 빌드 연산이 호스트 커널 자원을 영구 침식하는 데드락(Deadlock)에 빠지지 않도록 Firecracker MicroVM 또는 gVisor 샌드박스 런타임 환경을 장착해야 합니다. 스레드당 CPU 점유율, 가용 메모리 상한, 디스크 쓰기 속도(IOPS)를 강제 셧다운(Cgroup 및 Namespace Isolation)하여 이종 세션 간의 리소스 고갈 파멸적 연쇄 전파를 원천 무력화해야 합니다.
* **Durable Execution과 이중 원자적 디바이스 쓰기**: 세션 런타임 상에서 도구 지연(Latency)이 설정 타임아웃 임계치(예: 60초)를 초과하여 기각(SIGKILL)되거나 예기치 못한 시스템 패닉으로 가동이 중단되더라도, 즉각적인 복구가 가능하도록 상태 저장을 이중화해야 합니다. 매 노드 상태 변이(State Mutation) 및 `todo.md` 파일 업데이트가 발생할 때마다, LangGraph의 `InMemorySaver`와 같이 인메모리뿐만 아니라 외부 분산 스토리지(예: Redis, PostgreSQL JSONB 등)에 세션 체크포인트를 데이터 트랜잭션 로그(WAL, Write-Ahead Logging) 형태로 즉시 직렬화 적재하여 백업해야 합니다.
* **정상 오프셋(Offset) 기반 복구 및 폴백**: 시스템 비정상 중단 직후 새로운 복구 스레드가 활성화되면, 스토리지로부터 최신 정상 체크포인트 오프셋을 역직렬화 복구하여 다운되었던 최신 마일스톤 시점부터 끊김 없이 롤백 재기동(Durable Execution)합니다. 또한, 반복되는 실행 오류 발생 시에는 사용자 개입(Human-in-the-Loop) 제어 레이어로 자동 양방향 에스컬레이션(Escalation Route)을 수행하는 중첩 가드레일 오케스트레이션을 의무 구축해야 인프라 붕괴를 예방할 수 있습니다.
